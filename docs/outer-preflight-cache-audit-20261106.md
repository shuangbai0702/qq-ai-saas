复核在已验证支持提示字段的模型/服务商上获得独立阶段路由标识，仍按可信租户/机器人/provider 生命周期绑定。未知服务商保持原请求；不是新 API Key，不是显式缓存断点。

## 为什么原来不能直接对应 01:50 的两条账单

已定位 26 号机器人的周期 `2853b15b-0bf4-4c66-800b-322647497842`：北京时间 01:49:49–01:51:01，6 次模型调用、1 次工具调用。内层动作 01:50:16–01:50:38 调用了 `hosted_qq_group_context`，读取有确认回执，任务本身返回 blocked；后续由外层继续处理。这不是小双白普通私聊。

已检查小双白 82 份、26 号 29 份历史请求捕获；该分钟没有保存请求体。因此不能唯一证明两条账单分别是哪一次外层请求，也不能认定当时具体由哪个字段改变前缀。时间和周期可以定位，缺失的历史线缆不能伪造补齐。

为后续定位增加无正文诊断：

- `FISHBOT_DECISION_CONTEXT`：机器人、cycle/work、orientation/planning、system 哈希、历史轮次、尾巴长度、重建原因。
- `FISHBOT_MODEL_USAGE`：关联阶段、动作/消息、响应 ID、原始输入/输出/缓存计数及缓存字段是否上报。
- 重建原因区分初始/已清理、绑定改变、system 改变、摘要变化、空闲边界、轮数边界及字符边界。
- 不记录提示词正文、原始聊天、Key 或 Cookie；不新增数据库或后台模型。原有运行日志生命周期负责存储。
