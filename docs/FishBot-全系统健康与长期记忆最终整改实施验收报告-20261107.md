## 2. B 包：许可、Hold 与完整证据闭环

### 2.1 pending_coverage 待覆盖状态（已实现 + 已通过本地测试）

`memory_reconstruction_checkpoints` 新增兼容列 `pending_events TEXT`（旧代码忽略该列；旧代码对 `pending_coverage` 状态行完全不识别、不可用，回滚安全）。

- **铸造**：35 个真实完整新轮次满足条件但范围内存在未解决覆盖时，铸造 `state='pending_coverage'` 并保存等待中的事件清单（≤64）。无覆盖缺口时照旧铸造 `available`。不足 35 或仅失败轮：永远零铸造（未变）。
- **晋升**：`_promote_pending_checkpoints` 在同一摘要事务内将 pending 行转为 available，当且仅当其等待的每个事件都有完整 coverage 证明。Big Merge 携带覆盖后同样触发晋升。证据真实丢失的批次**诚实保持 pending（BLOCKED）**，不伪造 complete。
- **stamp 隔离**：`reconstruction_stamp` 现在只统计 `state IN ('available','reserved','consumed')`——pending 行**不提前退休 wire、不构成许可**；晋升那一刻才成为合法退休信号。
- **invalidate**：遗忘时 pending 行一并失效并清空 pending_events。

复现证据：`PendingCoverageTests.test_completed_35_rounds_with_hold_wait_as_pending_then_promote`——铸造→不可预订→补覆盖→晋升→可预订。

## 3. C 包：检查点调度、稳定前缀与容量（P0 核心）

### 3.1 无许可沿用已提交前缀（已实现 + 已通过本地测试）

`readonly_journal.prepare` 新增 `tail_extension`（模块级，逐字节、仅跳过已提交 System 块做位置对齐）与 `unprojected` 参数，实现两类**延迟退休**：

1. **System 变更延迟**：配置保存改变 System/工具定义后，未获许可的请求继续使用**已提交 System 字节**，仅追加真实新尾部消息；`retirement_deferred='system_change'` 入诊断。System 新值在下一个合法检查点才生效（与计划"配置升级安排在合法切换点"一致）。SystemContract 层继续按最终 wire 校验（wire 携带旧 System → stable，无越权）。
2. **覆盖退休延迟**：摘要完成后 coverage 投影丢弃已覆盖轮次时（含"最后提交轮被覆盖"这一生产实证死锁形态——窗口扩展无重叠、每轮必拒），behavior 层用**同一确定性 constrain 管线**构建诚实完整原生视图传入 `unprojected`；journal 对其做资料包剥离后逐字节尾部对齐，取真实新增尾部追加。**已提交 wire 原字节不动**，覆盖轮的退出推迟到下一个合法许可；`retirement_deferred='coverage_retirement'` 入诊断。有许可时仍走完整合法重建（退休+新 System 同一候选）。

两条路径均不改变：35 轮护栏、失败轮不充数、consumed 不复活、retirement_changed 仍必须经许可切换。

复现证据（修复前后对照）：
- 修复前形态复现：`DeferralTests` 中先断言无 `unprojected` 时该形态 `ContextReconstructionDenied`（生产小双白/大肥鱼 14:31 类死锁的最小复现）。
- 修复后：同形态下 `retirement_deferred='coverage_retirement'`、`wire[:len(first.wire)]==first.wire`（逐字节前缀不变）、新尾部正常追加、已覆盖轮保留在 wire 中等待合法退休。
- System 变更：`tests/readonly_journal_test.py`（按新合同更新）+ crash 测试中 `retirement_deferred='system_change'` 断言。

### 3.2 Journal 持久化保护（已实现 + 已通过本地测试）

`ReadonlyJournal._persist` 容量不足分支：**已存在有效 payload 的 scope 永不再写 unavailable 墓碑覆盖**（原实现会把最后可恢复快照置 NULL）。首次持久化（无可丢失快照）才允许墓碑。`commit` 失败路径保持诚实失败状态与内存续跑语义。

复现证据：`PersistenceGuardTests.test_capacity_failure_keeps_last_valid_snapshot`——收缩共享预算后 commit 拒绝，DB 中旧 payload/sha/state 逐字节原样。

### 3.3 请求失败分型与事务关系（已实现，见 A 包第 2 条）

- 许可消费与新基线持久化保持既有同事务原子路径（journal db == reflection db）；崩溃窗口测试证明：进程死亡回滚整个候选事务，快照原样、reserve 单独提交的 `reserved` 状态由下一次 reserve 的 `abandoned_request` 清理回收，consumed 永不复活。
- 不明结果（已发请求断流/进程崩溃）：保持保守——不 commit、不重放外部动作、诊断记录 `provider_request_sent`/`provider_stream_started`，证据不足时诚实阻断。

### 3.4 容量合同与数学边界（部分实现 + BLOCKED 部分如实说明）

- 已实现：每次拒绝的容量余量全部入诊断（第 1 节）；`_persist` 调用前按实际序列化字节数预检共享预算（既有机制保持）。
- **BLOCKED（需授权）**：对梁沅芷类"增量 250114/上限 256000"的存量会话，本地策略上限调整属于计划 10.5 的"单独有界容量修正"，**需明确授权且原字节不动**；本计划不授权清历史/新基线。在延迟退休 + readonly 增量去重生效后，此类会话的合法检查点重新可达（pending_coverage + reserve 回退 + 晋升），预期无需动上限即可自愈；若真实 provider 硬上限不足则保持 BLOCKED。

## 4. D 包：平台故障通知与角色经历彻底分离（已实现 + 既有集成测试更新通过）

1. **send() 故障分支重写**（behavior.py）：
   - 群聊（被动/主动/语义决策）：模型故障一律**静默**，不再向群发任何系统话术。
   - 私聊：发送一条短、真实、中性的平台通知——瞬时故障："这条消息暂时没有处理成功，稍后可以再试。"；护栏阻断（需管理员）："这条消息暂时没有处理成功，需要管理员检查后才能恢复，稍后再试。"——不再谎称"马上恢复"，也不再出现"未发送回复"与实际发送矛盾的话术。
   - 通知打上 `_hosted_platform_notice` 可信来源标记。
2. **经历写入全面排除**：平台通知不写入 `dialogue_feedback`（participation.outgoing/confirmed）、`companion_state.outgoing`、`initiative.outgoing`、`autonomy.note_interaction/note_reply`、联系人未回应统计、motive 状态、`reflection.record`/`confirmed_prefix`（原有排除保持）。通知计数进 `metrics.platformNotices`。
3. **首次保存前拦截**：save_history 包装器对平台通知的 assistant 消息与主动锚点的 user 消息置 `_no_save=True`（pinned SDK 原生能力）——通知与内部锚点**永不进入模型原生会话历史**；已提交历史不做任何改写。
4. **用户真实技术讨论不受影响**：排除逻辑只按平台内部来源标记（typed extra），无关键词黑名单；用户讨论编程/调试照常进入记忆。

- `send_lifecycle_test.py`（独立框架，直接运行）：`PASS model failure with delivered sanitized notice remains error and preserves actual receipt` 等三场景通过。

## 5. E 包：Claims、Facts 与长期记忆

### 5.1 Claims 语义化（已实现 + 已通过本地测试）

`summary_material.derive_claims` 重写：

- **删除逐轮自动转录**（每轮 human_statement + bot_statement 的机械循环）。
- 新增模型在同一次摘要请求中的 `evidence` 语义选择：`[{event,who:user|bot,quote}]`；代码只校验——quote 逐字存在于该说话人的可信证据文本（材料正文/确认回复/仅观察的 native 原文）、作者来自协议 payload、scope/event 归属正确、fit_claims 预算不变。字段缺失/非法**不回退全量转录**：低价值批次诚实零 claim。
- **确定性保留**：已验证纠错（memory_blocks）不依赖模型选择，永远成 claim（protected+value）；约定（commitments 语义 stage）与未完话题（motives→interpretation）既有校验路径不变；supersedes 同人同受众规则不变。
- 两处摘要提示词（companion_insights.SYSTEM 主路径 + 非洞见路径）加入 evidence 合同与"宁缺毋滥、逐字片段、不转述"要求；800/1500 摘要默认未动，无新增模型轮。

复现证据：`ClaimSelectionTests`（4 项）+ 更新后的 `d4_claims_test`（纠错跨合并/重启存活、native 原文仅观察、形状门、保护优先预算）+ `p1_commitments_test`（无关键词约定受保护、关键词闲聊不入 claims）。

## 13. BLOCKED、剩余风险与 Plan vs Actual

**BLOCKED（需授权/外部条件）**
1. 生产部署、进程重启、逐会话恢复写库（华为云服务器操作授权）。

**剩余风险**
1. `unprojected` 依赖 constrain 的确定性；若上游 QQ 图片 URL 重复下载返回不同字节，延迟路径会退化为诚实拒绝（fail-closed，不破坏不变量）。
2. pending_coverage 依赖后续批次补证；证据永久丢失的批次将长期 pending（诚实 BLOCKED，符合合同，但该 scope 需管理员介入）。
3. System 变更延迟生效（最长至下一合法检查点）——这是计划的明确取舍，需在发布说明中告知运维。
4. 预存失败项（d2_audience 1 项、4 个独立框架文件、memory-runtime 集成）在本轮未修复，属既有问题清单。

**Plan vs Actual**
