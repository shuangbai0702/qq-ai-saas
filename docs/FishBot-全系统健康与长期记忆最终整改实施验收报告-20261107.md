### 2.1 pending_coverage 待覆盖状态（已实现 + 已通过本地测试）

`memory_reconstruction_checkpoints` 新增兼容列 `pending_events TEXT`（旧代码忽略该列；旧代码对 `pending_coverage` 状态行完全不识别、不可用，回滚安全）。

## 3. C 包：检查点调度、稳定前缀与容量（P0 核心）

### 3.1 无许可沿用已提交前缀（已实现 + 已通过本地测试）

`readonly_journal.prepare` 新增 `tail_extension`（模块级，逐字节、仅跳过已提交 System 块做位置对齐）与 `unprojected` 参数，实现两类**延迟退休**：

1. **System 变更延迟**：配置保存改变 System/工具定义后，未获许可的请求继续使用**已提交 System 字节**，仅追加真实新尾部消息；`retirement_deferred='system_change'` 入诊断。System 新值在下一个合法检查点才生效（与计划"配置升级安排在合法切换点"一致）。SystemContract 层继续按最终 wire 校验（wire 携带旧 System → stable，无越权）。
2. **覆盖退休延迟**：摘要完成后 coverage 投影丢弃已覆盖轮次时（含"最后提交轮被覆盖"这一生产实证死锁形态——窗口扩展无重叠、每轮必拒），behavior 层用**同一确定性 constrain 管线**构建诚实完整原生视图传入 `unprojected`；journal 对其做资料包剥离后逐字节尾部对齐，取真实新增尾部追加。**已提交 wire 原字节不动**，覆盖轮的退出推迟到下一个合法许可；`retirement_deferred='coverage_retirement'` 入诊断。有许可时仍走完整合法重建（退休+新 System 同一候选）。

两条路径均不改变：35 轮护栏、失败轮不充数、consumed 不复活、retirement_changed 仍必须经许可切换。

复现证据（修复前后对照）：
- 修复前形态复现：`DeferralTests` 中先断言无 `unprojected` 时该形态 `ContextReconstructionDenied`（生产小双白/大肥鱼 14:31 类死锁的最小复现）。
- 修复后：同形态下 `retirement_deferred='coverage_retirement'`、`wire[:len(first.wire)]==first.wire`（逐字节前缀不变）、新尾部正常追加、已覆盖轮保留在 wire 中等待合法退休。
- System 变更：`tests/readonly_journal_test.py`（按新合同更新）+ crash 测试中 `retirement_deferred='system_change'` 断言。

### 3.2 Journal 持久化保护（已实现 + 已通过本地测试）

`ReadonlyJournal._persist` 容量不足分支：**已存在有效 payload 的 scope 永不再写 unavailable 墓碑覆盖**（原实现会把最后可恢复快照置 NULL）。首次持久化（无可丢失快照）才允许墓碑。`commit` 失败路径保持诚实失败状态与内存续跑语义。
