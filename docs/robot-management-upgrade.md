# 机器人管理完善：功能核对与实施设计

日期：2026-10-30。工作区：`D:\MYCODE\APP\fishbot\qq-ai-saas`。

本文件是本次“先仔细思考、看看别人怎么做，再完善管理界面”的调查与实施依据，不是开发完成报告。本次未修改生产代码、数据库、机器人配置或 QQ 登录态；没有重新执行功能测试。下面分别标注当前源码事实、参考机制和待实现内容。先保留方案，后续实施不得通过改写本文件把未完成项变成完成。

## 1. 结论

管理对象应是“这个机器人的聊天范围、行为、数据和任务”，而不是一份需要用户理解内部字段的配置文件。只增加群号选择框和插件开关仍不够。

采用机器人默认设置＋会话例外；扩展功能提供启停、作用范围、依赖、预算、数据管理和运行记录。功能效果与管理能力分别验收，不能用“有开关”代表功能健全，也不能声称已经与所有大肥鱼实现效果一致。

保留 AstrBot 和当前共享运行组，不另起管理服务，不把每个 QQ 群变成新 AstrBot 实例。不改邀请制和默认一名用户一个机器人/对应 QQ 的额度规则。

## 3. 管理页面组织

机器人详情使用一级导航，手机收为可切换菜单；保留现有 B 方案视觉基础及大肥鱼插画，不重新做一套装饰首页。

1. **概览**：QQ 在线、AI 进程、最近真实模型调用分别显示；展示缺少配置、异常原因、保存/生效版本和下一步操作。
2. **QQ 与聊天范围**：QQ 连接、群列表、私聊范围、会话例外。扫码仍在这里，不与模型配置混放。
3. **人格与模型**：名称、预设人格、System Prompt、模型地址/Key/ID、模型读取及最小推理探测。
4. **聊天行为**：唤醒、跟进、合并连发、分句、限频、引用、随机插话；基础参数优先，高级参数折叠。
5. **记忆与人物**：事实、人物、来源、修订、遗忘；情绪/关系作为人物子页，不伪装成完整心理画像。
6. **表达学习**：范围、已学表达、来源样本、学习批次、失败/暂停原因、禁用与清理。
7. **图片与表情**：已批准图库、待审核收图、使用场景、发图规则；识图、生图入口按真实支持状态显示。
8. **主动聊天与任务**：目标会话、静默/未回应、配额、安静时段、任务计划及发送记录。
9. **扩展功能**：能力目录和依赖状态，统一链接到上述具体管理页；语音、搜索、视频等放此处，不另做多套重复开关。
10. **日志与运行**：用户可读事件和高级日志；共享组、generation 等留在高级区域，不要求普通用户操作组。

不把十页平铺为十个顶部按钮；机器人侧栏列常用项，低频“扩展/运行”折叠。各页有清楚标题和说明，不使用抽象欢迎语。

## 4. 群和私聊管理的具体规则

### 群列表

- QQ 在线后，经后端校验 Bot 归属，从该 Bot 的 OneBot 端查询 `get_group_list`；群名/群号搜索、多选、查看当前范围。
- 列表显示群名、群号、是否允许回复、继承/自定义配置；成员数等仅在协议返回时显示，不用零代替未知。
- 支持“所有已加入的群 / 仅选中的群 / 关闭全部群聊”。仅选中模式下零个群必须是零个群，不得恢复成全部群。
- **旧数据迁移**：现有 `groups=[]` 的语义是所有群，必须原样迁移；不能在更新界面时默默收紧或放开现有配置。新机器人可默认关闭群聊，完成选择再启用；这是待实现的新默认，需专项回归。
- QQ 掉线、目录加载失败、未加入群、已选群未出现在最新目录，是四种不同状态。刷新失败不得清空已选配置。
- 仅选中模式下，新加入的群默认不启用。所有群模式明确说明新群也在范围内。
- 本页是选择已经加入的群，不冒充自动加群、邀请审批或管理员权限。

### 会话例外

首批只覆盖：是否处理、触发方式、冷却、随机插话、是否学习、是否配图、是否允许主动联系。先统一这些控制点，再考虑每群独立人格/模型；当前全 Bot Provider 配置不能仅靠前端选择器变成每群 Provider。

默认配置＋稀疏覆盖，提供“恢复跟随默认”。禁用会话时，回复、学习、自动收图和主动任务都必须检查相同的最终权限；避免“关了群回复，但仍采样/发图”。若用户需要仅不回复但继续学习，应提供另一个明确模式，不隐式保留采集。

### 私聊

增加私聊允许范围与屏蔽名单；可从好友/已有会话目录选择，不能假设好友列表等于全部私聊来源。陌生人、临时会话按协议能力单独描述。主动联系授权与允许被动回复分开。

所有会话主键由服务端生成并绑定 `tenant_id/bot_id/type/target_id`，不按群名或昵称聚合。跨 Bot 相同群号不共享任何配置或学习数据。

## 6. 后端与隔离边界

以下是待开发接口设计，不是现有 API：

- `GET /v1/bots/:id/contacts`：经过归属校验的只读目录，统一 group/private 结果；不接受前端提供协议 URL/token，不开放任意 OneBot action 代理。
- `GET/PUT /v1/bots/:id/conversation-rules`：稀疏会话例外、expected revision、有效配置预览；不额外创建 AI 实例。
- `GET /v1/bots/:id/extensions`：结合功能实现、已保存配置、生效 revision、能力探测、运行指标计算状态；不再维护一份会漂移的“已启用”数据库副本。
- 记忆、表达和任务各有专属的分页读取与受控修改 API；参数限定为当前 Bot 下的 scope/subject，不能接受磁盘路径或数据库名。

记忆/学习写操作由数据 Owner 处理，使用原生 SQLite 事务与数据版本比较。已有 Worker 持有连接时，不通过外部脚本直接覆写 SQLite 文件；停止状态下采用受控维护路径。不得每次翻页都启动 Python 解释器，也不新增每 Bot Web 服务。

配置写入继续采用现有 `expectedRevision`，保存与运行应用分开显示。数据删除/纠正需要独立的数据版本或持久化墓碑，防止模型在途结果、旧采样或重试复活旧数据。接口关闭后迟到 UI 响应不得覆盖新 Bot；取消前端请求不等于已经撤销服务端提交。

运行时把最终会话权限用于接收、采样、模型、工具、主动任务及发送检查；发送前再校验成员代次和权限。共享组只允许受控扩展，不因管理目录增加而开放任意 Python/文件/发消息工具。

日志优先显示用户能理解的事件，例如“未响应：此群未启用”“主动联系暂停：对方未回应”“学习等待：样本不足”，不默认暴露其他租户、完整聊天正文、Key 或共享进程内部状态。说明日志保留期，避免把诊断日志变成无界历史库。

## 7. 实施顺序与验收

### 第一批：基础范围和功能入口

实现只读 QQ 目录、显式 all/selected/none 模式、范围迁移、群选择页、扩展状态目录、现有功能入口重组。保留一份源文件基线；本批无需修改真实 QQ Session。

验收：两租户同群号不串；掉线/刷新失败不清选择；选择为空不放行全部；老配置语义不变；只有实际支持的扩展有开关；保存、生效和运行成功不混为一个状态。

### 第二批：现有数据可以管理

实现记忆/人物列表与纠正、表达查看停用、图库元数据编辑、主动目标及暂停记录；随后把每会话权限接入所有行为路径。不能只把后台 JSON 原样显示给普通用户。

验收：删改后下一次模型请求实际变化；旧学习结果不得复活已禁表达；记忆不跨群/人/Bot；配置更新或删除成员时，旧任务无权发送；批量清理需显示准确范围；失败保留可恢复状态。

### 第三批：重要体验缺口

先补自动收图待审和可验证看图，再接 ASR/TTS、真实日程、受控联网；按供应商和真实验收分批开放，不为了填满功能目录而同时安装整套插件。每项记录模型/存储/CPU 预算，不在基础套餐偷偷增加常驻大模型。

验收：授权群图片确实进入待审，通过前绝不发送；被拒图片不反复收录；语音/视觉失败不冒充成功；任务能取消且不会迟发；扩展停用清理任务和资源，仍保留用户数据，删除数据是另一项明确操作。

### 效果对齐

在授权 QQ/群进行少量真实验证：初见、多人接话、不该接话、跟进、玩笑、回忆与纠正、配图/不配图、长时间沉默、主动拒绝、重启恢复。用正确 Bot 的真实模型请求/QQ 接收证据核验；自动化替身单独记录。除非获得目标机器人的可比样例，否则称“基于开源机制的还原与改进”，不宣称视频效果完全复现。
