# 带表情包回复的聊天分段修复

用户要求：主人主动联系继续观察，先修复选择表情包后多段文字合并发送的问题。本次不调整主人联系、群参与判断、图片选择和内存参数。

## 根因和最小修复

`behavior.py` 只在消息链全部由 `Plain` 或 `Face` 组成时使用 `split_text`。平台表情包、QQ收藏表情包和图库图片均是实际 `Image` 组件，导致选图的那一轮绕过聊天分段。带引用或艾特的消息也存在相同条件遗漏。

保留原有分段开关、中文句子/换行规则、最多三段和发送节奏。允许文字与图片、引用、艾特组合进入分段：引用和艾特仅放首段；图片和表情仅放末段，完整回复只发送一次图片。纯图片不制造空文字消息；音频、文件等其他组合保持原发送方式。

每段仍在等待发送节奏后验证配置所有权、代次和投递条件；媒体转换后仍由原OneBot派发保护复查。没有为修复分段绕过并发、拒绝联系或迟到发送保护。

## 实际验证

- Windows受影响回归9/9通过：自主时钟、基础行为、主动联系、媒体归属、原生SDK发图、发送生命周期、社交状态及媒体API。
- Linux实际容器完成Python语法检查及5组测试：`sticker_native_test.py`、`send_lifecycle_test.py`、`autonomy_test.py`、`social_test.py`、`initiative_test.py`，全部通过，用时38.6秒。
- 新增检查直接调用真实AstrBot事件发送包装和SDK OneBot转换：三句话生成三条发送、真实图片段只在末条、引用/艾特仅首条、纯图片单条、关闭分段仍单条、纯文字仍分段、收藏表情与图库图片分段。
- 用明确交错检查首段发送后替换配置：后续文字及图片不得发送，不能重建已释放的SQLite存储。

这些是实际SDK加隔离传输的验证，不冒充真实QQ消息回执。上线采用只替换这处Python源码、等待AI空闲、受保护平滑重载共享AI的方式；不更新Web/API，不重启Agent或NapCat，不修改任何机器人配置。实际部署结果、版本一致性和在线状态由本次交付核对。
