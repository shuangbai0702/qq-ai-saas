## 实际修改
- quote_reply、qq_favorite_tools：工具定义只描述稳定合同；动态消息候选、图片句柄和近期收藏回执改为请求尾部 tool_context。引用、收藏执行端继续核对账号、群/私会话、代次和真实来源。
- inner_tools：前台、内部 Work 共用实时候选贡献和 request_context，不另建工具权限或记忆系统。外层元数据枚举不写事件状态。
- model_cache：对已核实接受提示字段的 OpenAI/aiapi.codes GPT 请求增加稳定 prompt_cache_key；以可信 tenant/bot/scope 的哈希命名，不冻结上下文，也不对未知兼容站点强加参数。
- model_request_capture、model_egress：默认关闭的操作者限时抓取；最多8次/30分钟，单请求4MiB、响应1MiB上限，私有文件权限0600；响应只保存 usage，不存回复正文；流式字节原样交付。失败不影响模型请求，既有网络/大小保护保留。
- Linux 长期运行 Agent 的旧 BotConfigSchema 会丢弃 reasoningEffort 与部分新行为字段；仅刷新磁盘适配器不足。已通过原对象更新 canonical parse，并检查运行 context 与最新正式合同一致。已验证旧10轮摘要默认值按现有正式合同迁移30轮；移除旧日摘要额度，恢复已保存的收藏、引用、B站搜索字段。数据库配置未改。磁盘产品合同本来已正确，因此不新增另一套兼容解析器。

## 缓存结论与限制
- 原先合成10K资料98%与真实聊天无直接等价关系。
- 使用抓到的完整真实请求、31项工具重放：单独稳定工具/补medium，未返回缓存命中，不能宣称这些修改独自解释了零命中。
- 完整真实请求完全相同的重放可返回38656缓存词元；并非接口完全不支持这种长请求。
- 相同真实来源的两条不同请求，经工具定义稳定化、候选移尾、稳定路由提示后，第二条37559输入中返回3840缓存词元（10.22%）。这是受控重放，tool_choice=none、输出上限128，不代表生产命中率或P95。
- 添加新对话尾部的多组复测出现502，作为接口失败单列，不计缓存成功/失败。后续实测另存私有实验日志。
- 相同真实请求再次重放可分别返回38656/38669、37504/37559，但这是整份请求已热的结果，不能算新增聊天命中率。
- 历史窗口滚动仍限制可复用前缀；没有为提高命中而伪造历史、冻结记忆/身份、延后摘要或增加无用填充。
