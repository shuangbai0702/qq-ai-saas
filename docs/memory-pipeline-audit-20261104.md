# FishBot 记忆与公共管线缺陷检查（2026-11-04）

本轮依据当前代码、生产只读数据及可复现测试检查并修复。范围是输入绑定、群消息合批、上下文组装、外层反馈、摘要提交、消息回执、原生历史及重启恢复。没有将历史文档或模拟协议通过当成真实 QQ 行为通过。

## 结论

发现并修复七处边界缺陷。共同原因是不同模块对“等待、执行完成、发送成功、当前记忆版本”的认定不一致。修复集中在现有公共入口及提交边界；没有增加第二套调度器、发送器、记忆库或模型请求。

| 缺陷 | 实际风险 | 修复位置 |
|---|---|---|
| 输入时取得的事实快照跨过合批/媒体等待后继续使用 | 用户修正或删除后，旧事实仍进入新一轮上下文 | `bot_pipeline.conversation_context` 每次组装重新读权威事实与摘要 |
| 合批等待协程返回被当成前台执行完成 | 外层收到尚未发生的“执行反馈”，干扰后续判断 | `AutonomousRuntime.completed` 不提交 waiting/combined Work 为完成反馈 |
| 内存合批队列消失，数据库仍长期等待 | 重启后显示不存在的等待任务 | `BotPipeline.__init__` 将遗留 batch_waiting 标为 interrupted；保留可持久恢复的群参与等待 |
| 摘要只在解码前检查记忆版本 | 删除与迟到摘要交错，重新写入已删除材料的派生记忆 | `Reflection.retry` 在实际写事务内再次验证 epoch 与配置所有权 |
| 非新鲜度复核路径中断发送，原生历史仍保存完整草稿 | 机器人把没说出去的后半段当成已说内容 | `behavior.send` 从空的确认前缀开始，随真实回执推进历史覆盖 |
| 原生历史保存入口未检查 lease/记忆版本 | 已失效事件仍开始保存原生历史 | 现有 `_save_to_history` 适配入口校验当前绑定与 epoch |
| 已发送前缀，随后媒体准备失败仍记录为纯 error | 混淆完全失败与部分成功，影响诊断及后续决策 | `BotPipeline.finish` 有确认副作用的失败归为 partial，保留原错误原因 |

前四项专项用例和“发送前缀历史”边界断言均先在修复前复现失败；partial 状态用例另行复现失败后修复。

## 当前管线与数据权威

```text
可信协议事件 → 绑定 tenant/bot/QQ 与 Work → 原始消息及来源观察
 → 参与判断/合批（等待不等于执行完成）
 → 公共 ContextBuilder（重新读取当前事实、摘要、近期消息及执行经历）
 → 内层模型/工具 → OutputPlan → 末端身份/版本/发送许可检查
 → 协议投递 → confirmed / rejected / partial / unknown
 → 已确认内容与真实工具结果提交 → 外层反馈及后续决策
```

事实和摘要来自每个机器人自己的行为库；原作者由协议发送者 ID 与来源记录确定，昵称、被 @ 的人及机器人旧称呼不升级为可信身份。外层和内层复用上下文组装及执行经历，不另造事实数据库。模型草稿、工具意图、等待状态及未确认副作用都不等于已完成经历。

摘要在远程模型调用完成后才取得短写事务，不在网络请求期间持有写锁。新增的权威读取是本地有界查询，不增加模型调用或后台进程。

## 生产只读发现

03:03 左右抽样：主机器人有 34 条摘要、43 条待整理成功问答、928 条近期材料；其他机器人数据单独存放。所有可查询来源表的机器人中，本轮作者字段一致性查询未发现不匹配；这不是对全部模型称呼正确性的证明。

主机器人存在 11 条旧 `batch_waiting`，最老约 12.9 小时；另一在线机器人有 9 条。新启动恢复逻辑只处理已经失去内存队列的合批等待，不清空用户记忆，也不重放旧消息。停止的机器人在其下一次实际打开行为库时执行同样恢复，不为整理记录而启动 QQ。

历史 `autonomous_owner_observing` 表示旁听/外层所有权观察，不代表同数量的活跃任务；本轮没有把这类记录批量改为成功。约 03:23 再读摘要：仍有 34 条摘要，重试表为空。待整理问答按 scope 和配置阈值触发，不能把全库总轮数直接当作某个会话已达到整理阈值；健康响应未返回所查询的摘要计数字段，未据此伪造成功或失败。

## 尚未承诺解决的边界

- 删除一条事实与彻底擦除原生聊天记录、工具经历是不同产品操作。本轮阻止已失效版本重新开始提交，不宣称已经跨所有存储原子擦除。
- 原生历史入口版本检查不等于覆盖其内部异步数据库提交全过程的跨库事务。本轮没有为此改写 AstrBot 持久层。
- 旁听历史记录与真实待执行 Work 的诊断展示仍需区分；本轮未批量改写历史。
- 没有进行新的真人群聊验收或长时间 P95 压测。隔离模型与受控回执测试不能证明所有真实接口与模型输出永不出错。
- 本次是相关链路的针对性检查，不是全仓库、所有权限与全部并发组合的无漏洞证明。
