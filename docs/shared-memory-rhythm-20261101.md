# 群聊私聊长期记忆互通与自然分条

## 执行依据与计划

用户要求同一机器人的群聊、私聊记忆互通；随后要求回复由模型决定1到4条，普通闲聊通常1到2条，并明确分条间隔与打字模拟等待相加。保留前一任务的鱼动图、单次末条发图及停止/更新后的迟到发送保护。主人主动联系继续观察，不调整策略。

1. 事实按协议提供的同一QQ ID互通，保留原始会话、事件与版本；旧记录直接参与召回，不搬库。跨机器人和租户仍隔离。更正、遗忘、管理入口和远程向量索引同步遵守这一范围。
2. 摘要仍在各自会话生成，检索时允许召回当前QQ真实参与的其他会话。参与者只取协议事件；旧摘要从准确事件ID或私聊会话ID恢复归属，无法证明的旧群摘要继续仅在原群使用，不从模型文本猜作者。原始短期聊天历史不合并。
3. 关键词、FTS、当前回复模型阅读及可选远程向量召回共用权威候选，保留原有条数、字数、每日请求与超时限制。不引入常驻服务或额外日常模型请求。
4. 模型通过换行选择独立消息；句号不强制拆分，最多4条，溢出内容保留在末条；代码与列表完整发送。图片只出现一次。第一条等待打字模拟，后续条等待分条间隔加该条打字模拟。
5. 更新默认人格及必要界面说明，保留用户自定义人格、现有CSS和其他工作区内容。Windows构建与关键回归、Linux隔离SDK/数据迁移验收后部署，只受保护重载AI和受影响Web/API，不重启Agent或QQ；核对数据保留、PID与Guard，再提交推送并核对两端。

## 验收重点

- 同QQ群→私聊→另一群；其他QQ、另一机器人不能取到该人物资料；摘要标明原始来源和多人归属。
- 旧库无损读取、重启、冲突选择、跨会话更正/遗忘/重新明确记录、管理入口版本冲突、在途摘要/向量迟到返回。
- 真实AstrBot SDK中1、2、4条、超出4条、代码/列表、图文末条单图、首条路由、延迟相加及中途配置更新。
- 生产验收不向生产记忆写入伪造资料；隔离验收与真实自然消息证据分别记录。

## 实际结果与 Plan vs Actual

Windows生产构建、14项关键回归通过；补充共享预算与摘要向量边界后的对应复验通过。共享记忆专用13项测试覆盖双向事实、旧库冲突、更正/遗忘、跨会话预算、管理版本、摘要归属及在途返回。真实AstrBot SDK验证了同一QQ私聊→群聊→私聊召回，共享AI的另一机器人不能读取这些事实，采集/检索没有新增模型请求。原生SDK发送检查验证1/3/4条、溢出保留、路由仅首条、鱼GIF仅末条一次，以及等待时间 `.4,1.2,1.2,1.2`（每条打字.4秒，后续另加.8秒）。现有主动联系集成检查保留了2条消息的真实发送路径。

浏览器通过实际登录API验证了新分条、记忆范围及等待说明，修改/刷新持久化，390px无横向溢出及无脚本错误。截图采样禁用页面入场动画，避免把过渡中的模糊帧当成最终显示；未修改产品CSS。

Linux完成9组Python检查、界面/默认配置检查、两条完整SDK用例、只读生产副本验收和生产构建。两条SDK用例各用独立PostgreSQL临时库和角色，运行后移除。第一轮两组共用临时库，后一组失败并超时；结合用例会启动库内既有实例的调用关系，按隔离问题处理。清理仅本次验证容器后，分库重跑全部通过。没有降低断言或强制测试进程伪装成功。Python/API阶段在源码和用例哈希完全相同时复用；新增界面说明另行构建并比对产物。

用户授权机器人的生产只读副本：3条事实、18份摘要的原始行及哈希保持，完整性检查通过；14份摘要恢复可信参与者，主人有11份可用摘要，其中10份来自其他会话。4份无法核实参与者的旧群摘要保留原群。迁移约25毫秒，5次有界读取最慢0.36毫秒，模型请求0。副本销毁，未向生产写入测试事实。

合理偏移：为保留已有UI，只更新必要文案与默认人格；没有重写用户已保存的自定义人格。原始短期消息、关系分数和心境没有混入全局事实。生产没有注入伪造QQ消息，实际对话效果不能由隔离模型夹具替代；发布后仅以自然消息或用户实际反馈继续观察。

为给部署产物明确的源码节点，实施顺序调整为：通过验收的代码先提交并同步，再更新运行目录，最后补齐本验收记录。没有扩大部署组件。实际发布用时61.1秒，只受保护重载共享AI和重启API，未重启Agent或QQ。保留4份行为数据库备份及源码/产物回退目录；6份QQ身份文件、账号、租户、成员、Key和QQ绑定表均通过保持检查。机器人配置版本和哈希、主人联系参数、用户CSS及无关未跟踪文件保持；Guard持续正常，原内存策略和OOM计数不变。

最终生产租户API读验收：157张鱼GIF已安装，实际图片HTTP返回GIF，3个废除ID均404。实际配置为分条开启、间隔800毫秒、打字模拟开启（15字/秒、最长3秒）；事实、摘要、语义召回开启，摘要仍按用户原配置每30轮、每天最多20次。未配置Embedding模型，因此使用当前回复模型阅读候选，未宣称远程向量服务已启用。生产数据库完整性通过，仍为3条活跃事实、18份摘要，其中14份已归属。

本次最终采样时，新AI进程尚无自然新入站/回复回执；不据隔离SDK结果宣称已观察到生产模型稳定选择1–2条，或已经验证新版本的真实QQ双向回复。确定的是运行代码已生效、完整SDK路径通过、QQ在线与数据保留检查通过。日常1–2条由模型提示引导，最多4条由发送代码保证。
