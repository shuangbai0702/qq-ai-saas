## 3. 最高合同：任何功能不得修改护栏来获得通过

### 3.1 上下文和检查点

1. 每个已提交wire消息的角色、字段顺序、内容、媒体字节/表示与序列化保持原样。末尾只追加必要新事件或紧凑delta；同一消息内不得回填、删字、改时间、改作者或重排。最终HTTP边界逐条验证，违规不能静默bootstrap。
2. 前台按真实完成业务轮次计35；工具调用、气泡、失败/取消/沉默、后台执行不冒充业务轮次。沿用已部署ACK完成轮次合同；媒体-only确认可以构成完整轮，unknown/partial不伪造完整。
3. 外层按35次**有效完整规划周期**独立压缩：同cycle有合法planning决策、持久提交、执行时完整反馈已结算、周期未失效，cycleId只计一次；纯orientation、抢占/超时/重复finish、轮询与回执检查不计。外部操作unknown须先处理现有回执状态，不能靠计数把它遗忘。外层没有获准检查点时也不能因体积/失败重构。
4. 外层检查点只影响该bot的外层传输历史，不改前台、System或其他租户。orientation/planning各自保存已提交消息，用同一有效cycle水位防重复消费，不能分别模型调用35次代替35周期。
5. System变更仅允许真实35轮摘要成功许可或认证网页明确保存配置的可信审计。不是任何摘要、部署、重启、工具切换、模型切换或epoch变化都能签发许可。新增System消息同样属于变更。
6. 本计划不要求每个35检查点都改System。首选维持System恒定；词汇/协议新版本排队，只有既有System合同能证明许可范围覆盖时才激活。若当前bot全局System合同仅接入网页许可，不借某一scope的35轮许可修改其他scope的System；先用真实网页许可激活，未完成覆盖证明的自动激活暂缓。
7. 不重发旧cutover登记，不恢复已消费许可，不把scope/Work/phase换名当初始会话。进程重启恢复原wire与合同；容量失败明确记录，不能涨上限、提前裁剪或换布局冒充追加。

### 3.2 身份、纠错、隐私的不同处理

- 当前作者、来源scope、对象是平台事件事实；执行授权来自真实事件、租户、QQ绑定、配置、Work/lease及后端工具检查。模型输出、引用、昵称、记忆不能授予权限。
- 不尝试developer。沿用已部署平台事件包及可信装配器，不把身份/执行权限交给普通文字声明；稳定System说明协议，动态事实只追加。文本来源标记本身不是密码学授权，需对伪造同名包做负面测试，模型识别风险不能以“后端安全”掩盖。
- **普通事实纠正**：旧说法作为历史保留，追加带实际纠正证据的撤回/替代记录；检索不再把旧值当当前事实，等待合法边界淘汰旧布局。不调用整库forget epoch冒充重构许可。
- **硬遗忘、撤销可见性、已混入他人私聊**：尾部remove不能让模型没看见旧字节。若旧wire含受禁内容，在现有发送边界阻止受影响scope继续请求并废弃在途候选；记录具体冲突，要求真正合法的网页保存或检查点后才能安全换基线，不能偷偷清前缀。只阻断受影响scope，不扩大到全bot。
- 若这种阻断使该scope无法积满35轮，必须在发布前安排用户真实网页操作的合法迁移；不能设计成“等自然35轮就会好”的死锁。没有可用迁移路径时，对应存量修复不可上线。两份原报告忽略了这项必要条件。

### 3.3 兼容激活规则

新增记忆布局、过滤规则先离线验证并登记pending布局版本；每个journal继续原周期布局，到自己的合法重构边界才切换。期间新业务事实/纠正可按原协议增量追加。System版本单独受更严格许可控制。安全阻断可立即执行，安全数据不能继续发送；阻断不是允许重构。合法工具集合仍实时变化，不强制固定列表。

运行转换必须按下表实现，不能只写提示词：

| 事件 | 候选/已提交基线动作 | 可否重构 |
|---|---|---|
| 新事实、普通召回、纠错、预算/表情候选变化 | 验证后追加delta；旧候选依赖过期则撤销，已提交基线不变 | 否 |
| 普通摘要或big merge提交 | 更新记忆版本和当前选用资料；`project_history`不能据此在35轮前剔除已提交原生历史 | 否 |
| 请求失败/取消、配置加载、重启、工具切换 | 撤销本候选或恢复原快照；新工具权限实时校验 | 否 |
| 硬遗忘/受众撤销且旧wire含受禁材料 | 受影响scope拒绝发送、候选失效，保留故障证据 | 否，直至真正合法许可 |
| 精确35业务轮成功摘要、可信网页保存 | 预留原范围许可；候选成功时快照与消费原子提交，失败释放预留 | 仅许可覆盖范围 |
| 35有效外层cycle检查点 | 仅相应外层phase消费子许可，不碰前台/System | 仅外层历史 |

`summary_material.project_history`、`behavior.prepare_chat_payload`、`Reflection.retry`必须共享上述合法水位：有覆盖证明只是必要条件，仍需合法检查点才对下一基线应用历史剔除。普通摘要完成不因“有coverage”取得提前压缩权。

## 4. 统一实施设计

下述新增字段/函数均是**拟实现**，不是声称当前已存在；通过现有数据库、ContextBuilder、Work、journal及Agent tick扩展，不建第二套记忆或授权服务。事务变更必须同步所有既有读写入口和导入导出路径。

### D1（P0）来源链：把引用证据与执行许可分开

**文件/函数**：`packages/contracts/autonomous.ts:ActionIntentSchema/GoalChangeSchema`；`packages/database/autonomous.ts:commitDecision`；`apps/node-agent/src/autonomous.ts`派发；`adapters/astrbot/autonomous_runtime.py:think/make_event/execute`；`bot_pipeline.py:bind_internal/annotate_speaker/experience_context`；`initiative.py`合成事件；`context_transport.py:authority_context_view`。

设计：

1. 模型action只可提供可选`evidenceRefs`（最多8项，每项引用本轮已提供记录的稳定ref）；模型不能写权威sourceScope、owner、sender或requestSource。TS schema与Python回退schema同步。
2. commitDecision在当前claim/goal revision事务内按本轮已提供的可信记录白名单解引用，校验tenant/bot、实际scope/event/sender、时间/摘要版本及当前允许用途；伪造或过期ref明确reject，不用objective关键字启发式猜来源。沿现有cycle决策/goal.source JSON保存`evidenceSources`，每条包含`ref,scope,eventId,senderId,at,kind,digest`，多源不强压成单scope。
3. 派发保留现有`requestSource`同scope handoff限制，**禁止**用跨scope证据包授予“回复原请求”的许可。另传`evidenceSources`用于内容归属；跨群→私聊仍走原主动发送预算/权限。观察到群消息不等于获准对该群发言，也不等于获准向另一人披露。
4. executor用现有平台task数据解释证据来源：引用群事需保留会话类型/合理时间限定，不能冒称私聊当前发言；无需外显QQ号或私密群名。无证据的模型自主想法标`model_intention`，不假装人说过。缺来源不强迫追问不相关历史，可保守表达不确定。
5. initiative不再把调度文案标成用户亲口发言。复用make_event服务身份及既有contact_subject/真实recipient字段；先调整依赖get_sender_id的寻址点并逐项测试，不能只改user_id=0导致消息发给0或丢联系人。此变更不能获得新scope基线。
6. feedback、pipeline_actions与experience保留证据包；旧null来源标unknown-origin，按现有target与隐私范围处理，不能“无来源全部放行”，也不删除旧执行回执。

验收：A action297脱敏fixture的“群里说→合法主动私聊”完整链路有可核对来源；同来源跨目标不产生requestSource；伪造ref/普通群友冒主人/同eventId不同scope/跨bot均拒绝；工作流、未完目标、未知回执不丢。措辞质量需要后述离线评价，字段齐全不等于模型必定说对。

### D2（P0）统一记忆受众与逐条归属，覆盖core_note旁路

**文件/函数**：`memory_scope.py:summary_rows/summary_item/fact_rows`；`memory_reflection.py:rolling/recall/semantic_recall/core_note/update_core_note`；`semantic_context.py:recall`；`bot_pipeline.py:memory_context/ContextBuilder/experience_context`；`behavior.py`摘要合并；`memory_search.py:MemorySearch.search`。进程资源脚本`scripts/memory_snapshot.py`不是记忆检索入口，不纳入本项。

4. prepare幂等key为真实Work/event+bot账号+handle+文件digest；同项重复返回already_prepared，不重复下载/改计划；同Work不同项只允许在尚未dispatch前原选择规则安全替换，已发送/ACK未知不再次发送。qf_/bf_/模型图片统一沿原OutputPlan去重。
5. d18停摆仅做有界定点诊断：provider就绪、实际视觉错误、pressure/chat_busy、nextAt、账号revision、manual状态、文件可读性。不可在根因未证实时删除压力门或换模型。补无正文reason与queueAge诊断即可定位，不再全审计。

这里的selection_disabled限制**自动按语义选图**，不应禁掉用户通过真实引用/已绑定图片来源明确指定发某张图的合法功能。显式选图须复用现有引用/媒体来源证明与后端权限检查，不能接受模型自报explicit=true绕过。工具参数中若要区分两种意图，必须由平台真实事件证据证明explicitSelection，不能靠模型一句“用户要求”授权；无可靠证明仍不自动选未知图。S1需同时固定这两条行为夹具，避免把所有无标注收藏一律封死。

验收：clear/manual合法项仍可列出、选中、发送和ACK入记忆；raw_text不直接启用；uncertain恰好最多3次，重启保留计数；后台压力缓解后可恢复；账号切换/晚到视觉结果不覆盖新索引；收藏保存/发表情未知结果不重复外部操作。

### D9（P2）存量治理：只修已核验内容，先阻断回灌再迁移

**文件/入口**：现有data_admin、记忆网页审计、数据库transfer、R4 journal/permit恢复入口；新增受控离线dry-run脚本放`scripts/`，不得在应用启动时扫描自动改库。

步骤：先D2/D3/D4防新污染；对summary52/53、称呼纠错、研究事实生成逐条迁移预览，记录原hash、目标claims、来源、受众、涉及journal、预计合法激活方式。保留“bot曾说过”和“发生过能力事故”的历史，不能为消除矛盾把真实记录改没。没有原证据的旧摘要仅标未核实、限制受众，不凭AI改写为确定事实。人工确认后才走现有管理事务更新，需expected revision/hash防覆盖新状态。运行时遇到新事件、遗忘或epoch变化取消该批迁移；不得还原整库覆盖新消息。

验收：存量处理前后protected集合、人物约定、图片来源、真实回执、未完Work逐项对照；受限内容不回流；旧版本留有授权审计但忘记内容按既有遗忘政策处理，不另留可被模型召回的“备份记忆”。本轮没有任何生产迁移授权。

## 7. 费用、资源与质量：如何判断收益

- 固定同一脱敏样本和时间口径，分别比较同scope前台、orientation、planning；记录请求数、completed/failed/canceled、有效业务轮/有效cycle、重构原因和许可消费。未报告usage不填0，失败无usage不计已知费用。
- 缓存使用实际input/cached/uncached及供方实际价格版本；报告总量和p50/p95，正常新增内容不全归重建。满本地前缀但上游0单列，不能通过gen-/resp推路由或声称解决TTL/驱逐。
- 字符、UTF-8 bytes、媒体bytes、实际Token分别记录；离线无usage只报告体积，不除以3冒充Token。CPU/RSS/SQLite体积与端到端响应延迟分别测，不把Python重放时间当模型耗时。
- 自然度离线集按闲聊、必要确认、用户要求汇报、关系纠错、故障分别分层；包含正常“回执/刚才/以事实为准”等负面样本。至少两位独立评审或盲评复核，分歧保留；正则只作弱信号，不参与删除正文、纠错权限或正负反馈决策。
- 第一硬门槛：越权/错误作者/错误受众/已遗忘泄露/重复副作用/正常回复误删为0（有限测试集边界）；protected记忆覆盖100%；旧前缀不变。不能用自然度改善抵消这些失败。
- 自然度目标沿用R2的<0.5%非必要技术词、<6%有害自指作为**待验证目标**，不保证达到；道歉率不作为强制压制指标。用户要求的汇报、真实错误说明和适当不确定性不算任务腔。600条周样本只作后续有授权的自然流量评价，不本轮制造新流量。
- 字符下降30–50%、缓存下降成本40%等旧估计不作为既定收益。若变更提高Token但修复隐私或保真，单列必要代价；容量不合格仍不能发布。
