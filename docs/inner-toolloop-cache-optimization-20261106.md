# 自主任务内层缓存修复与验收

## 原因与范围

用户 06:36–06:37 的低命中已对应到小双白真实自主任务。同一 Work 中第一步消息布局是“可信系统/原生系统/任务/完整只读资料”，工具返回后变成“可信系统/原生系统/任务/模型工具调用/工具回执/完整只读资料”。资料虽相同，第一次的完整请求不再是第二次前缀。原有 ReadonlyJournal 仅在前台 message/deferred_group 且开启记忆时接线，autonomous 没有接入。

原始线上捕获另核到同一 Work：20,850 输入/3,584 缓存；21,087 输入/6,784 缓存。工具正常执行，但只读资料移动破坏连续前缀，不能用“工具循环正常”来解释缓存已经正常。

## 修改

1. behavior.py 公共 provider 边界复用已有 ReadonlyJournal。只有内部服务身份的 action ID 与绑定 autonomous Work 的 event_id 一致才进入，按 (autonomous, Work ID) 隔离，仍校验真实 provider、当前配置、遗忘 epoch 及原生前缀。
2. 本轮只读资料无变化不重复注入；有变化追加原协议 readonlyChanges。上一请求保持原样，真实 assistant 工具调用与 tool 结果保持相邻，原生会话和 SQLite 记忆不改写。
3. 迟到响应提交前额外校验内部 Work 当前有效性；失效结果不能提交该传输历史。
4. autonomous_runtime.invoke 的 finally 释放当前 Work 的临时传输历史，成功、失败、取消都不把任务历史带进下一 Work；临时 Work 不占前台 8 会话历史名额。

没有新建记忆、调度、发送器、权限系统或常驻进程，未改前端、API、工具授权、模型配置和内存参数。

## 外层长度重建调查

06:36 外层 51,640 输入 / 8,320 缓存对应 history_size_boundary，下一次 55,001 / 51,456 已恢复。新捕获的约 7.7K Token 增量主要来自真实字幕检查点：188 段字幕及覆盖区间。它是任务反馈内容，不能为了缓存删除字幕或把元数据冒充内容理解。

试过将 checkpoints 接入不可变资料引用；同一组实际状态的线缆字符从 100,682 / 105,838 变成 100,811 / 105,967，没有实际缩减，已完整撤回该候选。保留现有外层长度保护、摘要与遗忘语义。并非每次长度重建都可消除。

## 上线后的实际链路

06:52 起仅采样主人自己的小双白，最多 8 个请求。一个真实 Work 内三次调用分别：13,183 输入/3,584 缓存（27.19%）；14,590/13,056（89.49%）；15,997/14,464（90.42%）。后两次均逐消息核实上一请求完整前缀保持，新工具调用与回执未拆开。此项是线上真实流量，与上文隔离 A/B 分开统计。

同批外层首次梳理 37,397/8,320 是运行时更新后的冷历史；之后规划 44,058/37,248（84.54%），再规划 47,051/43,904（93.31%），与已有跨阶段复用行为一致。不同阶段独立分支切换不要求与紧邻的另一分支完全前缀相等。

线上首条任务仍只命中固定公共部分；不同任务之间没有复用可执行历史。外层真实字幕反馈和有界长度重建继续保留。没有把首次低命中、重建或新增工具结果藏入平均数。
