## 实际进入产品的能力

- `adapters/astrbot/social.py` 是平台受控扩展，接入既有 dedicated/shared 两条 AstrBot 运行路径；未安装任意 Python 插件，也未增加一个常驻服务。
- 网页配置页增加“学习群友表达与黑话”和“按语境发送表情图片”。配置通过现有 revision/desired state 管理。授权真实测试 Bot 已开启，保存/生效均为 v9；其他现有 Bot 的功能开关未被批量修改。
- 学习从真实群消息采样，未 @ 的消息可学习但不因此生成回复。至少12条样本、至少两位发言人才触发，最多24条/批；同一群至少间隔15分钟，每台 Bot 滚动24小时最多4次学习尝试。失败也占用请求预算，不做后台自动重试。
- 使用所属 Bot 的原生 AstrBot Provider 进行提炼。接受表达必须在至少两位群友提供的原话里出现，有明确 source_ids；虚构来源、身份/指令类内容、过长结果被拒绝。这是保守的群体常用表达学习，不是已经完成任意个人风格建模。
- 每台 Bot 的 `behavior.sqlite` 分库存储，再按 group scope 分离。同一群号、同一个人出现在另一台 Bot 中，不共享学习结果。学习样本最多2000条/7天，表达最多200条/30天；每次回复最多注入3条表达提示，不改写人格。
- 图片由同一次回复模型从最多8个审核候选中选择，无额外情绪模型/Embedding 常驻服务。模型允许不配图、纯图、文字配图；原有 `[NO_REPLY]` 继续在程序层阻止发送。
- 图片标记 `[MEME:id]` 只映射到已知本地资源，路径不进入模型上下文；图片 bytes 通过 AstrBot Image 组件投递。无效或关闭功能时的标记也会清除。严重丧失/自伤类明确上下文有额外保守拦截，但这不是完整语义分类器。
- 默认每会话60秒冷却、每 Bot 每天20次图片尝试。额度在发送前同步预留，防止并发绕过；发送失败不增加 `imagesSent` 成功指标。图片被并发删除时不影响其余文本回复。
- 网页支持专属 PNG 图库：上传、预览、刷新保留和删除。每 Bot 最多5张、每张256KiB、宽高不超过2048。加上3张公共基础反应图共8张，所有候选均可被模型看到。用户填写使用场景，当前不进行自动视觉标注。
- 图片接口逐次校验 Bot 所有权；不从用户输入的任意 URL 下载，不接受本地路径。内置图来自 Twemoji，来源/署名见 `templates/reactions/ATTRIBUTION.md`。

## 与上游复用的关系

本轮采用 MaiBot 的情境表达＋来源筛选思路、Self Learning 的批次提炼思路、Meme Manager 的模型标记→Image机制、Magpie 的不发图/冷却/单次动作思想。没有直接复制其整套插件数据库，也没有宣称已原样部署这些插件。

原因是已发现上游部分路径只按 group_id 查询，另有全局单例/状态；与当前多客户共享运行组边界不一致。当前受控扩展使用现有 Provider、生命周期和每 Bot 数据根，避免同时开启多套接话/主动消息调度。

## 异步与状态修复

- Shared Worker 卸载成员前先使其 settings 失效，并取消学习任务，再等待平台/Provider drain；最后关闭 SQLite。迟到学习结果必须再次检查所属 setting 对象，不能写入新配置代次。
- 关闭时取消学习；取消和失败不把敏感错误写入 QQ 或共享日志。
- 网页图库请求在 Bot 切换/卸载时 abort，并在读取文件、上传及刷新后的提交点检查失效状态；客户端取消不等于撤销服务端已经成功的上传，重新进入后以服务端列表为准。
- 图库更改无需重启；开关仍需“保存并应用”。共享成员更新只重载该成员，不因上传图片重启整个组。
