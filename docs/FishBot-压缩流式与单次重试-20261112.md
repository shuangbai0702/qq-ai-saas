# 压缩流式与单次重试

## 原始实施计划

用户要求：压缩失败后再尝试一次，应用流式，然后推送 Git；包含此前已部署、尚未提交的材料脱敏一致性修复。

1. 正常 35 轮压缩与管理员强压复用同一模型请求路径，历史合并及仍受支持的恢复分支采用相同传输策略。
2. 流式只改变传输；读取完整最终响应后沿用现有解码、容量、来源、事务及 Journal 采纳边界。不发送片段到 QQ，不更换模型、思考档位或输出上限。
3. 单次处理的模型请求或输出不合格时最多再请求一次；取消、关闭、配置/epoch 失效及持久化失败不立即重试，不重复提交成功批次。两次失败后保留材料及既有退避恢复。
4. 通过受影响的隔离测试和 pinned SDK HTTP fixture 验证，包括中断、失败上限、无效输出、失效和提交边界。
5. 只部署相关 Python 模块，通过现有 Agent Owner 的停止围栏重载 AI，核对成员就绪、QQ 和 Agent 身份不变；核对 Windows/Linux 源码及运行文件摘要。
6. 审查本任务差异，保留其他任务脏文件；单独提交并推送，核对远程及 Linux 源码提交关系。

## 验证与 Plan vs Actual

- 实现：仅新增 `memory_reflection.summary_model_output`，普通摘要、管理员强压、大合并及旧 Hold 恢复复用。只在请求、解码和必需摘要验证边界最多请求两次；事务、Journal 采纳及清理在外。取消、关闭、配置或 epoch 失效不重试。
- 流式结束必须显式 `finish_reason=stop`。SDK 将只有合法 JSON 的无结束标记 EOF 合成为 final 的情况仍拒收；非 JSON、空摘要、截断或超限均不提交。每轮重置审计，避免首轮解码状态污染第二轮请求失败归因。
- Windows 选定回归同次执行 122 项全部通过。Linux 初次 115 项有两处旧测试 Provider 仅支持非流接口，适配 fixture 后该 115 项通过；新增核心便笺套件最初缺隔离目录依赖，补齐既有测试文件后 7 项通过。合计 122 项通过。HTTP fixture 使用 pinned SDK 验证实际 `stream=true`、503 总计两次请求、缺结束标记 EOF/截断不提交及材料保留，没有付费模型调用。
- 旧测试仅迁移 Provider 流式 fixture、合法成功响应 JSON 和失败后请求次数期望。扩大验证中，旧 foundation 有 6 项失败、sources 有 4 项失败、confirmed 有 1 项失败及 1 项错误，long_memory 整套 25 秒未结束；用 HEAD 原 `memory_reflection` 分别复现同样失败或超时，未削弱断言。另有既有 core_note 审计原因断言差异，仍未修改。
- 华为云部署：只替换 `memory_reflection.py`，通过现有 Agent Owner 原子停止围栏停止、重启当前受影响 AI 组，恢复 1 个实际运行成员；QQ PID/创建时间及 Agent PID 保持不变。当前实际成员数已因其他会话迁移变化，未沿用前次四成员基线。启动构建证据的 `sourceMatchesLoaded=true`，Windows、运行文件、Linux 原源码目录相关文件 SHA256 均为 `226aee8a634c109f3d0155e8e9c4d7aa652d3fd453e4ce79ac8c68984312c0f7`。部署证据位于生产 `/control/summary-stream-20261112`，未纳入仓库。
- Plan vs Actual：功能、针对性验证、华为云生效及源码回收完成；没有改模型、思考档位、输出上限或超时。增加严格结束标记检查是防止 SDK 不完整流被提交的必要边界。其他任务的 `shared_context.py` 和未跟踪文件保留，不混入提交。Linux 原源码检出存在大量既有差异，未为对齐提交号覆盖该工作区；本报告不声称其 Git HEAD 已与远程统一。
- 范围限制：检查部署时发现该账号已经由另一会话从华为云迁移到移动云；本轮未部署移动云。用户随后要求尽快提交，因此停止新增部署调查并先提交推送。不能把华为云生效当作移动云现用端已生效。

实验请求包、凭据和原始生产聊天不纳入 Git；生产验证未新增 QQ 外发或强压。
