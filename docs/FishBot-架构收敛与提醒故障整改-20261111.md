## 提醒逐阶段事实

### 第一次：02:25:45「2分钟后叫我」

1. 协议入站事件 `1978778638` 于 02:25:45 收到，进入 `private:768687099`；02:25:43 的旧回复早于本请求，不能当成答应提醒。
2. 02:26:16.754 的真实 Provider 响应 HTTP 200、`finishReason=tool_calls`、正文 0 字符。模型实际看到该请求并返回了工具调用；现有持久证据没有保留该次工具名和参数，不能猜测其确切内容。
3. 对应 Work 最终 `model_tools / blocked / cancelled`，发送尝试与确认均为 0；没有找到该事件的任务交接记录或平台任务。
4. 原 AI 进程于 02:26:53.530 接到 `managed-stop`，02:26:57 更换。停止路径会取消 SDK 活动任务，与该次取消一致；为何部署空闲门判定允许停止、为何工具响应到停止之间尚未结算，仍需调查，不能仅凭时间接近宣称唯一根因。

结论：不是“模型没有看到提醒”。未创建任务；取消与生命周期/恢复缺口尚未收口。旧提醒不重放。

补证：实际 `pipeline_events` 当时只有入站 `at`，没有更新时间或结束时间；该事件的五份已知模型诊断文件也只有 completed/tool_calls，没有后续取消记录。因此既不能证明取消先于停机，也不能证明由停机引发。当前生产与部署验证快照的活动统计实现一致，正常 SDK pipeline await 时 pending 非零，不支持“已确认统计漏报”的说法。

### 第二次：03:03:33「那你1分钟后叫我」

1. 实际协议时间为 03:03:34，事件 `150483576`。模型调用了 `propose_background_task`，`delay_seconds=60`。
2. 03:03:41.416 保存真实交接请求 `430aed0f-0021-5fb5-ab97-ddb9dce0e626`，最早执行时间为 03:04:41.416。工具明确返回 `pending`，并说明尚不等于平台注册或已安排执行。
3. 「这次真排上了」超出了当时 pending 回执的证明范围；后一句「等平台确认」反映了尚未接管。不能根据这两句文本认定成功。
4. 平台于 03:05:07.487 接受并落库，晚于最早时间约 26 秒。动作 `510c9125-684f-4ab8-97a4-e796609ff928` 于 03:05:07.809 开始，03:05:08.816 阻断。
5. 真实诊断定位 `readonly_journal.py:641 prepare`：内部临时 Work 的元组 key 被作为 SQLite 会话参数，触发 `ProgrammingError`。Provider 请求数、模型调用数、工具执行数与 QQ 发送回执均为 0。
6. 平台目标最终 abandoned，cycle 为 handoff_blocked；没有证据表明提醒曾发送。

通用修复 `8ed14ae`：内部临时 Journal 的非字符串 owner 不再充当 SQL scope，仍保留退休防复活检查。Windows runtime 16 项、readonly 27 项通过；Linux native_internal、readonly_journal、semantic_runtime 通过。版本 `semantic-batch-20261111-8ed14ae` 已部署并核对产物，Agent 与 QQ 协议进程保持，4 个 QQ 连接未重启。

## 取消诊断、停机与工具边界

提交 `681968d` 在既有 `pipeline_events` 增加 updated_at/finished_at，并在既有脱敏诊断中记录 pipeline_result 与取消时真实 raise-site。finished_at 仅表示一次激活结束，包括 waiting，不代表永久 Work 或用户任务完成；旧行保持 NULL，不伪造历史时刻。日志写入失败不能影响业务结算。

新增诊断 5 项、停机活动表征 3 项通过；相邻 BotPipeline 12、pipeline boundaries 10、worker lifecycle 4 通过。主智能体完整执行 autonomous_pipeline_test.py，退出码 0，覆盖真实 SDK 工具和 fixture 协议下的 confirmed/unknown、分段、身份与中断边界；不是实际 QQ 发送测试。最终合并候选 `semantic-batch-20261111-681968d` 在 Linux 隔离环境执行 BotPipeline、停机表征、完成诊断、认知审计四文件均通过；尚未部署。

停机表征测试稳定复现了“最后一次 idle 采样后，新 pipeline 进入，随后 stop 取消它”的竞态，但不证明历史提醒实际命中。现有停止 helper 只给 SIGTERM 5 秒；简单添加长 drain 无效。brain.drain 只管理内部任务，不能假称排空全部入站；直接关闭平台入口又会丢弃未持久化新事件。当前保留原运行策略，没有仓促新增第二调度或盲目重放。

SDK max_steps 仍为 5，外层 4 Pass 仍是激活预算；现有 12 次工具测试显式使用 fixture 的 16 步预算，不能当作生产支持 12 次调用的证据。本次两条历史提醒均没有达到工具步数上限的实际证据，因此未扩大限制。
