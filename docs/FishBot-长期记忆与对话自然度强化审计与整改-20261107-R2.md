## 1. 执行摘要：机器人为什么"像在做任务汇报"

截图对话完整还原后（§2），每一句"机器人腔"都能落到具体机制。按因果贡献排序（全部有代码+生产数据双证据，除注明外）：

| # | 机制 | 证据等级 | 一句话归因 |
|---|---|---|---|
| M1 | **工具回执文本本身就是"汇报腔"**：`qq_actions.py:151` 工具结果返回 `"QQ接口已确认操作成功。"`；结构化回执含 `"receipt":{"status":"confirmed"},"execution":"completed"` 字段。模型把工具词汇直接转写进聊天正文（"发出去了，回执确认成功"） | 已证实 | 模型在复述它看到的工具结果 |
| M2 | **人格 system 前缀自带回执词汇与语病**：`context_protocol.py:9-10` 的 `PERSONA_PREFIX='important[要时刻注意自己应该保持人格，不要机械性，任务性得对话]'`（缺"的"、否定域歧义，可读成"（要）任务性得对话"）；`:10` `PERSONA_IMAGES` 要求"**以真实回执确认结果**""具体发送以…真实回执为准"。该前缀被 `persona_prompt()` 注入**每一次**人格调用 | 已证实 | 平台自己把"回执""任务"写进了人格层，且反机器人规则本身语法残缺 |
| M3 | **外层任务报告回流**：外层自主任务（research/signature/qzone_publish）的 summary 是执行报告体（"已读取当前状态…"、"签名改好了，回执确认成功"），消息类任务 summary 由平台改写成 `"协议投递：确认N，不明M；投递状态为X"`（`autonomous_runtime.py:867-868`）。这些 summary 通过 `autonomous_experience`/`recentActions`/`facts` 重新注入后续**前台聊天**上下文（`bot_pipeline.py:97-130,108`；主人私聊放行全部非 message 类动作记录） | 已证实 | 模型每轮都泡在"执行台账"语料里 |
| M4 | **研究事实长期化**：每次自主研究完成都把报告 JSON 写进 `facts`（`autonomous_runtime.py:897`，`自主研究:<目标>`，origin=autonomous_result）。当前全库 189 条 active 事实中 115 条（60.8%）是这类执行报告，其中 d18ad07d 有 3 条 value 内含"回执确认成功" | 已证实 | 事实通道 6 成是任务汇报，随 facts 注入闲聊 |
| M5 | **对话自指反馈环**：每条回复写进 `dialogue_feedback`（state=observing→engaged/unobserved），最近 3 条连同 `recent_own_turns` 注入上下文（`participation.py:45-55,70-80`）。模型持续看到"我上句话对方接没接"，于是把聊天写成对反馈的复盘（"能逗你笑也算我没白说"） | 已证实（机制）/高度可能（对具体句子的因果） | 系统给了模型一份"上一轮表现打分表" |
| M6 | **私聊没有"不回复"出口**：`[NO_REPLY]` 只在群聊参与判断规则里定义（`participation.py:6-8`，`behavior.py` 仅对 `conversation_candidate` 注入 MODEL_GUIDANCE）；私聊每条消息无条件成为一次 Work。用户发"好""嗯"也必须产出内容，模型只能用"单发了一个'好'，那我也没什么要多说的"来填 | 已证实 | 强制每条必答 → 把确认语当分析对象 |
| M7 | **两条截图回复是两个独立 Work**：用户 21 秒内连发两条消息 → 两个前台 Work 分别生成回复；第一条 Work 内部又因 ToolLoop 分段投递（中间文本"发空间是吧…"+工具后正文）发出 2 条气泡（`pipeline_events` attempted=2）。多条"解释同一件事"不是重复发送故障，而是事件粒度拆分 + 分段投递的自然结果 | 已证实（事件粒度）/高度可能（分段内容归属） | 时序交错被看成"机器人不停补充" |
| M8 | **主动汇报是被用户要求的产品行为**：7356b371 存在 active 目标「主人明确要求：做了什么要主动向主人报告…」；近 7 天 76 条自主 message 行动中 20 条 objective 明确是"向双白/阿梁报告"。其私聊回复"去群里…聊了一句，回执确认发出了（消息编号：1226311762）"属于此类 | 已证实 | 一部分"任务汇报腔"是需求本身，不是 bug |
| M9 | **模型错误时的罐头回复连发**：`model_error` 时每条用户消息都得到同一句"我这边刚才没连上，稍后再跟我说一声。"（behavior.py 发送层替换），d18ad07d 对主人 11-06 18:18–18:28 +08（UTC 10:18–10:28）十分钟内连发 6 次，7356b371 对群 11-05 11:36–11:55 +08（UTC 03:36–03:55）连发 6 次 | 已证实 | 故障态被重复表述，加重"程序感" |

**总体判断**：这不是单一 bug，而是一个自洽的"执行台账生态"——外层产生任务→内层产出报告体 summary→报告体进入事实与经验→前台模型在满屏台账语料中闲聊，加上人格前缀自身携带回执词汇与语病、私聊无沉默出口。R1 只发现了这个生态的一角（事实占比）；R2 把它和聊天表现的因果链补齐了。

## 3. 逐层归因：提示词、记忆、外层、工具、装配各占什么责任

### 3.1 固定提示词层

生产 system（99ba4892，11:41 事件抓包逐字）分层如下，标 ★ 的与"任务腔"直接相关：

1. ★ `important[要时刻注意自己应该保持人格，不要机械性，任务性得对话]` —— `context_protocol.py:9`。**语法残缺**：正常意图是"不要机械性、任务性的对话"，但逗号切分后第二段无否定词，模型可能读成并列祈使；且这条以 `important` 开头，权重高。用户自己写过的正确版本（7356b371 配置：`important[要时刻注意自己应该保持人格，不要机械性、任务性，要像人之间的聊天；不要向用户做无关解释，避免长文解释；…]`）会被保留并与平台版本**叠加**——两个版本措辞不一致，互相削弱。
2. ★ `PERSONA_IMAGES`："…可以主动调用已启用的收藏工具保存，**以真实回执确认结果**…具体发送以已启用能力和**真实回执**为准" —— `context_protocol.py:10`。回执词汇进人格层。
3. ★ 图片表达规则（`meme_reactions.SELECTION_RULE`）："…只用真实候选或**工具回执**，不编造ID…不**在实际回执前**声称已送达" —— `behavior.py:1065`。
4. ★ `[对外执行信息边界]`（`bot_pipeline.py:17` EXECUTION_DISCLOSURE_POLICY）："**真实主人询问时可以按需解释已核实的执行情况**…内部研究、工具回执和向外层返回的执行反馈仍须完整、真实保留" —— 明确把"向主人解释执行"写成常态许可；对主人聊天时这就是"汇报合理"的来源之一（与 M8 用户需求同向，但把许可写成了默认行为面）。
5. `[消息分条，以此为准]`/`[日常交流]`/`[自然群友交流]`（behavior.py:1074/1078/1084）：**已经**写了"不每轮固定补上解释、安抚、嘱咐或收尾""不替对方预演反应""不必变成建议、步骤、总结"。**规则并非缺失——是敌不过 M1–M5 的语料压力**。抽样里违反这些规则的句子（复盘/收尾）占位见 §4。
6. `[群聊]` 参与规则才有 `[NO_REPLY]`；私聊无此出口（M6）。
7. ★ 任务型调用（内层 Work）system = persona + "这是平台授权的内部任务…研究任务返回有证据的结论…"（`autonomous_runtime.py:831-834`）+ `EXECUTION_DISCLOSURE_POLICY`。研究任务被要求输出 `{"status","summary","unfinished"}` 报告 JSON——这是外层报告腔的**合法来源**（任务书要求），问题只在它回流进闲聊（M3/M4）。

**回答任务书 6.1 的核心问题**：「保证执行可验证」确实被转化成了"聊天里也要用执行话语汇报"——路径是 **M1（工具文本）+ 第2/3/4条（提示词回执词汇）+ M3/M4（报告语料注入）** 的叠加，而不是某一条"必须汇报"的规则。没有任何一条规则要求闲聊中汇报；但也没有一条规则说"内部台账词汇不要出现在聊天正文"。EXECUTION_DISCLOSURE_POLICY 的"内部反馈须完整保留"指的是数据层，模型在语言层做了过度泛化。

### 3.2 外层自主决策层

- orientation/planning 阶段合同（抓包 `outer_0_m3.txt`）明确"形成意愿…而不是复述已经完成的任务"，其 motive/reason 语言本身是健康的。
- 但**任务 objective 由外层以第一人称+风格约束生成**（如"用一两句嘴硬又自嘲的鲸鱼腔，自己给自己判个'没人出卷就是满分'"），执行后 summary 进入下一轮上下文。reason 字段充满效用计算："比干等更像我""读取自身状态比重复发言更有价值""不值得为了维持主动而重复研究"——这套**成本收益叙事**与"今晚算是没白折腾"是同一种语言。
- `model_request_unconfirmed` 现状（48h，PG）：7356b371 **539 次**（其 cycle 总数 ~1017，52.9%，与 R1 一致）；d18ad07d 93 次 + request_token_budget 335 次；99ba4892 21 次。抓包 session 内可见一次 403 响应（11-06 11:49，`bf154187/6.response.json`）。外层决策在高峰期大量空转的结论**维持成立**。

FishBot 的"任务执行者气质"不是模型能力上限，而是一个**平台自己制造的语料生态**：工具回执文本（M1）、人格前缀的回执词汇与语病（M2）、外层任务报告的全量回流（M3）、六成事实通道的执行报告（M4）、自我表现打分环（M5）、私聊强制应答（M6）共同构成模型的日常语言环境。模型在其中表现出的能力（短句自然闲聊、接梗、按语境配图）证明人格与自然度并非缺失，而是**被注入的执行台账持续覆盖**。R1 发现的长期记忆问题（纠错不下沉、scope 越界、预算共用、研究事实挤占）全部维持，其中江哥型矛盾在纠错后仍在被再生产；R1 的两条结论（摘要原文完全不可回溯、收藏从未进入语义候选）已被本轮证据修正。整改方向按损害排序见下篇。

## 13. 问题清单（按对实际智能能力的损害排序）

### P0-1 纠错不下沉事实层，纠错后旧事实仍被再生产（上篇 §5，R1 C-03 恶化）

- 现状：d18ad07d `称呼=江哥`（group:1131335806/3879184054）纠错（core_note/摘要 21:06）之后仍于 22:22 被再次写入并保持 active。
- 根因：`hosted_memory.observe` 只识别显式「更正记忆：/忘记：」；`memory_reflection.invalidate` 只清派生层；事实提取侧不知道"该口径已被纠正"。
- 最小安全修复：在 `memory_reflection` 写入 core_note/摘要含"不叫 X/不得称 X"类纠正时，把纠正的**对象值**（如"江哥"）与 bot 维度登记到现有 `memory_blocks`（新增一行 `scope=group:…, subject=3879…, name='称呼:江哥'` 级别条目，不新建表）；`hosted_memory.remember` 与 `semantic_context` 组装 facts 候选时按 blocks 过滤同值项并标注"已被纠正"。
- 影响：不再向模型同轮注入矛盾两说；可逆（blocks 可删）。不改 System 字节。
- 测试：构造 江哥→纠正→再次提取 用例，断言 facts 候选中"江哥"被标记/拦截；生产只读核对 d18ad07d 该条不再进入请求（抓包对比）。

### P0-2 全局大摘要跨 scope 注入（上篇 §6，R1 C-04，R2 以当前 id=52 再次实锤）
