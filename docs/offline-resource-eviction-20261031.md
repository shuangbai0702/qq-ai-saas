# FishBot 内存与离线资源清退验收（2026-10-31）

已实施并部署到真实 Linux。最终规则采用用户最后指定的上限：启动中 120 秒、等待 QQ 连接 180 秒、持续离线 300 秒。自动重试不重置已观察到的阶段计时；用户主动启动或重新登录开启新代次。达到时限后由持久化命令停止对应 AI、NapCat/Mock 及受管子进程，成功释放后状态为 `offline`。

## 当前实例数量

生产保留 4 条机器人配置：1 个在线、1 个已清退为 offline、2 个 stopped。最终 Linux 进程实扫只有在线账号对应的 **1 个共享 AstrBot + 1 个 NapCat**，没有独立 AstrBot 或 Mock 协议进程。账号记录不删除，因此机器人总数仍为 4。

Docker 的 API、Agent、PostgreSQL、gate 四个基础服务容器继续运行。这是保留的独立部署架构，容器数不等于 QQ 运行实例数。

## 内存调查与实施

- 本次 Linux 全机实扫只发现一个独立 AstrBot，属于未连接 QQ 的 Mock 测试账号；未同时复现截图中的两个独立实例。该账号现已自动清退，独立 AI 和 Mock 进程均已消失。
- 独立 SDK 拥有各自 Python 堆和模块缓存；共享 SDK 复用同一个运行时。冷态共享 PSS 26 MiB 与热态独立 PSS 146 MiB 不能直接作固定开销比较。现场独立 AI 冷态快照为 PSS 9.17 MiB、USS 6.67 MiB、SwapPss 151.23 MiB，说明大量页确实能换出。
- 所有受检运行时均被控制器归入正确 cgroup。进程迁移后旧页仍可记账在父 cgroup，因此不能把子组 `memory.current` 当成该进程的实际 PSS。
- 修复空闲运行时每 5 分钟重复执行全堆 GC 的问题：同一活动周期只收集一次；新活动之后仍允许下一次空闲收集，保留 SQLite shrink 与 malloc_trim。
- 主机控制器设为开机启用、退出后自动重启；独立 guard 在异常时放宽软限制，连续健康约 30 秒后恢复。真实触发验收中，全部登记软限制成功放宽，约 33 秒后重新启用，随后取得新的控制器采样。
- zswap 保持启用，Swap 总量约 2 GiB。没有用“Swap 已使用”冒充物理内存，也没有为了低数字杀死在线账号。

## 真实 Linux 验收

| 场景 | 实际结果 |
| --- | --- |
| 真实 AstrBot 在启动时被暂停，无法就绪 | 127.386 秒后 AI、Mock 协议均释放；120 秒为触发上限，余量来自检查和退出等待 |
| Mock 持续等待 QQ 连接 | 185.313 秒后释放；同组在线成员和共享 PID 保持正常 |
| 真实 QQ 协议暂停 7 秒 | 原 PID 保持，恢复在线，没有清退 |
| 真实 QQ 协议持续不可用 | 首次确认故障后约 300.7 秒进入清退，约 311.4 秒完成释放；外部测试轮询及数据校验完成于暂停后 328.7 秒 |
| 清退后重启 Agent | QQ 仍为 offline，没有重新拉起协议或 AI |
| 主动启动真实 QQ | 读取原会话免扫码恢复 online；发送并回读验证成功 |
| 清退后主动登录（隔离测试） | 真实 SDK、Mock OneBot 重新创建，并完成 SDK→模型→协议回复 |

真实 QQ 使用受控的协议不可用故障，没有调用原生退出登录使保存的登录凭据失效。账号终态离线、短断线、协议故障和登录等待的分类另有策略及生命周期测试。隔离验收使用真实 AstrBot 子进程、真实 OneBot WebSocket、Mock QQ 传输和固定回复的模型服务；不把它描述成手机扫码或生产模型验收。

生产保留校验：用户、租户、成员关系、配置版本、密文 Key、QQ 绑定和机器人身份字段的摘要前后一致；清退期间 2,275 个非日志 QQ 文件逐字节摘要一致。没有删除账号、人格、记忆目录、会话或身份文件。

下表来自同一次真实 QQ 验收；清退前后均无隔离验收进程常驻。中间运行过独立的 Linux 测试负载，因此整机数值仍包含其遗留文件缓存、其他服务换页等影响，不能将全部差额归因于单一代码改动。

## 消息、竞态和恢复

- 固定模型服务的 Linux SDK 基准，清退前 20 次、恢复后 20 次均收到回复；P95 为 1.526 秒 → 1.510 秒，增量 −0.016 秒，满足该受控基准的额外 5 秒约束。生产真实模型尚无足够配对样本证明其 P95。
- 真实 QQ 的发送加回读耗时为 1.053 秒 → 1.032 秒；这是协议链路检查，不是生产模型端到端 P95。
- 清退持有机器人行锁，并检查代次；新登录/启动可以替代待执行清退。真正停止前再次探测，若协议和 AI 已恢复则撤销清退。新登录递增代次，防止迟到操作杀死新实例。
- 清退共享成员只做非永久摘除；还有在线成员时不停止共享组。使用同一数据库事务，避免单连接池下二次查询死锁。
- 过期或主动取消二维码会持久化清退，不再被自动恢复重新拉起。失败的清退会保留错误并重试，尚未成功释放时不显示“资源已释放”。
- 修复 NapCat 原生接口已连接但漏发启动回调的情况：两秒后只补查一次，而且不会与已经收到、仍在等待的原生回调竞争。SDK 修复在构建和独立 Agent 启动时幂等应用，覆盖容器重启与重建。生产 SDK SHA256 已核对为官方固定 Linux 包加本次 V2 修复，无临时诊断代码。
