## 2. 重要架构修改与理由

1. **许可与 stage 原子绑定**：把"许可已用"的定义点从 HTTP 后 settlement 前移到候选落盘。此后不存在"许可可能已用但状态还是 reserved→available"的窗口；代价是少量未发出的请求保守耗用许可（计划明示接受）。
2. **SystemContract per-scope 化**：Journal strict 已逐字节保护每条 wire 的 System 向量，全局单基线只在"一个 scope 先完成合法重构"时制造误伤。按 scope 独立基线+按 scope 消费可信 token 后，检查强度不降、跨 scope 误堵消除。
3. **计轮点后移到 Work 终态**：与 `pipeline.finish` 邻接，一个 Work 最多一轮、材料=全部确认输出；pending 答案逐气泡由既有 `confirmed_prefix` 实时维护，崩溃窗口的材料可从 pending+wire 恢复。
4. **受众三维度拆分**（author/source_scope/audience）落在 `memory_audience`+`summary_rows`+`pending_messages`+`retained_context_visible` 四处一致；跨场景连续性改由 facts（语义投影）与 R5 agreement 视图承担，而不是原文流动。
5. **删除 web→Journal 许可**而非修补：配置保存授权的是"改配置"，不是"删模型历史"。新 System 在该 scope 下一枚合法 35 轮许可时生效（Journal 已原生支持该延迟生效）。
