# 废除黄头像、使用真实大肥鱼动图

用户要求：废除的三张黄头像不能再发送，平台默认使用鱼动图；保留刚完成的带图文字分段。主人主动联系继续观察，不调整策略。

## 实际根因

Linux鱼图包的157张文件均存在，4个运行机器人的配置也都选择了 `blue-fat-fish`。真实发送记录却出现了 `thinking`、`laugh`：`SocialStore.catalog` 仍无条件把 `templates/reactions` 的三张旧图和鱼GIF混入同一候选，旧API及界面也仍把它们列为内置基础图。上轮分段修改没有改动这个目录，验收遗漏了旧图下线不完整的问题。

过去部分正向测试还用 `[MEME:laugh]` 验证能发图。此次将正向SDK夹具改成从本轮真实候选里选择鱼GIF，并增加明确拒绝旧ID的检查，避免“能发图片”掩盖资源不符合要求。

## 修改与保护

- 运行时不再加载旧基础图目录；`hug/laugh/thinking` 即使有旧的启用覆盖文件、旧候选或历史图片标记，也不能恢复为可发送图片。
- 三份旧元数据标记为停用和废除。PNG及版权信息仅保留为隔离测试素材，不删除用户数据，也不作为运行时兜底。
- API不再列出、读取或重新启用旧ID；管理页面删除“另含3张内置基础图”及对应入口，保留Windows现有CSS。
- 缺失图包字段的旧配置采用与新建配置一致的鱼图包默认值；显式空选择仍表示停用鱼包。现有4个机器人配置无需改写。
- 用户上传图片、群内审批表情、QQ收藏、普通图库及多租户归属继续沿用原规则；本次不清空这些用户资源。
- 图片仍由模型按当前候选判断；保持原冷却、敏感场景保护和发送前校验。鱼GIF与文字分段、首段艾特和末段单次配图共用原发送链。

- Windows生产构建通过。受影响17项检查中首次16项通过，鱼包检查因旧预期“默认3张基础图”失败；将其改为严格验证默认鱼包、停用一张后156张均为鱼，并保留选中停用图不能发送的断言。对应鱼包和原生媒体6项复验全部通过，其余已通过检查未削弱。
- Windows浏览器检查通过：鱼图可见且真实HTTP返回 `image/gif` 与GIF文件头；旧基础图说明不再出现；图库上传、持久化、分区及390px布局正常。
- Linux实际容器完成5组Python检查、6项社交/鱼包API检查、1项真实AstrBot SDK集成检查及生产构建，全部通过；总计125.5秒。API/SDK使用独立PostgreSQL临时库和角色，测试后移除，未使用生产消息或用户Key作为夹具。
- 39个当前JS入口与Web产物共58份受控产物逐一匹配Windows。用户CSS哈希保持不变。
