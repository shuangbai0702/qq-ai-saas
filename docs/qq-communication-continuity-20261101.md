# QQ 跨会话接续与真实艾特

## 本轮依据与计划

用户提供了真实聊天：私聊要求机器人去群里叫人，机器人要求用户先在群里开头；群内回复只有文字“@主人”；用户已在群里说话，私聊却说尚未收到。用户随后明确要求未压缩消息先参与临时记忆、摘要生成后替代，并要求查明为何一直未主动找主人。

1. 未摘要的真实协议消息先作有界临时记忆，覆盖尚未回复的群消息；同一机器人同一真实QQ跨群/私聊可读，保留来源和时间。成功摘要只移除实际覆盖且未在异步期间变化的临时记录；失败、重启、更正/遗忘与租户隔离需验证。不额外增加摘要调用频率或引入常驻服务。
2. 群内模型回复可输出真实At，依据协议QQ和当前群成员核验，字面昵称不猜账号；保留分条节奏、图片末条一次、配置替换后的迟到发送保护。
3. 主人明确要求时提供受控跨群工具，仅当前机器人已加入且主人在内的允许群；目的地不明确询问，成员核验、事件去重、超时不重试、不借用其他机器人权限。自动搭话白名单与定时策略不因此扩大。
4. 只读核对主动主人判断、计时和阻断原因，以真实运行证据决定是否修复；不为测试强行发送或重置生产额度。
5. Windows针对性回归、Linux原生SDK和数据副本验证后，仅部署受影响AI代码，保留回退和全部持久化数据，Agent与QQ进程不重启。最后按计划与实际结果收口并同步代码。

## 初始实际证据

生产记录确认11:23内容来自私聊，11:25内容来自群聊；群聊回复为普通文本“@主人”。人格工具列表为空，现有额外工具仅QQ资料/空间；定时主动选人已有At发送，但没有普通回复的模型At表达入口。跨会话只召回长期事实与摘要，原始待摘要材料和未回复群消息没有进入私聊候选。

主动主人设置为开启，间隔60分钟、空闲30分钟、每日判断12次；当天已有3次检查、没有主动发送记录，最近真实互动持续更新计时。旧检查原因没有持久化，需要进一步验证10秒判断超时与实际模型耗时的关系。

### 主动找主人的实际计时测试

原配置为判断间隔 60 分钟、空闲 30 分钟、主动联系冷却 3600 秒；真正与主人交流会刷新全局互动时钟，其他会话也会影响是否到时。达到时间只是进入模型判断，不保证发送。每日次数、未回复上限、安静时段等保护仍在。

- 11:55 的旧版实际调度检查没有产生发送，旧版缺少持久化原因，不能断言是模型拒绝或超时。临时参数已恢复。
- 新版部署后，按用户“立即改计时”要求，仅将目标机器人临时改为间隔 15 分钟、空闲 5 分钟、冷却 900 秒，并有条件提前它的判断时钟。没有更改真实互动时间、联系人消息、聊天记录、发送额度或其他机器人的配置。
- 12:01:53 正常调度器发起真实模型判断，6029 毫秒完成，持久化状态为 `model_silent`。联系人 `last_attempt` 仍为 0，无私聊发送预约及发送记录。此次没有超时，也没有强制改成发送。
- 判断结束后恢复原配置。后续核验目标完整配置哈希与测试前相同，原判断记录在配置重载后仍保留；其他机器人的配置版本、运行代数均未变化。

结论：本次确认计时器正常执行，当前这一轮未联系是模型的沉默选择。旧日多次未发送的具体原因无法追溯，不能用这一次的结果补写历史。两次只读模型探针约 4.7 秒、7.0 秒，加上真实检查约 6.0 秒，均不足以形成 P95 结论，因此没有扩大生产判断超时或增加反复重试。

### 与原计划的偏移及边界

1. 用户明确追加“立即改计时”后，从只读调查扩展为目标机器人一次受控真实计时测试；所有临时参数已恢复，没有向生产注入测试聊天或强行发送。
2. 主人判断不是仅补日志，同时加入原先缺失的同人记忆和通用联系动机信息；仍由模型决定是否联系，保持原时间、额度与防打扰边界。
3. 新增跨会话原始材料读取是用户本轮明确授权的范围变化；仍限制当前机器人、同一可信 QQ，不合并全体群成员历史，也不扩大自动群搭话白名单。
4. 没有重建或部署 Web/API；本轮运行变更仅涉及 Python AI 适配层和 Mock 测试支撑，已有编译产物核验未变，避免覆盖正在由另一位 AI 修改的前端。
5. 用户最新要求不赶 Git/Windows 同步，因此部署优先于 Linux 标准检出目录同步。实现节点此前已经提交推送，Windows 后端源码已是该版本；本报告补充的实际验收结果暂未另行提交。

尚未拿到新版真实主人主动私聊及跨群工具发送的正向生产回执，不能宣称全部真实消息场景验收通过。临时记忆、权限隔离、发送链路及失败/竞态行为已有 Linux 原生 SDK 和生产数据检查证据。

## 追加计划：模型判断社交距离，保留可配置判断冷却

用户随后明确修正：不增加姓名关键词直接唤醒；普通群消息仍须白名单、新消息和用户设置的判断间隔同时满足。是否被讨厌、是否需要收住等由模型结合语境判断，只增加有限、可到期的冷却，延长多少由模型选择。完成后继续验证主人主动私聊。

1. 追查旧群级拒绝标记的现存来源。区分原始消息、备份状态与无法追溯的推测，不把旧标记当作被讨厌的事实。
2. 去掉聊天关键词直接写入永久群拒绝和固定八小时告别暂停；真实消息只记录事实。模型可在现有群参与、主人判断和日程调用中选择额外冷却，不新增常驻服务或逐消息判断调用。
3. 用户配置的间隔为基础；模型选择额外间隔数，有限上界用于防止无效数值形成永久停止。新消息、真实互动刷新、白名单、手动暂停、安静时段、未回应及发送额度边界继续生效。普通@和引用不受自主入场冷却阻止。
4. 保存判断原因与冷却来源，补充配置重载、到期、异步迟到、失败与租户隔离测试。检查跟聊/疲劳/情绪是否另有永久或不合理硬拦截。
5. Windows 与 Linux 原生验证后部署受影响的 AI 代码；协议进程不重启，不覆盖网页工作。恢复生产参数，再核对真实群参与和主人联系回执。

此前准备过的“人格姓名开头直接触发”草稿已按用户修正撤回，没有部署；相关私有草稿验证记录不计入本计划验收。

### 追加范围：更自然地主动联系，并复核群聊

13:30 后用户反馈仍未主动私聊，要求更主动并查看群聊。只读生产检查证实，定时主人判断使用空的原生上下文，临时记忆函数却默认排除当前会话，导致缺失当前私聊尚未摘要的前文。实施范围如下：

1. 主人判断分别读取同人的有界私聊材料和跨会话材料，保留来源、时间和原发送者；记忆关闭时不读取，普通回复仍不重复注入原生当前会话历史。
2. 通用判断提示允许熟悉关系中的自然靠近、好奇与分享，不以未完任务为前提；暂无话题通常只保留基础间隔。群聊解释既有参与风格，真实称呼及指向仍由模型结合语境判断。
3. 当前授权目标的主人判断间隔改为 30 分钟、空闲要求 10 分钟、每日判断上限 24、每日主动发送上限 10 次（用户随后明确指定）；群参与风格设为 active，群判断间隔仍 15 分钟。保留未回复不追发及全部身份、白名单、安静时段和内存保护；其他账号配置不改。
4. Windows 针对性测试、Linux 原生 SDK 回归后部署 AI 源码，再经正常配置 API 应用参数，核对真实群/私聊回执。已有模型冷却和真实交流时钟不为制造成功而重置，不覆盖网页或推 Git。

### 后续用户修正与最终管线验收

上述 15 分钟群间隔、目标账号每日判断 24 次及仅更新该账号，是当时的历史计划。用户随后明确改为所有机器人的默认：群间隔 **10 分钟**；主人判断 **30 分钟**、空闲 **10 分钟**、实际定时发送每日 **10 次**；取消旧的每日 6 次日程规划判断上限，冷却到期应检查已收到的消息。主人判断默认上限 48 次，用于覆盖每日 30 分钟判断机会；这与不限日程规划、实际发送额度分别处理。

这些配置已通过正常配置 API 应用到 7 个现有非删除机器人，保留显式停用、定制值、白名单与安静时段。整机主干管线和完整 Plan vs Actual 见 [机器人管线合同与验收](robot-pipeline-20261101.md)。

真实生产正向证据已补齐：14:51 正常主人判断选择联系，2 条私聊发送均有协议确认；14:59:57 调度器自动补判冷却期间留下的真实群消息，无需再等新消息，本次判为他人定向交谈且该配置不允许介入，因此沉默。普通群回复与自动鱼动图也有真实回执。新版主动群插话正向生产发送、真实跨群工具发送及长期延迟 P95 仍不应宣称已全部验收。
