## 当前实际状态与任务化来源

生产4个在线机器人均开启平台表情、群语境、疲劳、人物记忆与摘要；仅2个设置了可信主人，只有1个配置主动联系目标。当前使用机器人的主动开关为开，但目标为空，模型日程规划为关。因此它可以按群触发条件接话，却不会靠定时调度主动找人。另一个已配置联系人的机器人达到1次未回应限制，停止继续追问符合当前配置。

4个机器人的注意力开关均为关闭。现有开关只是词组硬过滤，不等于兴趣与关系驱动的语义注意力；此前为避免正常接话被误挡而关闭，这次不批量打开。疲劳是5分钟4次输出后抑制自动接话，直接@和指令仍可应答；这不是有情绪变化的“话题聊腻”。每机器人全部群的滚动小时20次尝试限制独立生效。新默认随机插话3%，另外3个已有配置仍显式保存1.4%，不能用修改默认值冒充覆盖了它们的保存值。

自己的喜好目前主要来自配置人格与有限对话历史。数据库保存的人物事实属于真实聊天者，未实现独立的机器人兴趣证据、跨日小目标及完成进度。亲密度和5分钟情绪状态有持久化，但不足以代表“她有持续生活和欲望”。调度输入过去只包含最近一问一答，缺少当前人格，也容易生成泛化的提醒或任务式话题。群聊发送工具支持mention_user消息段，但没有接上自主选人、选择@时机及收件人授权的完整决策路径，不能称为自主@已实现。

## 已修复的明确缺陷

| 问题 | 修正与边界 |
|---|---|
| trigger=all绕过疲劳与注意力 | “回复全部”不再等于每条都被直接点名；自动群消息仍受疲劳，直接@/指令保留豁免。内部群主动消息也受疲劳；增加fatigueSuppressed、attentionSuppressed计数 |
| 晚安/再见造成永久拒绝 | 告别改为8小时临时暂停，真实定向交流或明确恢复可结束暂停；真正“不要主动找我”仍需明确允许才恢复。未点名的群内路人告别不再关闭主动联系 |
| 规划联系人被其他会话挤掉 | 在SQL中先筛选授权目标再取最近50条；安静时段与临时暂停不启动规划，保留已有每日额度和迟到结果隔离 |
| 规划缺少当前人格 | 同一机器人规划请求带入有长度上限的当前人格；约束以真实上下文、既定喜好决定联系动机，不默认转成提醒和待办 |
| 否定情绪误判 | 不喜欢不再识别成开心；“没有讨厌”不直接当作讨厌。已有历史分数不凭空重写 |
| 页面只有开关没有运行条件 | 主动开着但无联系人时明确提示不会定时找人；数据页显示告别暂停及到期时间；保留旧库只读展示 |
| 对话过度解释机制 | 开启社交语境的角色补充通用交流规则：在既定人格内保持偏好判断、允许自然联想，不强制总结/建议/追问，不解释触发器，不编造离线经历；不使用针对某个群的台词例子 |

临时暂停新增每机器人SQLite表initiative_pauses，是增量结构，旧版本可忽略。不会自动清除既有opted_out，因为历史拒绝来源不能可靠还原。用户重新输入“可以主动找我”可按既有规则恢复。没有修改任何租户的主动联系人、群名单或主人配置。

## 尚未实现的能力与适合本项目的补法

1. 持续的自我偏好：与用户事实分表，保存偏好、来源、时间和置信度；已有对话/真实活动提供证据，去重、衰减和纠正，不定时随机编造“今天做过什么”。
2. 自己想继续的话题：少量可持久化的未完成话题、联系原因和状态；复用当前调度与每日预算，用户正在聊天时让路。先做聊天内闭环，不增加浏览器/本地模型常驻服务。
3. 群内选择交流对象与@：只从当前机器人、当前授权群的可信近期成员ID选择，最多一人，禁止@全体与自由构造陌生QQ；遵守退出、冷却、疲劳和小时额度，模型不能指定跨租户目标。
4. 兴趣与关系注意力：沿用一次正常模型回合判断是否参与；轻量兴趣信号只排序，不靠词组不重合一票否决，也不为每条路人群消息新增分类模型请求。
5. 话题疲劳与关系变化：与现有发言密度限流区分；真实输出后记账，同一人重复与其他人的正常提问分开，直接请求不因虚构脾气被丢掉。

上述五项是明确的能力缺口与后续实现方案，本轮没有把它们伪装成已部署功能。
