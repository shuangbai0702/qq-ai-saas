## 为什么最新快照仍然大

样本完整最新快照 51,226 字符（不是 Token），结构主要为：

| 部分 | 字符数 |
|---|---:|
| 7 个会话的共享上下文 | 32,355 |
| 自主执行经历 | 6,439 |
| 工具执行经历 | 3,454 |
| 目标 | 2,848 |
| 近期动作 | 2,253 |
| 反馈 | 1,371 |

表内是不同分支，无需把父子字段再次相加。剩余是其他状态、身份和 JSON 结构。

会话内部各字段值的合计长度：recent_messages 9,129、conversation_timeline 3,987、state 3,362、companion 3,325、dialogue 3,225、recent_cross_session_messages 2,978、persona_core_note 2,324、conversation_environment 1,248，另有身份及引用结构等。这些数不含键名开销，不能与父对象字符数严格相等。说明实时快照中混有大量近期背景、记忆和经历；它不是每轮都变化的纯状态。

不能仅凭字段名称认定重复后删除：需按事件 ID、经历 ID 和来源比较，保持会话归属和记忆完整。应把可证明不变的历史资料移入稳定历史，仅把当前有效的状态留在尾部。旧历史里的当时状态也要明确属于历史，后端身份、权限、工具仍实时校验。

## 技术取舍与后续条件

1. A：没有旧快照负担，模型当前状态更明确；稳定历史前缀可持续复用的实际效果，依赖当前服务商是否支持并真正写入断点。推进新断点还需验证旧断点查询与新断点写入，不能只验证参数接受。

3. 不建议现在直接替换。先向中转确认受支持的显式断点路由/参数；如有可用路由，再跑 A 完整三轮及冷启动、摘要重建、身份变化、工具链用例。迁移 Responses 如有必要应单列适配与回归，不能假定只是改 URL。
4. 无论选择哪种布局，都应拆解当前大快照，识别稳定背景与真实动态字段，避免把所有重新采样的数据都视作实时状态。
