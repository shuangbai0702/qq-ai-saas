# 主人联系与回复分条修复（2026-11-01）

本次处理当前机器人不主动联系主人、闲聊经常三段的问题。未实施主动型 AI 架构调查中的新内核或自主循环。

## 根因与修改

1. 生产主人私聊的一次主动联系记为 `unanswered=1`，配置 `maxUnanswered=1`，使后续主人判断在调用模型前被硬性拦截。按本轮要求统一为 `maxUnanswered=4`：已有 1–3 次未回应仍可判断，第 4 次未回应后停止后续主动尝试。模型仍决定是否联系；安静时段、额度、冷却、显式管理暂停及回执保护继续生效。
2. 主人在群里与机器人真实恢复交流时，只刷新主人互动时钟，未清除私聊未回应计数。现在同一个可信主人、明确面向机器人的新互动可清掉旧计数；旁人、背景消息及不晚于最新主动尝试的旧事件不能清除。保留私聊原始历史、发送额度及管理员 opt-out。
3. 解除计数门槛后，生产首次主人判断确实发起，但命中写死的 10 秒超时。主人后台判断改为 60 秒；群参与判断的独立超时保持原样。失败仍保留判断记录和冷却，不在轮询时反复重试；新消息或配置变化仍使迟到结果失效。
4. 默认源码已是 1–2 条，但生产保存的人格仍含“一到三句”。现统一通用段落为“通常 1–2 条，必要时最多 4 条，不凑条数”，并说明不照搬历史分段节奏。未改成固定条数，也未用概率控制分条。原有四段上限、代码/列表完整性和末段媒体计划保留。

## 应用范围与部署事实

- 全部 8 个未删除机器人的未回应阈值均更新为 4；7 个能确认属于通用模板的表达段落更新，另一个自定义人格未被覆盖。机器人身份、主人 QQ、模型配置、记忆开关及原有生命周期状态均经逐项比对保持一致。
- 3 个在线机器人的配置命令均完成，应用版本与保存版本一致。停止/离线机器人没有被启动，新配置在其下次启动时使用。
- Linux 运行目录与源码检出的 7 个后端模块逐文件验证一致；Windows 同步保留同一修改。API 加载了新的默认值；Agent 没有重启。
- 只改了前端阈值的默认显示与说明源码。未发布前端资源，保留另一个 AI 正在修改的 Windows 样式和页面工作。
- 原配置保留为历史版本；运行文件和源码另有私有回退副本及部署摘要。未进行 Git 提交、推送或工作区覆盖操作。

## 偏移与限制

- 计划中的 AI 单独重载，第一次触发自动恢复失败并重建了一个 QQ 协议进程。它已使用原会话恢复在线；另外两个协议进程 PID 保持不变。不能声称全过程所有协议均未重启，或据当前在线状态宣称消息零丢失。
- Agent 活进程启动早于磁盘后来更新的恢复模块，磁盘代码一致不代表该常驻进程已加载新代码。此次未为加载 Agent 模块而重启全体在线 QQ；此部署问题作为后续维护项保留。
- 第二次 AI 加载使用现有 Agent 的 apply/start 路径，协议 PID 未再变化。辅助就绪检查因比较旧的共享组代次误报超时；已修正该维护脚本，最终状态通过独立原生健康接口验证，未因此重复重载生产。
- 隔离维护实验中尝试过日志管道交接，未通过，未在生产采用；最终没有新增常驻监督进程或产品兼容层。
- 真实下一轮主人联系仍依照原互动时钟、冷却与模型意愿执行；本轮未伪造主人入站、清空真实互动时钟或强迫机器人发送验证消息。60 秒截止时间通过回归及运行文件确认；修复后真实主人判断结果仍需后续自然周期观察。

## 计划与实际核对

原范围“计数门槛、跨群恢复交流、通用表达默认值与已有配置、Linux 应用及回归”均已落地。额外修复了实际暴露出的主人判断超时；其职责仅限后台主人判断，未与群参与时限合并。未改变公共发送、工具、记忆、权限和租户绑定管线，未覆盖自定义人格或其他前端工作。运行中 Agent 的旧模块与实际主动消息的下一周期验收保留为明确未收口项。
