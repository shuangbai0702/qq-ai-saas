## 一、图片重复的真实位置

生产 SQLite 以只读方式读取 Journal v2，校验并还原媒体，分别遍历 `base` 与最终保存的 `wire`。图片身份使用完整 data URL 哈希；来源使用可信 `(scope,event_id)`，不输出图片、聊天原文或账号凭据。

| 机器人 | wire图片位置 | 不同图片哈希 | 有图片的来源事件 | data URL字符总量 | 同事件同图重复 |
|---|---:|---:|---:|---:|---:|
| 梁沅芷 | 113 | 74 | 113 | 2,942,026 | 0 |
| 小双白 | 32 | 29 | 31 | 1,027,330 | 0 |
| 大肥鱼（对照） | 13 | 6 | 13 | 546,421 | 0 |

三者 `base`、`wire` 的 `(scope,event,image_sha)` 多重集合完全一致，额外投影和缺失位置均为0。所有图片均处于有明确来源的 user 消息。小双白唯一一个双图事件包含两张不同图片。

因此，26号113与74之间的39个差额、小双白32与29之间的3个差额，均发生在不同来源事件，不能视作装配错误。旧报告的106/68是较早快照，不与本次113/74矛盾。字符量不等于视觉Token、实际费用或延迟。

实际链路：

1. `shared_context.observe` 从真实 QQ 事件取得作者、Scope、事件ID、时间和附件，首次入池后不覆盖。
2. `queued/compose` 排除已提交事件；邻居 Work 已首次提交的消息直接复用 Journal。
3. `current_view` 不把 SDK 旧历史再次作为新输入；`model_images.constrain_messages` 只处理未提交的新消息。
4. Journal v2媒体仓解决持久化重复，向模型还原原来的完整图片表示；存储去重不意味着可以删除不同历史事件中的图片。
5. SDK ToolLoop 的续轮 `prompt=None`，不会每次重装 `extra_user_content_parts`。SDK两个图片槽存在理论上的同资源重复可能，但本快照未发现对应事件，未为猜测添加业务补丁。

**实际处置：** 保留正确媒体链路，新增回归证明跨事件同图、引用多图、邻居先提交、工具续轮均不破坏历史。没有进行全局去图、转文字、重新编码或统一降质。完整原图及持久化证据保留。

## 二、辅助缓存：当前证据与真实限制

01:39采样前6小时，按 Provider 实际 `request_result` 统计。仅对明确报告缓存且有输入Token的完成请求计算加权率；未知不计为0。

| 小双白阶段 | 完成请求 | 明确0 / 正缓存 / 未知 | 加权缓存率 |
|---|---:|---|---:|
| Foreground | 50 | 11 / 38 / 1 | 66.45% |
| Private Freshness | 17 | 14 / 2 / 1 | 1.02% |
| Group Presence | 8 | 5 / 3 / 0 | 3.25% |
| Owner Contact | 6 | 5 / 1 / 0 | 0.72% |
| Group Freshness | 1 | 1 / 0 / 0 | 0% |
| Companion Plan | 2 | 1 / 1 / 0 | 23.66% |

同窗大肥鱼的 `deepseek-flash`：Foreground 156次，96.61%；Private Freshness 62次，71.31%；Owner Contact 3次，48.91%。这是不同端点、凭据、人物和流量的对照，**不能直接推出只改模型名即可获得相同结果**。

真实 wire 复核：小双白同阶段模型参数、无工具目录保持稳定；已记录 User 公共前缀的相邻请求中，Private Freshness公共前缀中位5554字符（7个有基线样本），Presence为4779字符（4个），Owner Contact为4579.5字符（2个）。这些是实际未变化的请求前缀，不是缓存命中保证。跨阶段或不同当前材料不应强行冻结。

现有 A+B、来源ID精简已经生效；本轮没有发现足以证明需要再删人物、约定、工具证据的资料。原有 `routingSha` 是 `prompt_cache_key` 的哈希，空值哈希不能证明端点相同。此次增加 `endpointSha`：只哈希实际HTTP请求的协议、主机、端口与路径，不记录URL、凭据、查询参数或正文；端点不同的前缀基线分开计算。

| 小双白现端点，deepseek-flash | 两次403，不构成有效模型质量比较 |

测试初始将SDK环境变量占位符当作凭据的请求也返回401；修正测试取密钥方式后才进行上述验证。拒绝请求不作为缓存/质量样本。真实Key仅在服务器内存使用，未打印或落入报告。

**判断：** 低命中现象已证实，端点/凭据差异已证实；唯一根因尚不能确定。当前配置无法进行有效的替代模型A/B，不应虚构端点切换收益，也不应因此改主聊天模型。

### 辅助模型配置的最小实现

- `BotConfigSchema.auxiliaryModel` 为可选字段，无默认替换。
- 仅允许 Private/Group Freshness、Presence、Owner Contact、Companion Plan读取。
- 从绑定 provider 的可信 lease 读取，拒绝事件/decision与租户、机器人身份冲突；不从普通消息取模型配置。
- SDK组装前按本次请求选择模型，最终 extra body合并不能覆盖这一选择；不改变共享provider或主聊天模型。
- 实际 wire诊断继续记录最终模型名。

当前所有机器人均未设置该字段。Python路由能力已加载，但未激活切换；Node/API常驻校验器未进行本轮换载，不能把磁盘新增Schema描述为已经完成在线配置界面验收。后续若取得允许替代模型的**该机器人自己的**配置/凭据，应先验证端点及判断质量，再按既有配置热更新合同完整接线；不需要改 Journal 或 System。
