# QQ 头像、B站取图与统一能力注册验收（2026-11-04）

本轮依据用户要求：核查头像接口、增加B站取图，并让真实工具能力结构性同步给模型。未执行 Git 操作，保留此前未提交的页面与提示词修改。

## 原状与修改

- 小双白线上 `qqProfile=true`，但原头像工具只接受主人当前附带/引用的 QQ 图片。旧自主工具装配没有头像入口。
- 新增 `bilibili_images.py`：从成功的搜索、热门、榜单、视频详情、UP资料、合集目录等真实公开读取结果收集封面/头像。排除个性化推荐、私信和通知来源。模型仅能选择本轮真实句柄，不能传 URL 或路径。
- `bilibili_tools.py` 在真实结果返回处登记候选；`executor.ts` 保留平台返回的视频封面及UP头像字段。不存在候选时，先用已授权读取工具获取素材；不是任意网页图片搜索或视频截帧工具。
- `hosted_bilibili_image` 的 list/prepare 下载、解码并返回缩略图给内层模型。prepare 不代表换头像。
- `hosted_qq_avatar` 接受已准备句柄或原有 QQ 附图，核实当前 QQ 身份，经原协议接口执行。保留操作账本、不可自动重发未知结果、配置失效与取消保护。主人前台仍需明确要求换头像；主动内层受 QQ资料管理开关及实时 Work 副作用许可约束。
- 原生协议末端增加 avatar 的授权识别，仍使用原公共管线记录真实副作用与回执。影子模式不能换头像，离线账号不会因此启动。

## 结构性能力同步

新增公共入口 `inner_tools.features()`，前台与自主内层从这里装配实际工具。外层每次快照调用同一装配入口，读取实际工具的 name、description、parameters、可用状态、副作用属性；额外返回 capabilityRevision，意图形成与决策阶段都读取当前版本。

B站子工具仍来自 Node Agent 按当前配置、账号状态及权限发布的真实 manifest。新注册操作缺少中文描述时保留参数合同并给出通用说明，不再静默漏掉。未授权操作依然不发布，后端继续作最终权限校验。

以后增加 FishBot 托管能力，应在公共工具入口注册工厂；不能只往提示词里添加一条能力。没有另外维护一份手工模型能力清单。外层枚举工具不会调用工具，不产生外部动作。

签名、空间、聊天目的地等既有任务授权保持原状；头像可作为内部工具任务执行，没有新建专属自主调度器或常驻 Agent。

## 媒体生命周期与资源

只接受真实结果中的 hdslb.com / biliimg.com 图片引用；已知 CDN 的 HTTP 引用升级为 HTTPS。禁止跳转、凭证 URL、异常端口。单次下载最多2MiB、4百万像素，限制到512像素PNG，单张PNG最多256KiB。共享运行时同时只进行一个此类下载。

复用每个机器人的现有SQLite存储：最多32个候选、8张PNG；1小时过期，读取和写入时懒清理。没有清理计时器或常驻下载进程；过期记录即使尚未清理也不能继续换头像。换头像经有限大小的base64传给协议，避免跨容器路径假设。原内存策略与Guard配置未修改。

Linux实际只读实验：绑定账号读取指定视频详情，HTTP 200，122ms；下载真实封面123597字节，规范PNG73087字节，下载处理771ms。隔离Python进程峰值RSS63468KiB，处理前PSS23667KiB、处理后47492KiB。此数包含隔离进程首次导入HTTP/图片依赖，不是共享AI的常驻增量，也不能当作整机容量验收。
