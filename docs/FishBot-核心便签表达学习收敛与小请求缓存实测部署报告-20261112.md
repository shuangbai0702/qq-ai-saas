### 核心便签：旧拒收原因与新处理

上轮只读生产记录显示发布后5次便签提议，4次 `unknown_event`。这只是接收结果；旧审计没有保留模型原始引用，不能证明4次都是同一种命名空间错误。

`memory_reflection.Reflection.update_core_note` 原来对 `missing_evidence`、`invalid_evidence`、`unknown_event`、`unknown_summary`、`evidence_capacity` 直接返回0。本轮改为：

| 情形 | 处理 |
|---|---|
| 完整引用匹配本批提供材料 | 正常更新，`source_verification=references_matched`；仅证明引用匹配，不证明认知内容为真 |
| 引用缺失、容器/类型错误、未知ID、引用超限 | 正常校验文本并更新；`unverified`，审计 `applied_source_unverified:<具体类别>` |
| 旧库记录 | 新增列默认 `unknown`；不改旧文本、更新时间，不倒推验证成功 |
| 明确引用未提供的其他Scope事件或摘要 | `cross_scope_evidence`，仍拒绝；不迁移归属 |
| 非法操作、敏感文本、超过300字符、快照变化 | 仍拒绝 |
| 数据库/事务失败 | 原事务回滚，不能假装更新成功 |

新列位于原 `memory_core_notes`，没有新记忆库。模型读取 `core_note()` 可见验证状态；归属来自本批程序可信材料及旧便签，不能从模型ID推断人物或权限；sources仍为空并遵守原始索引退休规则。

实现定位（`5b277ac`）：`memory_reflection.py:255`增量迁移、`:566`模型读取、`:597`接收器、`:1242`可信作者归属传入、`:16/:105`接收限额及生成提示；`social.py:44/:62/:172`本批收集/摘要接收/证据校验；`behavior.py:465`检查点回调已无独立学习调度。
