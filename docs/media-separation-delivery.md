# QQ表情、聊天表情包与普通图库

工作区：`D:\MYCODE\APP\fishbot\qq-ai-saas`。按 `media-separation-plan.md` 实施；继续使用AstrBot共享/独立运行与原有权限系统，没有安装任意第三方Python插件。

## 产品行为

“基本配置”现在有三个独立分区：

| 分区 | 来源 | 发送方式 |
|---|---|---|
| QQ内置表情 | 协议编号，无需下载 | 原有QQ_FACE受控转换；当前14、4、5、32，并非全部QQ表情或手机收藏同步 |
| 聊天表情包 | 原有手动反应图、内置基础表情、从授权群收集后人工审核的表情 | 模型按语境选择MEME；受原有冷却/每日图片额度限制。收来的表情仅在来源群使用 |
| 普通图库 | 用户单独上传的PNG | 独立galleryEnabled，默认关闭；只有用户明确请求看图才提供普通图库候选，IMAGE标记投递；不进入MEME候选 |

普通图库独立API和目录，最多10张，每张PNG最多256KiB，支持场景、停用、删除、刷新持久化。原有5张自定义反应图仍在聊天表情包中，不自动搬走。图库与表情发送可分别关闭，已保存客户配置未被批量改写。

## 自动收集

在“聊天表情包”开启“自动收集聊天表情包”，填写允许收集的群号，保存并应用。默认关闭，空群名单不收图，仍受总聊天开关和机器人群白名单限制。

实际路径：`behavior.py:execute` → `StickerCollector.observe` → 有界下载/首帧PNG → `sticker_inbox`待审核 → 用户填写场景/批准 → `SocialStore.context`候选 → 模型MEME → `behavior.py:send` → QQ Image消息段。

收图发生在@/触发判定之前，不为收图调用聊天模型；不收机器人自己的输出。只接收实际OneBot消息中 `image.data.sub_type=1` 的图片，不把普通照片全部收进表情包。无法提供此标记的协议端、商城mface等其他段类型暂不会收集，不能把二维码已登录等同于已验证收图兼容性。

收来的图片先待审核；用户补充适用场景后才批准，不自动调用视觉模型。审核、移除、预览通过已有运行Owner端点；停止时走短时维护，不增加常驻Web服务。普通用户不能传入文件路径、任意URL或SQL。

限制与数据：

- 每Bot最多10张待审核、20张已审核；每分钟最多一次下载，默认每天10次尝试，最多配置30次，0停止。每天北京时间08:00重置；失败或重复下载仍占尝试预算。
- 仅HTTPS、固定QQ媒体域名、无重定向；关闭环境代理，不接收用户指定本地文件或内网URL。
- 原文件最多1MiB、最多1048576像素，压缩成最多512×512和256KiB的PNG；GIF/WebP只保留首帧，暂不保留动画。
- 每Bot一个在途任务，进程最多两个同时下载，超时10秒；不启动Embedding/视觉模型。未实测内存，不报告MiB收益或新增成本。
- 内容按Bot/来源群去重；丢弃后保留最多200个摘要阻止立即重收，丢弃的图片内容被清除。待审核图片不进入回复候选，原群表情不能跨群使用。
- 更换配置、停止/删除实例使旧任务失效；任务取消或晚返回不能写回已释放/替换的状态。
- 候选只读取少量元数据；批准图片在实际发送时才读取对应BLOB，不把整个图片库长期放在内存。
