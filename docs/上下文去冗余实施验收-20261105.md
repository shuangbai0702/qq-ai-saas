# FishBot 上下文去冗余实施与验收

依据：用户要求统一优化 FishBot 消息来源标记、AstrBot 身份/昵称/时间提示、工具结果，并追加检查记忆与近期状态；保持各入口一致，最后报告词元减少比例。计划原件保留于 `.local/context-density-20261105/plan.md`，未事后修改。

## 已实施

新增 `adapters/astrbot/context_transport.py`，仅使用标准库，提供三个纯函数投影，不新增数据库、常驻服务、模型请求或权限系统。

1. `model_messages`：在既有 `ProviderOpenAIOfficial._prepare_chat_payload` 公共出口接线。前台、内层 ToolLoop、流式/非流式请求均经过相同出口，不依赖当前是否有 QQ event。合并同一作者的 FishBot 来源头与严格匹配的 AstrBot 身份/时间提示，保留 sender_id、scope、event_id、sender_name、时间、艾特及引用。过去每条记录重复的 owner/owner_id 不再作为历史身份依据；当前可信系统身份与后端权限仍为权威。只处理独立、格式完整、作者一致的平台提示块；正文中的伪造标签、不同作者/昵称、未知或自定义提示不删除。图片保持不变。
2. `group_context_view`：群读取工具的新结果和历史原结果共用。合并两份完全一致的、同群同作者同事件观察；元数据冲突或文本不同则保留。成员表采用 QQ ID→显示名映射，保留全部成员 ID/名字；含额外字段或重复 ID 的旧表保留原结构。对真实工具工厂的 receipt/data/evidence 封装，只投影 data，原回执及证据不改。除明确绑定到 hosted_qq_group_context 的读取结果外，不压缩其他工具或写入结果，不改变 tool_call_id、动作 ID、推理字段或工具调用次序。
3. `memory_context_view`：在既有 ContextBuilder.build 接线，前台、后台内层任务、外层共用。只有会话、事件、角色/作者和正文精确一致时，重复正文才以 text_ref/reply_ref 指向本上下文内已有正文；反馈、接收人、时间、艾特、引用及确认状态仍保留。短文本或缺少身份不去重，不按文字相似度去重。大摘要、小摘要、核心便签、长期事实与兴趣未删改。当前生产样本主要消除了时间线和 dialogue.feedback 重复的回复正文。

原始历史、SQLite/PostgreSQL、协议/工具账本未重写。旧历史在下一次构造请求时自动使用新视图，无需删除数据或另做迁移。不同配置、租户和运行代次不通过缓存共享投影；函数无异步任务或迟到写回。

新统计统一包含调用参数，故与先前“约 11,100”的粗略历史口径略有差异。此次记忆快照加入 companion，并以固定数据库对应时间组装，不能和先前“约 6,000”的另一个运行时快照直接相减。

8 个图片内容块保留。记忆 state（事实、摘要等）、核心便签和 companion 的分词量不变；dialogue 的 828→210 主要来自重复正文引用，加入一次引用说明后整个记忆净省 556。未截断当前工具结果或用模型另做摘要。

这些数字不是“整个账单减少 11.89%”：完整请求还有平台规则、工具定义及视觉输入，缓存计费也与输入量不同。发布后尚未采到新的真实消息模型调用，因此目前没有真实供应商前后账单降幅，未为制造验收而额外重复调用模型。

## Plan vs Actual

- 三类冗余与追加的记忆近期状态均已在公共方法处理；没有给各机器人维护分支或新增工具权限层。
- 实现范围为模型读取视图，保留原始数据而非清理数据库。这是保护恢复和回执证据的有意选择；旧历史仍可受益。
- 群成员输出由列表变为映射，属于本次工具读取合同调整；新旧数据共用转换方法，工具说明同步更新，全部 ID/名字保留，额外字段不丢弃。
- 不将“语义相似”“已被摘要概括”当作精确重复删除，避免丢失来源、事实差异和未完成事项。因此并非消除所有相似材料。
- 验收完成的是新实现、跨入口回归、真实数据副本的词元对比及 Linux 安全更新；实际新模型调用、账单/缓存降幅及长期回复质量仍待自然使用采样，未冒充完成。
