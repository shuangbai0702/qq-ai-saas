# 前端交互整理（2026-10-31）

执行前完成三轮复核：用户/管理员完整路径；状态、草稿与操作的调用关系；页面层级与请求所有权。问题是渐进新增功能堆叠，而非缺少组件库。

固定计划：
1. 平台管理拆分运营、内存监控、激活码。保留旧路由与功能，按当前页加载，不把所有内容堆在同页。
2. 机器人配置导航按基础、聊天、媒体、扩展分组；启动/停止是主操作，重启/删除收至更多操作；配置保存区区分草稿/保存/应用，提供明确放弃修改。
3. 列表/详情状态统一，处理停止/启动/过期回执；草稿切到QQ/日志仍提示保存位置，切分区保持草稿，离开机器人仍确认。
4. 公共资源请求绑定URL、页面和请求代次，URL切换时不得渲染旧资源，新请求失败可重试，不新增缓存框架。
5. 针对页面路由、草稿、危险操作、状态及迟到请求做浏览器/相关回归；桌面和手机视觉核验、Windows/Linux构建，仅Web热更新不重启在线QQ、AI、Agent；记录产物和两端同步。

沿用现有视觉、React和hash路由，不引入UI库、后端接口、数据库表或内存参数变化。不重构全部表单和组件，不改聊天行为。既有未跟踪生产验收材料不动。

## 实际实现

普通用户：
- 列表和详情共用状态语义：停止请求尚未完成显示停止中、旧在线回执不再计在线，过期/启动/失败明确区分；列表QQ搜索包含计划登录号。
- 配置导航分基础设置、聊天与关系、图片与表情、扩展能力，保留所有原分区及链接；人格与模型作为默认落点。主要操作是启动/停止，重启和删除在“更多操作”，重启二次确认。
- 保存区区分未保存、已保存等待应用、下次启动应用、已生效，未编辑时禁止无意义保存；增加确认后放弃草稿。跨配置分区保留草稿，QQ/日志页提示返回保存位置。未保存时，启动和QQ登录统一要求先保存或放弃；已有连接及登录状态观测保持正常。
- 运行与内存细节折叠，保留简要QQ/AI/Key信号。所有配置页统一提示：参数和开关需保存，图片上传/审核及记忆管理即时生效。聊天节奏和推荐预设移除“对齐参考/高播放量”措辞，明确多项草稿变更与请求成本。日志区分加载中与确实没有日志。创建、登录、模型读取、记忆、图库、主动目标、插件等现有能力保留。

管理员：
- /admin 为运营页，/admin/memory 为内存和进程页，/admin/invitations 保留原激活码路由。三个页面共用二级导航，顶栏只保留平台管理入口。
- 运营页不挂载内存组件和原始状态轮询；只有进入监控页才读取这些接口。保留原操作分区及进程高级详情。

公共请求：
- useLiveResource 按URL标记返回值与错误，切换URL当轮渲染即隔离旧数据；页面与请求代次继续控制回写，旧refresh不能在新页面取得所有权。未增加缓存、常驻服务或路由库。

Linux：限制1核/768MiB的隔离环境完成6项相关回归、类型检查及生产构建；最终QQ草稿逻辑后再次完成类型检查及生产构建。最终Web产物为 index-DESgYLKb.js / index-BBYjb6mo.css，与Windows构建一致。真实PG读取12个工作区、7个机器人、4个QQ在线；首轮更新的Agent/4个QQ/共享AI共6个PID与创建时间保持，6份QQ身份文件摘要保持，users/tenants/memberships/secrets/qq_bindings/bot_config_revisions六表保持。最终静态补充不重启API，连同API共7个进程保持。
