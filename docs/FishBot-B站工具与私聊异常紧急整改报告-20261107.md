# FishBot B站工具与私聊异常紧急整改报告（2026-11-07）

## 结论与范围

本报告独立记录本次紧急故障，不更新或替代其他 AI 正在负责的全系统整改报告。

**截至 22:25，大肥鱼、梁沅芷均已有修复后的真实私聊处理、模型成功结果和 QQ 发送确认。** 大肥鱼的历史 Hold 已解除，原有合法 35 轮检查点已由正常请求消费。未清空历史、未伪造许可、未重复执行旧工具，4 个 QQ 协议进程始终保持原 PID 和出生时间。

这两次故障不是一个原因：梁沅芷是窗口衔接误拒绝；大肥鱼是旧工具回合覆盖不完整，导致合法重构许可不可用，最终触及容量上限。此前仅扩大容量是临时缓解，不能宣称解决了检查点阻塞。

## 一、原始证据与因果链

### 1. 大肥鱼：容量错误背后的检查点阻塞

- 21:22、21:27 的失败为 `ContextCapacityExceeded / request_not_sent`。当时已提交 Journal 文本 381,338 字符，旧上限 384,000，只有 2,662 字符余量；对应失败没有进入模型，更不能推断为 B站工具执行失败。
- 21:35 的小补丁把本地传输文本上限改为 512,000，之后观察到多次真实对话成功。这证明缓解有效，但不证明能一直撑到合法检查点。
- 22:06 再次失败时，Journal 75 次提交、文本 504,744 字符、wire 962,236 字符，仅余 7,256 字符。`Journal.turns` 是请求提交计数，**不是完整业务轮数，不能拿 75 签许可**。
- 数据库有唯一旧 Hold：round 409，原因 `uncovered`；材料 v1、`complete=false`。唯一检查点 id=1 已有真实 35 轮批次身份，through=506，但状态为 `pending_coverage`，等待此旧事件。
- 原始已提交 Journal 中仍有该事件的完整调用链：用户消息 → `propose_background_task` → 对应真实 tool receipt → assistant 原文。它并非证据丢失。
- 旧材料格式不能表达完整工具回合，旧恢复调度还要求再积累 35 个新轮才重试旧 Hold。容量耗尽后，新轮无法成功，形成闭环阻塞。

**已证实根因：工具证据表达缺口 + Hold 恢复调度缺口，容量错误是结果。** 本次对应旧工具为后台任务提议工具，不是 B站工具。不能据此断言 B站能力整体正常或异常；本次没有重新执行任何 B站或旧后台任务。

### 2. 梁沅芷：完整窗口与已覆盖投影的衔接缺口

- 首次新失败约 21:53，诊断 `ContextReconstructionDenied / request_not_sent`，`valid=true`、权限和 epoch 未变化，文本 183,084 字符，容量充足。
- SDK 窗口前部仍有已经被摘要覆盖的旧回合；Journal 的基线已经合法省略这些回合。SDK 向前移动窗口后，投影后的历史尾部可以与 Journal 精确衔接，但原代码只对未投影的完整窗口执行尾部匹配，因此误拒绝。
- 使用现场 Journal、SDK 历史、coverage 以及实际失败消息离线重放：原生产代码稳定拒绝；补丁后追加 2 条消息，原 85 条 wire 前缀及图片字节完全不变，不使用许可，提交后重新加载完全一致。
- SDK provider 的图片重新物化、空 reasoning 字段以及摘要投影均按真实链路处理；该离线重放不是实际 HTTP 请求，不冒充现场 PASS。

**已证实根因：合法投影窗口的匹配分支遗漏。** 不是图片内容丢失、容量不足或护栏本身需要放宽。

## 二、最小修复与护栏

### 窗口衔接

模块：`adapters/astrbot/readonly_journal.py`。

1. 先尝试经过可信 coverage 投影的窗口，再保留原完整窗口回退。
2. 若投影窗口能够衔接，要求完整窗口中“最后一个已提交锚点 + 全部追加后缀”也逐条一致；不允许投影隐藏尚未提交的新消息。
3. 拒绝匹配后缀再次出现已知事件，防止短匹配误接重排、重复事件。
4. 成功分支仍使用原 `old.wire` 加新后缀；不重序列化、不替换旧角色、正文、System、图片或顺序。

### 工具 Hold 合法恢复

仅从生产冻结源码构造必要补丁，涉及：

| 模块 | 必要改动 |
| --- | --- |
| `context_protocol.py` | 校验完整、成对、调用 ID 绑定的工具请求与回执，并计算工具证据摘要。 |
| `summary_material.py` | 兼容 v0/v1；v2 保存有界工具证据；coverage 同时绑定用户、回复、工具；旧材料升级保留已确认投递的回复。 |
| `memory_reflection.py` | 对证据齐全的 `uncovered` Hold 单独补摘要；模型实际收到工具名称、参数和结果；恢复任务不增加轮数、不移动 watermark、不新建许可。 |
| `behavior.py` | 从本 bot、同 scope 的已提交 Journal 重新捕获旧证据，通过原 digest、存储和材料验证入口补全。 |

没有使用关键词判断重要性。现有摘要模型负责语义保留，程序只验证证据和结构。缺失、未知、无法证明完整的工具回合仍保留 Hold。

新增边界：单次工具参数最多 4,000 字符、结果最多 8,000 字符，整轮工具文本最多 64,000 字符；超出不强称完整。模型获得完整有界证据，不能仅给截断结果却签完整覆盖。摘要仍为默认 800 字符，大摘要仍为 1,500 字符。

本地回归发现“保护预算冲突被恢复流程连续重试”风险，已修正：仅 `uncovered` 可触发独立恢复；纯 protected 不进行付费重复摘要；恢复后仍有 Hold 时复用原 retry 表至少延后 600 秒，不增加新计时器或第二套状态机制。
