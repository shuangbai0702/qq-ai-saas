日期：2026-11-12。实施基线：`main@88af33ade47becc45daf0c0bc8363f8166943448`。代码提交：`d13bb520894fb1145f811769d740e3e1466d1d03`。

## 1. 交付结论与限制

已实现：35轮仍全部合法压缩；原有本批整理调用同时可产生交流连续性资料；按检查点持久化，写入下一份固定上下文基线；没有固定最近5轮、TTL、轮数失效、额外生成调用或独立历史池。下一合法检查点采用新Journal时替换产品并清理旧版。普通请求不改写已提交基底。

**工程生命周期验证通过，交流质量只得到部分证据，不能宣称已经解决所有压缩后断话问题。** 最终提示能让实测模型保留近期独特说法，但仍漏掉助手当时的具体回应，且会夹带远期目标。问到被舍弃的回应时，有无连续性资料都要求补充。该缺口没有用格式测试或Mock结果掩盖。

没有部署、推送、修改生产数据库或Journal，没有QQ/B站外发、重新登录或强制生产压缩。生产尚未获得本次功能；本轮没有重新采集4个QQ在线状态。

## 4. 完整生命周期

```text
已有合法完成业务轮累计35
  → 原有材料回采/缺失说明/版本校验
  → 原本本批整理调用：summary + 可选 conversation_continuity
  → 原有事务：长期产品、水位、checkpoint、新连续性产品
  → 已有semantic_runtime构造新的合法基底
  → Journal采用事务：检查产品归属、保存新快照、批次退休、清除旧产品
  → 原有可恢复清理流程清理本批原文/媒体，保护其他引用和新批次
  → 普通新交流继续追加；固定基底不变
  → 下一合法35轮重复上述流程，不把上版连续性当新交流
```

数据格式为 `conversation_continuity:[{source_scope,text}]`；单一可信会话时兼容单段字符串，但多来源字符串因无法归属而拒收。source_scope只能来自本批可信作者证据，不能由模型自己创造会话。所有text合计500字符；无必要线索可省略、null或空数组。

资料在固定基底中有checkpoint编号、来源会话和非授权说明。实现沿用现有基础区的Provider `role=user`技术承载形式，**没有伪造QQ来源头或真实User事件**。它不是System权限，也不生成消息事件/Work/业务轮。不能把“不是原始User消息”误写成“HTTP中绝不使用user角色”。

Root状态保留foundation元数据用于恢复，实际排列时从热资料包剔除该foundation，单独注入一次。普通请求由 `freeze` 保持上一版基底；合法重建才选择精确的新checkpoint产品。

`summary_material.snapshots`只捕获可信QQ来源；基础区不满足该合同。测试把实际含连续性的Journal wire送入捕获链，确认产品正文不会进入下一批model_view。连续性不写入 `memory_summaries`；旧小摘要和big合并不会直接读到它，避免程序造成循环总结。模型根据新真实交流再次认识同一事实，不等于程序重复归档。

### 故障及替换规则

| 条件 | 结果与恢复 |
|---|---|
| 正常产品、摘要事务成功 | 保存checkpoint产品，等待原有合法Journal交接；同批未完成交接不清旧版 |
| 产品省略/null/空 | 明确记省略或模型未选择；本checkpoint产品为空，新基底不回退旧话题 |
| 产品格式错误、越界来源、重复来源、超过500字符或含凭据模式 | 记录具体拒收理由，只舍弃产品；不新增修正调用，不无限等待 |
| 摘要失败/截断、版本变动、配置或epoch过时 | 沿用原有拒绝提交；旧基底和未退休材料保持，不把迟到产品发布出去 |
| 事务写入中失败 | checkpoint、产品、水位和摘要按原事务一起回滚 |
| 新产品与Journal许可checkpoint不一致 | 明确报 `semantic_continuity_checkpoint_mismatch`，Journal切换及旧产品清理回滚 |
| 第三小摘要等待既有big合并 | 新产品随本checkpoint暂存；旧基底继续有效；big输出的同名字段不覆盖新产品 |
| 摘要已提交、进程重启或Journal采用失败 | 由原有committed批次恢复流程重做合法交接；不重新生成连续性，不创建任务 |
| 旧原文缺失 | 按既有尽力回采与缺失说明整理；可选产品可为空，不能因此永久堵塞合法压缩 |
| 采用后原文/媒体清理暂时失败 | 沿用原有可恢复清理与pending报告，不因产品存在谎报全部clean，不绕过引用保护 |

旧checkpoint产品仅在同Scope新Journal采用事务中清除。新表列没有单独版本库；旧产品不会按时间、后续消息数量或重启自动删除。显式遗忘遵守现有epoch隐私失效，不新增自动失效来源。

## 6. 真实模型对照：效果及失败均保留

使用用户提供的测试端点，凭据仅临时进程环境注入并在结束后清除，未写入源码、Git、脚本文件、测试产物或报告。材料全部为合成35轮，不含生产私人对话或真实记忆。

本轮 `/chat/completions` 共13次尝试：12次成功、1次HTTP503。先用请求别名 `5.6luna` 返回503；只读 `/models` 另1次返回200，列出 `gpt-5.6-luna`，之后12个成功响应均返回此模型ID。因此HTTP总数14，成功生成12，不能将503算成质量样本。没有自动重试。

成功生成包括4次本批摘要及8次压后接话。首轮两组对照后发现漏记近期轻松互动，再做两轮单组提示修正验证；后续增加的调用用于具体缺陷复验，未扩成大样本统计。供应商usage合计prompt 41,229 Token、completion 5,216 Token，均为成功请求；不是本地代理估算。

发现的实际提示冲突：已有长期整理总则要求“普通闲聊直接舍弃”，原连续性只弱化为“可以进入”；模型仍按长期价值筛，偏向最后一项待办。最终明确此长期取舍规则**不适用于连续性字段**，要求近期具体问答、双方语气及必要短原话，不仅保存待办或复述长期目标。独立Sol复核确认第31轮双方原文确实在请求内，未发现编码或材料传输遗漏。

最终样本仍夹带“明年读三本书”的早期目标；没有凭一次改善宣布去重或自然度达标。500字符摘要有损，无法保证未来任意原句提问均可回答。没有为了补回个案，把程序改成固定最近5轮、关键词命中或额外调用。

原始合成请求、响应、接收审计和usage在忽略目录的 `requests.json`、各`*-comparison.json`。这些文件不作为生产数据，也不会被上下文管线读取。

## 7. 安全、兼容及账本边界

- 每Bot仍使用已有独立数据库。非共享Scope严格限制产品来源等于当前Scope；`bot_shared`只接收本批真实来源并保留标签。沿用既有同Bot跨会话认知共享，**不意味着群私完全隔绝**，也不产生对外披露授权。
- 内容不是工具参数、授权、任务创建或发送回执；未改权限/预算/unknown与外部副作用账本。没有把约定摘要重建成真实业务任务。
- 基线中的连续性不参与业务轮记录，不消耗或生成checkpoint许可；不把工具循环/自主思考变成新真人业务轮。
- 迁移只对Bot SQLite既有checkpoint表加可空列；旧记录为NULL。不修改PG结构、不回填旧产品、不重写旧Journal。重启迁移测试保留原35轮行逐字段不变。
- 老Journal不强制重建，等待已有合法检查点；A/B旧表示及原有来源/媒体序列化不变，相关Journal及上下文回归通过。未对所有生产年代的损坏库做迁移演练。
- 回退应回退本次源码提交并保留数据库/Journal；新增可空列无需删除。已经采用的新基底不能用恢复备份或手改历史的方式回退，应先隔离验证旧代码读取能力，再按原检查点合同接续。

## 8. 未完成验收与后续观察

1. **自然接话效果未完全达标**：实测仍丢助手回应，不能保证所有语气与指代都被保留；尚无跨多种人格、群聊、多用户的长期质量证据。
2. 两项旧回归失败保留，需另行确认其断言与当前原文缺失/合法交接合同的关系，不能仅凭本次基线相同便忽略。
