# 白名单群自主接话：源码核对与整合方案

日期：2026-11-01。状态：方案与核心可抽取性核对完成，**尚未接入 FishBot、修改生产配置或部署**。本文补充原 `plugin-comparison-plan-20261101.md` 的群聊参与阶段，原计划及原执行记录保留。

## 目标与边界

- 只在机器人明确配置的白名单群启用无人 @ 时的自主参与；白名单为空时不启用，不能解释成所有群。
- 能加入正在发生的公开话题，也能跟住已经开始的多人对话。人格兴趣、情绪、关系提供判断依据，不能变成每层都必须通过的硬门槛。
- 设置要能解释实际行为：为什么判断、为什么开口、为什么沉默、是否触发预算或白名单限制。
- 继续使用当前回复、表情包、记忆、认主与可靠投递链路。保留共享 AstrBot 和机器人之间的隔离，不增加新的常驻 AI 进程。

## 与现有功能的关系

当前 `behavior.py:eligible()` 的冷启动入口主要是 3% 随机概率，兴趣词重合只能放大概率；`Participation.blocked_reason()` 也仍含话题词重合筛选。当前 `naturalConversation` 和 `followupSeconds` 已能向模型提供连续对话机会。

整合后，话题注意力成为参与判断的一部分，替换粗糙词重合筛选；不在已有注意力、疲劳、概率之后再叠一个否决器。正在进行的对话保留实际参与者、最近机器人发言、话题及引用关系，用于正式回复模型选择回应或沉默。

当前 `reserve_interjection()` 在调用模型前记录所有尝试，包括模型沉默，并按机器人合计所有群。新方案保留机器人级总预算，但将“判断调用”“新插话预留”“已确认发言”分开，避免沉默耗尽发言额度。

## 入口与执行顺序

1. 先应用账号、机器人和允许服务群的现有权限；忽略自身回声与重复事件。
2. 私聊、正常指令、明确 @ 机器人和平台结构上引用机器人的消息走现有直接回复路径，不额外调用插话判断模型。
3. 无人明确叫机器人的群消息先检查自主参与开关和**该机器人的群白名单**。不在名单内，不触发本功能的模型判断、随机搭话或无 @ 跟聊。空列表不会自动填入历史群号。
4. 同一权限检查须覆盖旧随机入口及自动选群入口，避免旁路；开启本模式时，旧的“全消息触发”也不能绕过白名单。显式配置的定时任务与私聊主动联系在界面上单独说明，不借用本功能扩大目标范围。
5. 白名单内，已有对话的接续消息交给现有正式回复路径按完整上下文判断；换了词、换了群成员不能直接判成无关，也不重复执行首次插话冷却。
6. 首次参与或结束后重新参与：将短时间内消息合并成有上限的一批；在判断预算允许时，调用一次结构化判断。
7. 判断输入包括真实 QQ 指向、近期发言、机器人实际说过的话、人格、可信兴趣与当前情绪。用户文字不能改写发送者、主人身份或白名单。
8. 结果只接受有界字段：是否参与、对象是机器人/别人/开放话题、参与方式、是否续话、兴趣程度及简短原因类别。正式回复收到“为什么参与、对谁说、以什么姿态说”的提示，无须重新猜入口原因。
9. 首次插话先预留发送名额；回复经当前平台链路生成、选图、发送。收到成功回执后幂等确认名额；明确未发出的失败释放预留，发送结果不明时不自动重发。
10. 每个异步边界及发送前重新核对机器人配置代次、白名单、会话与消息锚点。删除群、关功能或换账号后，旧结果不能继续发言。

“插话空位”代表当前对话是否适合参与，不等于一定要全群静默。兴趣、情绪和疲劳一般作为模型输入；明确停止要求、租户边界、白名单及成本预算才是执行限制。

## 设置与建议初值

以下为待验证初值，**不代表已经在服务器生效**。配置归属为机器人，白名单群可覆盖参与风格与节奏；机器人总预算不能被多个群分别放大。

| 设置 | 建议初值 | 含义 |
| --- | --- | --- |
| 自主接话开关 | 预设可开启，空白名单实际不运行 | 页面明确显示“尚未选择任何群” |
| 允许的群 | 空；由用户选择 | 从当前机器人的真实群列表选择，支持逐群关闭 |
| 参与风格 | 自然 | 保守/自然/活跃，调整参与倾向；不使用随机回复概率 |
| 开放话题参与 | 开 | 话题未点名机器人，但它有实际想表达的内容时可以参与 |
| 别人之间的定向对话旁观补充 | 关 | 可单独打开；允许相关补充仍不能冒充别人回答 |
| 多人持续跟聊 | 开 | 使用对话状态与语义；不要求后续消息必须来自同一个人 |
| 跟聊有效窗口 | 120 秒 | 以真实发言和参与为依据，刷新条件需验证；不是任何消息都强制回复 |
| 短消息合并窗口 | 800 毫秒 | 延续当前合并节奏；采用确定的最长等待，避免群一直发言就永远不判断 |
| 合并最长等待 | 1500 毫秒 | 从首条候选消息计算，不被后续消息无限延长 |
| 单批消息上限 | 12 条 | 超过上限保留最近消息与必要回复锚点，避免上下文无界增长 |
| 判断上下文上限 | 12 条、3000 字符 | 身份、人格摘要另设有界字段；不加载全量聊天记忆 |
| 首次参与判断最短间隔 | 每群 10 秒 | 批次内至多判断一次；明确 @ 和持续跟聊不受此项影响 |
| 判断预算 | 每机器人最多 6 次/分钟 | 所有群合计；活跃群轮换机会。是成本上限，不是实际一定调用量 |
| 新插话间隔 | 30 秒 | 防止重复闯入；在进行中的自然回应不反复触发此冷却 |
| 每小时新插话上限 | 每机器人合计 20 次 | 仅确认的新插话消耗；沉默、重复回执不重复计数。正常被叫回应及已有对话接续另计 |
| 判断模型 | 复用本机器人模型，可选专用远程模型 | 显示模型及调用统计，复用本机器人凭据，不设共享租户兜底模型 |
| 判断超时 | 3 秒 | 新插话判断超时保持沉默，直接回复仍可正常处理；连续失败退避 |
| 安静时段 | 沿用现有配置 | 主要限制新主动参与；已被明确叫到和正在被回应的对话分别处理 |
| 参考兴趣、情绪、关系 | 开 | 作为参与意愿与口吻信息；不增加独立模型调用，不赋予权限 |

页面建议放在“机器人 → 社交 → 自主接话”，默认展示开关、白名单、参与风格、跟聊及发言预算。时间、批大小、上下文、模型及判断预算放高级设置。逐群覆盖项显示“继承机器人默认/本群覆盖”，避免多个开关互相遮蔽。

状态详情显示最近一次判断时间、群、决策类别、静默原因、判断与实际发言计数及耗时；保留有界记录，避免每条群消息长期落库。展示的是枚举原因与运行事实，不保存或展示模型内部推理。

## 成本与可靠性

- 一批首次参与候选最多增加一次远程短判断；明确 @ 与已在进行的对话优先走已有路径，避免所有消息双重调用。
- 判断并发纳入现有机器人并发控制，给直接回复保留处理能力；候选批次与缓存有上限、过期清理，不能因为配置了很多群而积压任务。
- 默认不进行图像理解或新的向量检索来决定插话，模型根据已有文本及已生成的描述判断。图片发送继续由正式回复模型选择。
- 判断模型不可用时，对无人邀请的新插话保持沉默并退避；不借其他租户 Key 重试，不重新开启随机入口。
- 800–1500 毫秒合并与 3 秒判断超时只是设计预算，不能据此宣称满足额外 P95 ≤5 秒。需要真实模型、相近负载下测直接回复和自主参与，并比较 CPU、RAM、PSI、成功回执及费用调用量。
- 保留现有 48MiB/16MiB `memory.high`、40 秒 PAGEOUT、Guard 和离线清退策略；本方案没有新增本地模型或 AI 常驻进程。

## 本轮已核验与后续验收

已在隔离目录用 Python 标准库直接导入上游 `utils/participation.py`，6 项检查通过：开放话题结构化结果、平台直接指向覆盖、明确指向别人时不允许伪造直接回应、非法枚举拒绝、诊断话题长度限制、带机器人命名空间的节流隔离。这只能证明该模块可独立运行，不能证明 FishBot 集成、对话质量或生产性能。

实施后必须覆盖：

1. 白名单为空、名单外、名单内，以及旧随机/全消息/自动选群入口的旁路检查；名单外仍能正常 @ 回复。
2. 换词续话、换人续话、确实换了话题、明确回复别人、活跃群持续有消息时的合并与最长等待。
3. 机器人兴趣相关但没有同词、低兴趣但真正被问到、收到停止要求，验证软信息与硬边界没有混淆。
4. 模型沉默不耗实际发言额度；并发抢最后一个名额、重复回执、明确发送失败与发送结果不明。
5. 判断中关闭功能、移除白名单群、重新加群、配置更新、账号重连及共享运行时同群多机器人隔离。
6. 现有表情包由模型选图、记忆、主人权限及回复回执回归；不以强制发图伪造效果。
7. Linux 真实群消息与相近负载对比，确认判断预算、额外延迟、QQ 在线、CPU、RAM、PSI及无重复发送，再决定默认启用范围。

## Plan vs Actual

原计划的群聊参与阶段要求更完整的上下文判断和有界并发。既有实现已提供自然跟聊与上下文，但首次参与概率、词重合筛选及把沉默算作搭话额度仍在；不能写成已经完成插件核心接入。

本轮按用户新增的“仅白名单群、详细设置、同时考虑三种实现”收敛上述方案，完成固定版本源码核对与独立模块检查。原计划的上游完整插件 A/B 仍未执行；本文选择抽取核心、保留平台回复链路的路线，理由是共享多租户、既有投递与内存边界。应用实现、网页设置、Linux 部署和完整集成验收仍未执行，没有用独立模块检查代替这些交付。
