## 数据与运行边界

- `apps/control-api/src/behavior-data.ts` 提供受 Bot 归属校验保护的列表和有限数据操作。拒绝任意 SQL、数据库路径或其他机器人 ID 代理。
- **运行中**复用 Worker 现有回环健康服务。dedicated 与 shared 都有 Bearer token、成员 generation/revision 检查，shared 另校验组 generation。浏览器拿不到这些运行凭据。
- 数据由当前 Worker 的 Store/SQLite 连接处理；没有每次在线查询都启动 Python，也没有每 Bot 新增 Web 服务。
- **停止状态**才使用短命的 `data_admin.py` 维护入口；SQLite 只打开已有文件，不创建幽灵数据库。维护并发最多2，查询最多100条/类，命令超时7秒；查询保持同一读取快照。共享组仍运行其他成员时，已停止成员正确走维护路径。
- 事实纠正、关系重置和图片编辑有各自数据版本检查；学习停用有管理 epoch，清理使在途批次失效。被停用的表达不会被迟到学习重新激活。
- 清理群学习材料会删除样本和表达，保留表达阻止记录；确认框说明已学表达会被阻止重新学习，不把它称为彻底擦除全部痕迹。
- 新控制表由各 Bot SQLite 的幂等初始化创建：`memory_blocks`、`social_pattern_blocks`、`social_control`。没有改动平台用户/密钥/QQ 绑定 Migration，事实与群体表达仍按每 Bot 数据根分离。
- 网页请求归属于组件生命周期和操作序列；页面退出后不提交旧结果，旧查询不能覆盖后续修改。请求取消不代表已提交的数据修改被撤销。

运行数据和配置的职责沿用现有实现。没有直接安装新研究插件的全局数据库或任意 Python 插件代码；采用其机制的受控适配已经存在，本轮将其纳管并补齐明确控制点。源码依据见 [社交学习与配图调查](social-learning-and-meme-timing.md)。
