## 0. 结论摘要

**一句话**：FishBot 的上下文系统已具备业界少见的"append-only wire + system 合同 + 部署时一次性 cutover 许可"护栏骨架（R4），护栏本身经 8 智能体交叉审计未发现实质性绕过（15 条路径 fail-closed、43/43 wire 校验通过），但**增量通道实质性退化（C类语义重复55-90%、readonlyChanges 实质全量重发）**、**外层自治空闲成本失控（24h 1.2亿 input tokens、>60%周期零产出）**、**R4 部署资产未 commit + 三轨并存 + 阈值静默变更**、**自主经历注入私聊与遗忘自锁**是当前四大主线问题；缓存偶发未命中归因于中转多上游轮换与图片 base64 重传，非本地重建。

十大关键发现（全部有源码/生产双证据）：
1. 【P0·在途缺陷】R4 reconstruction_authority 未接线 + R4 删除了 6h/35轮外层边界：按当前分支上线外层规划即瘫痪（§5）。
2. 【P0·成本】外层空闲空转：夜间92请求/h，24h 1.2亿 tokens，model_request_unconfirmed 876周期/5天零产出空转；dailyTokenBudget=0 无日预算（§6.5、§2.4）。
3. 【P0·冗余】前台增量通道被三重机制击败：readonlyChanges 27轮209k字符、C类语义重复75-90%（conversation_timeline 80k滑窗逐位重发等）；journal 距 added_text_limit 仅~6k字符，35轮摘要节奏即将被卡死（§5.2）。
4. 【P1·污染】autonomous_experience（4.8-6.5k字符，峰值15k）经 bot_pipeline.py:103 进入 owner 私聊资料包；74条 autonomous_result 事实存而不忆（不进人聊但占自主循环预算）；agent-memory.ts 实为堆参数工具（E2 纠偏）（§7）。
5. 【P1·重复】外层执行经历4路同源重复进入同一请求（§6.3）。
6. 【P1·架构】"35轮压缩"从不缩小基线（155-165k字符全量重建）；summary 水位是唯一现实重置源，其余边界生产零触发（§6.4、§5.1）。
7. 【P1·部署】R4三轨并存+混合版本运行+journal只覆盖2/4活跃bot+多bot配置代次漂移（§2、§5.3、§2.4）。
8. 【P1·稳定】agent心跳文件ENOENT持续刷错（§9）。
9. 【P2·布局】双system开头；行为规则(policy~3-5KB)在user角色事件包而非system（与context-pipeline合同文档不符）（§3、A报告）。
10. 【P2·重复计算】同周期orientation+planning全量重算snapshot/sharedContext/catalog两遍（§6.1）。

重要否定结论（同样有价值）：
- **"关闭长期记忆绕过 Journal"不成立**——memory 只门控观察/召回/语义/执行记忆与 project_history，prepare_chat_payload 无条件走 journal；关记忆=触发许可门重建（合法路径）。（C2 确证）
- 工具结果始终 role='tool'、执行记录不进 System、身份提升面查无——A 的错位七项检查基本干净。
- 前缀冻结双运行时强制真实有效：43/43 verified + 43/43 stable，时间戳只在新 suffix，零前缀抖动。（C2）

### 4.2 增量序列（连续请求逐轮）
- **前台**：每轮 +3 消息 / +10-12k 字符（爆发期 +23k），前缀保留率 **99.97%**；wire 146k→297k 后 summary_changed 压缩至 43k，**23 分钟又爬回 315,613c（103,379 tok）**——压缩只是续命，增量速度才是病根。
- **失败后假增量**：失败重试出现 fd=0/82 全量重发 242k，journalReason 仍标 'append'（behavior.py:1236 `prepared.reason or 'append'` 掩盖真实重建）——诊断不可信问题。
- **外层跨周期断裂**：每 cycle 首请求与上一 cycle 仅共享 **11.9k system 前缀**，159-163k 基座整体换代；cycle 内追加健康（缓存 0.94-0.99）。跨周期缓存结构性失效（§8.4 已证 miss 属中转多上游轮换+无 prompt_cache_key 亲和；system 内字符级根因见 §12-2）。

- 影响评估=低但有读取方：healthcheck 交叉验证 pid/processStart+20s 新鲜度；竞争必有胜者刷新文件（实测 Fails=0 healthy）；RestartPolicy=unless-stopped，unhealthy 也不触发重启；真正风险=长 busy tick（>20s 无心跳写入）。无自愈连锁。修复=tmp 文件名加唯一后缀。

### 9.2 生产三层代码代次混合【实测】

### 9.3 看门狗与恢复【源码确证】
- guard（host）只在 controller 'armed' 心跳>15s 失效、API /v1/health 两连败、容器重启/OOM 计数变化、PSI full-stall 时 rollback=**放松 memory.high（非重启）**；controller 管 pageout 回收（e0d8043 的 reclamation=内存回收，不清理磁盘）。
