# 群聊搭话与平台表情包策略（2026-10-31）

本轮要求：群聊可回平台图片表情，加强选图与搭话相关性，每小时最多自动搭话20次，并统一默认值。保留租户隔离、QQ Session、聊天数据和既有内存策略。

## 最终行为

- `hourlyInterjectionLimit=20`：每个机器人所有群合计，滚动3600秒；包含随机插话、自动跟进及群内定时主动联系。被@和指令回复不占此额度，私聊不计入群聊额度。按模型尝试预留，模型沉默或失败仍消耗，实际自动回复不超过尝试数；一次回复可能按既有设置分条发送。
- 新增单机器人 SQLite `group_interjections` 表，事务内清理过期记录、计数和预留；更换配置或重启后保留。其他机器人的额度独立。
- 群内随机插话与定时主动联系的每日额度分离。后者保留原有每日限制、明确授权目标、拒绝状态及未回应保护。保留随机插话1.4%、跟进窗口120秒/80%、安静时段、群范围和默认5分钟4次的疲劳保护，不按小时强行凑数。
- 平台表情包默认开启并选用蓝色大肥鱼包，普通回复70%概率开放候选；不代表70%实际发图。明确索要图片表情时跳过该概率，仍受20秒同会话冷却和每日50次上限约束。群聊与私聊均可选图，禁用QQ内置表情不会关闭图片表情包。
- 选图以词组匹配代替单字交集，图片标题匹配权重4、描述匹配权重1，保留情绪与类别多样性判断；模型进一步判断话题、情绪及表达意图，不强行配图。话题注意力默认开启，提示规则加强相关性并允许被点名时正常回应。没有增加本地模型或Embedding请求。
- 配置Schema、新建机器人、大肥鱼预设、Web默认值和说明一致。保留已有显式自定义配置；现有配置缺少小时额度字段时运行时默认20。不批量覆盖人格、Key、主人或其他用户选项。
- 增加候选开放、未选图、选图后受限、图片读取失败和小时限流的累计计数，避免下次只能凭最终发图数猜测。

## 验证与部署

Windows：生产构建、默认值、21项行为测试、26项社交测试、配置语义测试、社交API与发送生命周期测试通过；原生共享AstrBot/OneBot集成验证群聊 `send_group_msg` 含图片消息段、移除内部标记、禁用内置Face时仍可发图、第二次受冷却限制；前端完整导航和草稿流程通过。

Linux：11项相关Node测试入口通过（包含原生SDK、共享/独立运行时、租户隔离、群聊图片、生命周期与API）；收紧为机器人所有群合计后重新验证行为和配置语义；最终普通图库独立分支修正后，26项社交测试及社交API/生命周期入口重新通过。最终生产构建通过。原生集成使用受控模型和Mock协议，不冒充真实QQ收发验收。

生产仅独立更新Web/API和必要Python逻辑。共享AI在连续空闲窗口后通过现有apply命令重载两次，最终一次19.7秒完成恢复核验；Agent和4个NapCat进程创建标识均未变化。最终4个QQ在线、4个共享成员、无成员加载错误。6份身份文件哈希不变；users、tenants、memberships、secrets、qq_bindings、bot_config_revisions六张表记录一致。首次快照文本对比因末尾换行误报，逐行JSON检查和修正后的比较均确认无数据变化。未改48/16MiB阈值、40秒PAGEOUT、zswap25%、Guard或离线清退。

回退材料在服务器 `/opt/fishbot-group-social-policy-20261031/backup`，包括PG备份、SQLite备份、原源码/产物。新增SQLite表为增量结构，旧版本可忽略；恢复Python后通过既有apply重载即可，不删除用户数据。原始采样、数据库及身份文件不入Git。

## Plan vs Actual

已覆盖群聊图片、相关性、小时额度、默认值、Linux构建/运行回归与数据保护。初始实现按每群计数，随后收紧为每机器人所有群合计，防止多群放大总量；同步修改文案和滚动窗口/跨群/重启/跨机器人测试。额度采用保守的模型尝试数而非成功消息数，Web明确说明。最终审查发现候选排序替换误及普通图库独立分支，已恢复该分支原行为并补测试后部署，未保留该偏移。没有新增常驻服务或重构模型调用架构。

本轮没有主动向真实QQ用户/群发送测试消息，尚无新策略下真实QQ群发图回执，也未重新测P95；在线/就绪状态和受控协议集成结果分别记录，不能替代真实群收发证据。
