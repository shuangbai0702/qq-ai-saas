# FishBot 整批语义压缩与持久化检查

执行依据：[原实施依据及后续授权](FishBot-整批语义压缩实施依据-20261111.md)。本文状态以最后的生产验收记录为准；本地测试不等于生产旧历史已清退。

## 实际实现

- 一次完整批次请求提供全部文字、来源关系、图片、真实工具状态及已有记忆；保留35个合法完整业务轮与管理员明确例外，无600条机械截断、无额外摘要层或压缩调用。
- 模型做有损语义选择。保存摘要、现有各类记忆后，整批许可替代逐事件Coverage/逐图批准；Journal成功替换后清理热材料、来源列表、引用副本、归档及可证明属于本批的原图。新批次引用保护和失败重试不变。
- 去除摘要输出和已选记忆产物的静默截断；真实容量不足明确失败，输入不被退休。已有Hold材料整体加入下一次合法整理，旧Hold分类不再阻止退休。
- 同一模型请求可对现有 facts/metadata 新增、修订、合并、覆盖、弱化、遗忘；不因旧origin优先级拒绝模型决定。本人显式隐私遗忘、身份权限及跨租户边界仍保护。完整快照版本防止迟到覆盖。
- 现有relations增加trust、impression、semantic_updated；亲近、信任及印象是模型的整体目标值。入站只记录真实互动和时间，不再逐消息机械加减分。共享整理可阅读参与人物合法历史关系；写入范围与当前bot隔离。
- 事实与关系整理不依赖naturalConversation开关，但继续遵守相应记忆/自我发展配置；这些可写开关在整理输入中明确给模型。
- 风格学习并入同次整理输入与事务；样本仍按原群隔离、需两位真人证据，不增加模型请求。取消每类结果固定取前4项。

## 持久化入口是否集中在35轮

并非所有持久化都在35轮，也不应把事务安全与真实执行记录延迟35轮。

| 类型 | 实际更新时机 | 本轮判断 |
|---|---|---|
| 摘要、核心笔记、模型事实/喜好、关系整体认知、批次表达学习 | 现有35轮整理事务；三小合一大保留 | 本轮修正认知权限、截断与清理顺序 |
| 本人明确记住/更正/忘记、管理员操作 | 实时显式操作 | 应保留即时生效；并发版本与隐私保护不能移走 |
| Journal、Work、发送确认、授权、未知外部效果 | 每次实际事件/执行事务 | 属于可靠性基础设施，不是等待摘要的认知记忆 |
| 真实互动时间、群成员、调度取消、约定执行状态 | 事件或执行时 | 应即时提供，不能用35轮旧快照覆盖 |
| 情绪、兴趣热度、主动话题、机器人显式表达 | 仍存在实时规则与现有整理更新 | 未借本次重构；不能声称都已改为模型35轮认知 |
| 工具经验、主动任务经历 | 实际工具/任务结算后，整理时进入基础视图 | 真实回执不等待35轮，模型认知不替代回执 |

已证实的问题是旧固定优先级限制语义事实修订、关系机械计分、样本早于学习清理、旧归档持有原图、模型产物被程序二次截断。本轮针对这些问题修复。其他入口仅按相关职责检查，未宣称完成全仓审计或统一所有人格机制。

## 验证与Plan vs Actual

本地已执行真实AstrBot SDK到HTTP回归：完整35轮原文和有效PNG进入整理请求；成功后下一次HTTP保留System、摘要和新消息，排除旧事件ID/正文/图片；上游length截断保留全部材料。

其他实际回归覆盖34/35、601条pending、失败/容量/配置失效、并发图引用、真实文件删除、SDK迟到保存、跨会话与跨租户、归档触发器恢复及回滚。事实关系覆盖旧显式事实覆盖、合并/弱化/遗忘、ABA并发保护、隐私屏障、非自然聊天模式的同次整理与退休。

计划增量来自用户后续明确要求的事实和关系认知权限，不是自行扩展。另回收此前已存在的合并转发修复，不能算作本轮记忆修改的新产出。没有新增模型调用或记忆系统；关系表字段及联系人事件归属是现有机制的基础设施适配。

生产验收、具体测试计数、版本及剩余问题将在实际部署后追加，当前不作成功断言。

## 首次生产部署及读取断层（处理中）

生产已发布 `cbc978abe749c0c5ce1daa23af14483529cff87d` 对应15个Python运行文件，源码与运行目录共30个SHA核对一致；17份数据库备份通过quick_check。仅重载两个AI组，Agent及四个QQ协议进程的PID/创建时间保持不变。域名健康接口返回正常；生产仍在华为云，移动云未接管。

26号管理员整理请求确实已触发，返回 `semantic_batch_material_missing`，在调用模型前失败；没有摘要成功、检查点提交或原材料退休。故不能宣称旧图片、来源头已清空。

根因包括两个不同层次，不能混为“原文丢失”：

1. 回采实现只读活跃Journal，会话重建后，尚未整理材料可能位于旧检查点或管理员会话归档；这些归档未接入整理读取。通用修复在既有同一回采入口读取合法归档，不按26号或70条ID特判，不增加模型调用或压缩周期。
2. 输入回采及失败内部控制清理产生写事务；模型返回后另开产物事务可能嵌套失败。修复在HTTP调用前保存输入清单修复并结束事务；产物仍经独立事务及并发版本校验提交。此时只修复取材，不退休真实聊天。

另两条被误留在聊天pending的记录经真实账本证实是未提交模型、零发送的失败内部主动触发，不是QQ聊天。仅精确匹配这类控制记录才清理；保留安全流水，真实QQ、未知投递、部分发送或活动Work仍保护。已补最终Provider HTTP验证：35轮真实内容及图片完整、控制残留不混入、失败不退休真实材料。

Plan vs Actual：首次部署完成，但生产压缩验收失败；因此原计划的“成功后整批清理”尚未收口。新增归档读取与事务衔接属于修复同一整理入口的根因，不是新增记忆系统。归档恢复、原始内容真实缺失范围及生产重试结果须以后续实际证据更新，不能用旧哈希或Coverage缺失替代“原文缺失”的判断。
