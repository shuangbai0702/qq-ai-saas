# FishBot 移动云预部署与最小化迁移验收报告

日期：2026-11-12。范围：Git 收口、移动云实际预部署、稳定必要数据投影、隔离验收；随后按用户授权切换网站并启动无账号的 Agent 试运行，不执行生产 QQ 接管。最新网站及监控状态见第13节。

## 1. 结论和未完成边界

**移动云已运行新的 PostgreSQL、API/Web，并完成真实 AstrBot SDK 隔离测试、空白 QQ 配置的原生 NapCat 启动、API 故障自动恢复和临时外网 HTTPS 验证。稳定认知、账号配置及有现行引用的 Social 素材已经迁入并读回校验。**

华为云仍是唯一生产 QQ 消费者。预部署首次验收时移动云为 preflight；随后用户授权网站直接切移动云、Agent 也应启动。当前网站和 Agent 在移动云运行，生产 QQ 未迁入，原生产执行权文件仍不存在；未调用真实付费模型或发送 QQ/B站消息。

**本次尚未实现“晚上执行少量脚本即可确定几分钟切换”的全部条件。** 两个关键缺口：

1. Linux QQ 登录资料在 Windows 原生 QQ 中免登录恢复的最小文件闭包及兼容性，未得到证明。不能用 `identity.json` 或目录存在代替登录验证，也不能为此盲目复制整个 QQ 聊天档案。
2. 最终冻结后的跨 PostgreSQL、SQLite/WAL、Journal、unknown/partial 回执及引用媒体的完整采集、独立两端验收和切换编排，尚未端到端演练。已交付文件差量复制及 manifest 预检工具，不能把它们说成完整切换系统。

因此本轮交付是**已验收的预部署环境和必要稳定数据**；正式接管仍受上述条件约束。旧服务器和原数据保留，没有强行上线。

## 4. 最小数据集合如何推导

依据当前PG外键和Schema、`agent.context` 的配置授权回执来源、SQLite认知表及checkpoint关联、`conversation_continuity.view`、sticker发送读取逻辑和QQ收藏/本地素材索引，而非按目录整包复制。

新增 `scripts/mobile-predeploy-snapshot.py` 仅生成**不可执行的稳定投影**：

1. PG表用同一个SQL语句读出，具有同一MVCC快照；Schema导出是另一时点。每个Bot的SQLite单独只读事务，**不声称各库或PG/SQLite跨存储原子一致**。
2. SQLite保留原Schema、必要产品、Scope/ID/epoch及高水位。FTS shadow建表由虚表自身完成，原文索引不搬迁；索引和触发器在数据后建立。
3. checkpoint须有实际摘要且处于可承接状态；semantic batch和管理员许可引用相同可用集合。仅凭 `state=retired` 不足以搬入孤立batch。
4. `contacts.last_text/last_output` 实际含近期聊天，排除整个contacts投影；不会把它当“联系人配置”提前复制。
5. 仅复制approved表情BLOB、绑定账号的QQ收藏索引及精确文件引用、本地reactions/gallery有效成对素材。拒绝任意路径或符号链接逃逸，不扫描QQ profile。

稳定投影不是最终恢复镜像，**不能直接恢复生产账号和任务消费**。本轮后续仅在账号停用、执行表为空的条件下启动 Agent 试运行。正式接管需取得冻结后的完整最小依赖闭包；不能把空原文投影解释成“生产已经合法退休”。

### 13.1 主机采集告警根因及修复
