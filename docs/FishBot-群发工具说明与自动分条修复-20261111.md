# FishBot 群发工具说明与自动分条修复

实施提交：`6a0d759ad4734ff5d5524e516c3803bd0f49c9d3`，已推送 main。

## 事实及原因

生产证据显示，普通群聊曾调用 `hosted_qq_group_send`，被当前工作的工具授权检查拒绝，随后普通回复仍成功发送两条。模型将工具拒绝解释为整个群不能发言，属于错误概括。最新一次调用来自主人在当前群的普通聊天，授权门通过，工具发送成功；完整文本含空行却只取得一个 QQ 回执。原工具发送实现未调用普通回复使用的分条函数。

原说明强调“真正发送”，没有明确普通当前会话回复通常直接输出，也没有解释工具授权拒绝与 QQ 禁言的区别。这是已确认的说明缺口；不能从日志证明模型内部选择工具的全部因果过程，也不能保证补充说明后绝不再选错。

## 修改及边界

- `group_actions.py`：补充统一工具说明和授权拒绝解释。工具继续通过同一目录对群聊、私聊、主人及普通发言者提供，实际发送保留原授权校验，不按发言者隐藏工具。
- 复用 `message_layout.split_messages`，遵循现有 `splitMessages` 开关。空行最多拆四条，多余段落合并到第四条；单换行不另发；代码和列表保持布局。提及只在首条，准备好的图片只在末条发送一次。
- 同一源事件保留一次发送预留，逐气泡持久化真实回执。部分成功、未知尾部、取消、配置失效均停止剩余发送，不重发整批。旧单条回执继续兼容；多条进度存于现有回执列，不改数据库结构。
- `behavior.py`：整次工具发送只结算一次互动，保留已确认前缀、全部回执及完整性标记；后续 freshness 检查携带已发前缀，不把尾部误作首次发送。
- 不修改 System、已提交 Journal、压缩轮数、任务授权和已有业务状态。
