## 2. P0：受众隔离与既有前缀安全

### P0-1 任意群摘要进入其他会话的滚动背景 — PASS

**根因**：`Reflection.rolling()` 将所有 `group:*` 小摘要作为共享背景，不要求当前私聊 QQ 的真实参与记录。查询召回已有参与者门槛，但滚动背景绕过它。即使 QQ 只在摘要正文被提及，也能得到该群摘要。

**修复**：本群摘要仍可用；私聊跨群背景使用现有 `summary_rows()` 与 `memory_summary_people` 证明；其他群背景不再无条件灌入。明确的同一 QQ 跨群私查询召回保留原有规则。

**证据**：新增 `test_rolling_excludes_unrelated_group_but_preserves_participation`；`shared_memory_test` 同时验证真实参与者重启后可召回、仅被正文提及的 QQ 不可召回。旧测试曾要求向该非参与者披露，已纠正该安全预期，保留合法访问断言。

### P0-2 未知来源或 self 核心便签被视为公开资料 — PASS，历史证明不完整部分 BLOCKED

**根因**：`core_note_visible()` 对空来源、`*`、单一 `self` 返回公开可见；`legacy_unverified` 标签并不阻止模型接收。

**修复**：未知来源只保留内部/管理读取及配置所指机器人的主人私聊可见；单 scope、多 scope 维持既有隔离规则。`conversation_context()` 传递可信配置 `ownerUin`，避免收紧时同时错误阻断主人可见的核心便签。没有从用户正文推断主人身份。

**已提交前缀**：仅过滤新快照不足以清除旧 journal。新增 `retained_context_visible()`，在前台准备请求时检查平台生成的历史资料包：已知不合法的核心便签、全局滚动背景不得继续复用。发现冲突仍走原有合法重构许可检查；无许可明确拒绝，**不编辑旧消息、不添加隐私应急重构例外**。

**兼容边界**：只对有可靠结构和来源用途的资料判断，保留合法的同 QQ 跨群私查询召回。已经合并删除、无法恢复参与者证明的历史摘要不能凭空补证；本轮没有改库迁移，也不宣称旧历史全量排漏完成。部署前必须检查对应私有快照并选择合法检查点处理；不能为了不中断而放行已证非法资料。

**证据**：`test_unknown_and_self_core_note_not_public`、`test_forbidden_committed_memory_blocks_without_rewriting_prefix`、`test_personal_query_recall_is_not_confused_with_global_background` 及 D2、群私记忆回归。

## 3. P1：记忆保真、并发与状态合同

### P1-1 自然纠错可伪造替换值、误处理普通第一人称或覆盖新版本 — PASS（确定性边界），语义完整性未保证

**根因**：只有 quote 来自用户并不足以证明 newValue；旧实现没有要求替换值出现在 quote。没有比较抽取开始时的版本，A→B→A 后迟到结果仍可能覆盖更新。精确 scope SQL 又遗漏同一人的群→私旧事实。

**修复**：用现有 `fact_rows()` 选择同一真实 QQ 当前事实；比较 `(source_scope, version, event)` 与抽取前快照；拒绝相同新旧值；替换值须出现在真实引用中。引用须出现旧值及明确纠正关系；转述、引用、假设和普通第一人称不能直接授权。歧义进入现有 `correction_unverified`，不直接写事实或旧值阻断。

**差异**：有效的“我不叫甲，叫我乙”“小寒也不对，我叫阿寒”“别再叫我江哥了”仍生效；模型不能凭空替换为用户没说的名字；迟到 ABA 被拒绝。未明确提到旧值等歧义表达会等待核实，不能声称所有自然语言纠错都自动识别。

**证据**：新回归中伪造、同值、ABA、引语、假设、普通聊天、合法跨 scope 场景；D3 全部回归。身份来自真实事件 sender，非模型自报。

### P1-2 失败的显式恢复提前解除遗忘阻断 — PASS

`ScopedMemory.remember()` 先 `release_value()`、后额度判断，导致写入失败也解除遗忘。改为事实 INSERT 成功后再解除该明确值的阻断，仍在调用者事务内，不改变其他值的纠错记录。新增 200 字段额度边界用例，失败后 `block_all=1` 不变；正常恢复及多次纠错继续通过。

### P1-3 受保护证据被截短却算作完整保留、被遗漏的原轮次仍获覆盖证明 — PASS；极端容量 BLOCKED

**根因**：`derive_claims()` 在判断与保留前截短，保护 ID 对应完整原文但实际正文只有前一段；`fit_claims()` 静默过滤无效长 claim；摘要事务仍给受保护内容未承载的事件写 coverage。后续可凭该证明省略完整原轮次。

**修复**：先按完整原文识别保护信息。普通 claim 保持既有短表示；保护内容不假装截短等价。超出既有单 claim 上限的保护内容列为 hold，保留原轮次/材料；holds 事件不发 coverage、不清 pending。存在 holds 的批次不得签发 35 轮重构许可。编码预算补计 JSON 列表逗号，严格保持原有有界上限。

**不做的事**：没有删保护事实、降低 35 轮、扩大容量、偷偷重构或新建记忆库。超长保护段目前不自动拆分；因此安全保留后可能阻止压缩。其正常真实轨迹发生频率与容量裕量本轮未重新测量，发布门槛仍 BLOCKED，不能将 fail-closed 当作已完成容量优化。

**证据**：长保护段、精确字节预算、D4 hold/no-coverage/no-checkpoint 断言；原文保留与摘要事务测试。

### P1-4 保护信息存在数据库，但模型召回看不到；claim-only 更新未进入并发依赖 — PASS

**修复**：`summary_item(..., db=...)` 从现有 v2 claims 附加受保护内容；搜索、词法、语义候选、滚动路径统一使用。按既有受众门槛选择后再附加，不放宽 scope。核心便签的受众校验后同样输出现有 claims。`context_dependency()` 增加 schema_version、claims，只有 claim 变化也能使旧候选失效。

**证据**：`test_protected_claim_reaches_model_and_fences_inflight_update` 检查真实返回对象与指纹变化；摘要、上下文装配、恢复回归。没有用“库里还有”代替模型可见性断言。

**代价**：被选摘要附带保护原文会增加请求体，受既有 claim/请求容量限制。没有实际上游 token、费用或完整 35 轮资源前后测量，不声称缓存费用下降。

### P1-5 两个不同 System 变更在提交 CAS 之前均可发送 — PASS

**根因**：原有 `SystemContract.reserve()` 允许两个不同可信 token 同时预留不同目标，直到 settle 才发现冲突；此时两个请求已可能发给模型。

**修复**：事务内检查其他未完成的 System 变更；目标不一致则报 `system_change_in_flight`，禁止第二个非法向量进入请求边界。第一次失败释放后第二次可重新申请。复用原许可与事务，没有新增许可种类、角色、超时豁免或 scope 旁路。

**证据**：`test_conflicting_system_transitions_cannot_both_be_sent` 确定性复现 reserve A → reserve B → abort A → retry B。现有 System 数量、位置、顺序、完整内容、可信 token 一次消费和实际 wire observer 测试通过。

**行为影响**：不同 System 的并发请求会明确失败，未增加自动排队或自动重试，避免扩大生命周期和外部副作用风险。

### P1-6 收藏同步与后台维护并发覆盖状态、伪造 manual 标识、绕过有限重试 — PASS

**根因**：最终合并只比较部分字段，后台更新的 semanticAttempts/failures/retryAt 可被迟到同步覆盖；部分并发分支把维护结果当人工编辑。网页重新同步对 uncertain 结果又采用不同条件，无法遵守已有共享尝试上限。

**修复**：最终锁内比较同一条完整初始/当前记录；有并发更新时保留最新完整记录，删除本次临时生成而当前记录没有的字段，撤销对应 staged 媒体替换。没有将其擅自标为 manual。网页同步复用既有 uncertain≤3、failure≤5 与 retryAt；压力/聊天忙仅延后、不消耗尝试。数值来自现有维护策略，没有修改产品预算。

**证据**：新增 Node 确定性 barrier 夹具，分别覆盖 maintenance retry 与 manual 编辑晚于 caption 开始的交错；原维护、账号变更、API 所有权、取消清理、图片语义回归。

### P1-7 QQ 原描述被网页同步自动赋予可发送语义；旧索引绕过语义确认 — PASS

**修复**：QQ modifyWord/desc/ocrWord 仅记 rawText/rawSource，新条目默认无确认语义；人工确认或 clear 视觉结果才可进入自动候选。同步时降级无证据的旧 meaning；Python `descriptions()`、`catalog()` 在读取边界也复用 `confirmed_meaning()`，无需等维护先跑。仅 semanticStatus='ready' 的字符串不能替代确认记录。

**保留能力与代价**：人工编辑、clear 视觉、原始动图、账号隔离均保留；未确认的旧索引仍保留文件和描述，不再自动选择，需要现有网页确认或视觉维护。没有替用户批量确认历史条目。现有“未建索引收藏的显式 prepare”兼容路径未重构，其实际用户选择证明能力见剩余风险。

**证据**：新增 Python legacy-index 测试；新增 Node raw-description 测试；正常候选夹具补充其真实语义确认来源，保留原有媒体、发送及隔离断言。

### P1-8 一次性收藏附件清理后仍可再次 prepare；图片发送统计被局部变量覆盖 — PASS

**修复**：在任何 await 前检查既有 `_hosted_meme_sent`，不依赖已被消费清除的附件对象，未知回执也不重新准备。移除重复不可达判断。发送清理使用独立 `prepared_sticker` 变量，不再覆盖已选择的 `image`；发送成功后恢复 image_sent、冷却和统计。

**证据**：准备对象已消失但 sent 标志仍在时，新增用例要求直接 already_sent、登录/下载调用均为 0；SDK 原生媒体测试检查 lastMemeDecision=sent、分条图片只出现一次、首条路由、跨机器人/账号拒绝，以及中途替换 lease 不发送尾部。
