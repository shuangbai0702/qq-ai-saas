## 4. Journal/SDK/摘要/记忆专项

### 4.1 职责分工（代码确认）

- **Journal**（readonly_journal.py:1-5 自述"Disposable provider wire continuity"）：`fishbot_readonly_journals(scope PK)` 存 base（投影消息深拷贝）/wire（实际发送字节，append-only）/state（只读资料包合并态）。用途：前缀复用（缓存）、崩溃恢复、素材重捕。
- **SDK**（native_history.py）：只接管轮次限流（完整 user 轮截断），"15条窗口"是 AstrBot provider 配置值经 `keep_most_recent_turns` 传入，仓库内无硬编码；**窗口截断不回写 Journal**。SDK 任何再水化差异都靠 5 个窗口适配函数（confirmed_native/tail/window_reload/uncommitted_head/fresh_event，readonly_journal.py:58-290）弥合——**双份维护是最大复杂度来源**，新 SDK 字段可能触发整份重建（prefix 失配→native_prefix_changed）。
- **状态机**：prepare→stage_candidate（落盘失败=拒绝发请求，behavior.py:1392-1397）→HTTP→settle：成功一律 commit（含摘要依赖变更，防死锁一）；submissionStage 四值（request_not_sent/provider_response_received/provider_stream_started/request_submission_unknown，model_cache.py:364-396）；unknown→retain（许可消费不回借）；遗忘→retire；确定未发送→abort 恢复上一快照。
- **容量**：传输 512,000 文本字符/2MiB wire（decision_history.py:20-21）；快照存储 16MiB/bot、64 ready、4096 墓碑；HTTP body>4MiB 候选期即拒。无许可触顶→ContextCapacityExceeded（诚实阻塞）。

### 4.2 35轮压缩与许可（代码确认+生产证据）

35 完整业务轮（合同归一化，非35配置计 summaryRoundsIncompatible）→ 摘要（800字）+ 铸造**恰好一个** checkpoint（UNIQUE(scope,through_round_id)）；uncovered/protected Hold 重入下一批或独立恢复（hold_recovery 不动水位/不计轮）；protected 冲突使 big merge 放弃。**生产实锤合法压缩链**：d18ad07d 01:56:19 与 02:04:06 两次 small_summary（in=13,106/13,144），每次后 foreground in 从 74.5K 掉到 23.8K 重启前缀，随后 16 个 checkpoint consumed——压缩、许可、消费、缓存在生产按设计闭环。

### 4.3 Claims/Facts 召回与去重（代码确认）

- facts：显式>自述；遗忘/纠正块（含"改名字段也不能带回旧值"）；每日20条预算；版本化保留10版。
- 召回三通道：词法 recall、语义 recall（未启用）、FTS5；受众闸门 `memory_audience`+`retained_context_visible`（需已提交 wire 中已有该记忆才可见）。
- **跨scope通道只有两条**（对同一 QQ 号，`person_filter`：memory_scope.py:14-19）：①facts 跨 scope 匹配 subject；②`recent_cross_session_messages` = memory_pending 的同人未压缩消息（**默认 cross_scope=True**，memory_scope.py:235-249；conversation_context 里的 recent_messages 则显式 cross_scope=False）。条目形态 `{kind:'recent_uncompressed_message',source_scope,sender_id,at,age_seconds,user,bot}`，7天窗、≤16条、3000字符预算。

### 4.4 已证实的结构性风险（代码确认）

1. **持久化失败后的内存-磁盘分叉**（readonly_journal.py:672-673,690-694）：commit/retain 落盘失败仍设 `self.last=prepared`+`retired_reason='persistence_unavailable'`——内存有了新基线而磁盘没有；下次 prepare 失效→needs_reconstruction→无 checkpoint 则 ContextRecoveryUnavailable。磁盘满期间该 scope 只能等摘要（摘要本身也要写库）。这是注释自认的取舍。
2. **retired 快照永不释放字节**：16MiB 预算计入 retired 行（:374-385），只能运维清理。
3. **memory_rounds 对重复事件 INSERT OR IGNORE**（:118,342）：同 event 重试的新内容被静默丢弃。
4. **window_reload_extension 纯 assistant 尾部死角**（:287）：重载后新尾部若无新 user 事件不被采纳，依赖兜底函数；极端顺序下可能反复 native_prefix_changed。
5. **媒体轮次占位符**已修（20261107 D包，behavior.py:1119-1133）但"待自然样本验收"。
6. **新发现（本轮）**：多气泡回复只把第一个气泡记入 memory_rounds.answer（02:25 案例 len=50，第二个气泡 36 字未入账，见 5.6）——记忆归属不完整，影响后续摘要素材。
