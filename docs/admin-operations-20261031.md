# 管理员运营增强（2026-10-31）

固定计划：
1. 保留内存监控、激活码；新增分页用户/名额、全平台机器人诊断、管理员名额操作记录。
2. 仅管理员读取跨租户的必要元数据；普通租户路由不扩大权限，不读取密码、模型Key、人格、聊天或QR。
3. 调整名额锁定工作区，与创建机器人共用锁；校验期望旧值、范围和实际占用，审计同事务提交。不得缩到现有占用以下。
4. 前端明确确认、失败提示、分页/搜索和迟到请求保护；无后台持续新轮询，不增加常驻服务或数据库表。
5. API权限/并发/分页/脱敏回归、浏览器桌面/手机、构建及Linux隔离验证；仅Web/API部署，备份及PID/在线核验。提交和两端同步沿用用户已有授权。

不加入跨租户启动/删除、杀进程、密钥查看、聊天窥视、封号/重置密码、收费系统。本轮只补运营所需最小能力。

## 实现与入口

顶部入口改为“平台管理”，保留既有内存监控和激活码。新增运营分区：用户与名额（按工作区列成员及邮箱、机器人占用/限额）、全部机器人（名称/QQ/邮箱/工作区搜索，在线/待连接或错误/停止筛选，QQ与AI状态、共享组、配置版本）、名额操作记录（操作者、前后值、原因、时间）。查询每页20条，上限页数及关键词长度有边界；新列表只手动刷新和切换查询，不增加定时轮询。

API新路由独立注册在 admin-operations.ts；所有入口先验证管理员。普通 /bots/:id 权限保持按租户，管理员不因此获得跨租户机器人编辑或秘密读取权限。机器人列表使用显式返回字段，健康载荷中的额外字段和错误原文不透传。名额1–20，与创建流程共用 tenants 行锁，检查期望旧限额及有效机器人数量（含删除中），实际修改和审计同事务；相同值保存不生成重复记录。审计列表仅取本次名额事件的指定字段，不透传任意历史detail。
