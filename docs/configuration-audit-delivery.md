## 实际修复

| 问题 | 原因与修改 | 验证 |

| 主动概率实际比填写值高很多 | `adapters/astrbot/initiative.py:candidates` 原来每次5秒轮询都重新抽签；现按每个会话的主动间隔保存一次抽签结果。失败窗口重启后保留，修改概率立即重新判定；成功结果在重连期间保留，实际尝试仍受额度/间隔/未回应限制 | 新Python测试覆盖重复轮询、重启、概率变化和重连 |
| 目标授权正确但没有主动联系 | 原先先取最近100个联系人再筛选授权名单；改为先按授权名单查找，最多50个 | 120个无关联系人不能挤掉授权目标 |
| 群插话未发出却扣额度 | `behavior.py:eligible` 先扣额度再检查回复冷却；现在先判断冷却。不再因旧配置仅开启 proactive 就隐式开启2%随机插话 | 冷却不扣、有效尝试扣一次、旧配置默认不插话 |
| 分条开关悄悄改变其他偏好 | `bot-detail.tsx` 分条开关只改 splitMessages；跟进、合并等待和间隔独立编辑 | 浏览器保存/刷新后73秒、600毫秒和1100毫秒的自定义值保持 |
| 关闭功能后看不出为何不生效 | 能力页明确聊天总开关、记忆依赖；关闭时保留子项偏好；其他分区显示总开关关闭提示。无目标、零额度或零概率有阻塞说明 | 浏览器验证禁用状态、保留偏好和阻塞提示 |
| 学习开关可能连带改变语境判断 | 编辑器读取旧配置时固定其原有的 socialAwareness 有效值，之后开关独立；不会批量重写客户配置 | 开学习后语境判断仍关闭，保存刷新不变 |
| 清空学习后原表达永久学不回来 | `data_admin.py:clear_learning` 清除该群样本、表达与停用记录；旧任务仍被 epoch 拦截，新消息允许重新学习 | 新样本可重新形成相同表达，既有迟到任务测试保留 |
| 人物筛选不筛选人物状态 | `data_admin.py` 的关系查询增加 subject 条件，同时保留 scope 条件 | 两人状态只返回指定人物 |
| 回复字数上限可被多文本组件绕过 | `behavior.py:send` 对同一回复的多个 Plain 组件共用剩余字数 | 原生SDK测试：三段共150字，限制80字，实际仅80字 |
| 保存成功后误报服务器有新版本 | 配置冲突判断从版本不等改为服务器版本更大；保存版本显示取本地保存回执与读取版本的较大值 | 浏览器人为返回旧轮询快照，保存后没有错误冲突 |

## 操作体验

- 主动目标用“私聊/群聊 + 号码 + 添加/移除”，无需输入 `private:`、`group:`。数字长度、重复及50个上限仍有校验；需要已有聊天记录才生效。
- 行为数据会话筛选同样改为类型与号码。明确人物筛选作用于事实/关系，关键词仅作用于事实，计数是整机器人累计。
- 记忆纠正和图片场景编辑改为页面内对话框：长度计数、必填、保存中状态、局部错误与取消。通过 portal 避免表单嵌套；Ctrl/Cmd+S 不会误保存外层机器人配置。
- 首次行为数据读取失败会显示重试入口，不再永远显示“正在读取”。图片操作成功但刷新失败会说明操作已提交，避免把重试当成未执行。
- 明确北京时间安静时段、起止相同的含义、主动联系与随机插话共用每日尝试额度、零额度的作用，以及图片额度北京时间08:00刷新。没有为了统一文案改变现有图片计费日界。
- 增加角色主人QQ号编辑入口；不授予平台管理权限。群白名单支持逗号/空格/换行，并说明空名单允许所有群。

## 配置建议与边界

当前默认采用被@触发、不随机插话、不主动联系、自动记忆与表达学习按需开启。这能避免刚创建的机器人打扰群聊或无意产生学习调用。需要更像群友时，可按实际群氛围开启90秒跟进、800毫秒消息合并和短句分条；这些是界面建议，没有直接覆盖用户参数。

主动联系必须同时满足授权目标、真实历史、安静时段、每日预算、沉默时长、尝试间隔、概率与未回应上限。0.25是每个符合条件的间隔25%概率，不承诺每小时一定发言。群内随机插话是另一个设置，关闭主动联系不会自动关闭已独立配置的插话；两者共享预算。模型选择不等于推理验证通过，AI进程就绪不等于QQ已在线。

自动收图/视觉识别、完整个人风格模仿仍未接入，没有添加无效开关。本次验证配置语义及接口，不证明真实模型在所有群聊场景下都自然，也不承诺所有配置组合已穷举。
