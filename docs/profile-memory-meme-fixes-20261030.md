# 签名、内存回收与发图配置修复（2026-10-30）

## 签名

原因：模型工具参数直接进入 QQ 资料接口，没有经过聊天消息控制标记处理。qq_actions.py 在昵称、签名、说说操作边界移除 QQ_FACE/MEME/IMAGE/NO_REPLY 标记，在限长、额度、防重复、历史和网络调用前完成清洗；保留普通方括号和 Unicode emoji，清洗后为空则拒绝。工具描述同步要求普通文本。

真实签名从“被夸可爱了，今天尾巴翘得高高的[QQ_FACE:4]”清理为“被夸可爱了，今天尾巴翘得高高的”，get_stranger_info 无缓存读回一致。没有为此额外发消息或发布说说。QQ 自身可能同步签名到空间，未独立验证该机制。

companion-features、plugin-alignment、plugin-runtime 共 5/5 通过，包含执行边界过滤、防重复、真实 AstrBot 工具路径。初次正常启停未替换共享 AI 进程，不能作为代码加载证据；后经私有路径及创建时间校验结束旧共享 AI，由服务恢复至新 PID 57528，AI 就绪、QQ 在线，完成加载。

## 内存

runtime_memory.py 空闲等待由 300 秒改为 60 秒，Windows 与 Linux 一致。保留活动阻止、CPU 判定、每活动周期一次、5 分钟尝试间隔及进程所有权校验。Linux 移除“空闲内存充足则跳过”的条件，仍要求 swap 和原生接口支持；每次匿名私有驻留页换出建议最多 64 MiB，保留 cgroup 回收及降级行为。Windows 使用 EmptyWorkingSet，是工作集回收建议，不是固定 RAM 上限或直接指定压缩比例。

行为内存回归入口通过，内部 20 项全部通过，含 59/60 秒边界、活动保护、冷却、PID 替换、无 swap 降级和 Windows 实际子进程原生调用。脚本每次从磁盘读取，线上热生效。线上持续有活动，最终回执 waiting-idle；未取得当前真实 QQ 空闲回收前后降幅，未在 Linux 主机执行实际换出。

单号采样：NapCat 约 199–208 MiB，共享 AI 进程树约 193–210 MiB；不含控制服务、数据库和系统开销，也不含独立桌面 QQ。主机约 31.2 GiB RAM，首轮可用约 10.2 GiB，系统 Memory Compression 工作集约 1.67 GiB，为全机值，不能归因单个 QQ。

## 发图配置

用户要求提高附图频率。旧值：memeProbability=0.35、冷却60秒、每天20张。经现有认证配置 API 保存为 v17 并确认 applied_revision=17、AI ready、QQ online：概率0.7、冷却20秒、每天50张，增加轻松闲聊多数轮次选贴切候选图的角色提示。原有配置字段逐项保留。接口拒绝最初10秒/200张提案，最终使用现有允许范围，未放宽合同。配置 API 补齐了新增选项缺省值，未主动启用这些选项。

70%为模型已选图后的放行概率，不是所有回复必达70%；还受合适候选、冷却、额度和实际投递限制。未执行大量真实发消息来统计频率。
