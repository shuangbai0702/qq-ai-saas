## 1. 结论与交付边界

1. **连续性有实际改善**：把取舍单位从用户事项改为双方互接，保留助手实际回应，并明确谁称呼谁。两组真实模型对照中，原提示都漏掉了目标助手回应；最终候选都能恢复互动链。中间版本出现过称呼方向反转，已保留失败证据并补约束复测。只是两个合成题材的局部结果，不是生产自然度全面达标。
2. **生产认知确实在更新，但不能把写入当认知质量**：发布后事实11项、关系3项写入被接受；核心便签5次提议4次被 `unknown_event` 拒收。3个Bot库共4份已提交Journal能看到选中的事实、关系、表达、摘要、约定及经历。最新12条事实因原文已退休或不可定位，无法重新证明语义准确。
3. **10K不是本次端点的统一缓存门槛**：实际供应商输入4.1K、6.9K、8.1K、9.6K、9.7K及10.3K左右都出现正缓存Token。匹配一路生产配置的 `nai / deepseek-v4.1-flash`，稳定追加时8/8暖请求命中；同一9.6K前缀约347秒后却返回0，再追加恢复9472。客户端完全一致不保证服务端仍有缓存。
4. **没有为了制造收益改动缓存历史**：未发现本轮可证明需要修复的客户端前缀破坏；routing key没有显示额外收益，显式断点参数返回400，不采用。没有重排/合并旧消息、刷新Root、偷改检查点或发付费保活请求。

本轮仅本地修改和提交。没有部署、推送、修改生产数据库/Journal、真实QQ/B站发送、重放unknown或重新登录。

## 3. 分项一：双方互动连续性

### 原问题、实际修改

前次资料会保留用户说法或最后待办，却忘记机器人怎样接住、玩笑如何延续、称谓如何修正。此次换用未用于前次调优的两种题材：低电收音机/频道互接，以及导航员改成长椅的语气修复；末尾分别混入挪薄荷、邀请卡未改且不要发送，避免只测试没有竞争信息的简单对话。

修改仅 `adapters/astrbot/conversation_continuity.py:16` 的局部生成合同：

- 以双方互接的一段交流为单位，成对保留用户触发说法和机器人实际回应/修正短句。
- 不以话题标签、情绪标签或最后待办代替互动。
- 称谓明确谁称呼谁，自称、用户对机器人的称呼和机器人对用户的称呼不可互换。
- 没有实际回应就标未答，不编造；近期新交流仍优先，不强迫续聊旧话题。

没有把合成题材里的词写成生产关键词，没有结构化强制复制固定几轮；仍在原本一次摘要调用生成500字符以内产品，接收器、持久化、35轮许可、固定基线、退休及账本均未改变。

### 实际API方法及口径

独立合成资料，不使用生产正文。请求保存完整JSON、物理消息角色及边界、逐消息hash、tools hash、请求hash、端点hash、共同完整消息数、首个不同块、共同序列化字节数、UTC时间、请求间隔、实际usage、总耗时。每条链只追加独立消息，旧块字节不变；另做独立负对照，将合成System早期时间值改变，绝不操作生产历史。

本地 `o200k_base`只作构造长度/完整块前缀代理统计。以下表格输入和命中均为**供应商实际usage**；供应商隐藏模板、tools位置和tokenizer不可见，不能把本地JSON Token数当其精确缓存Token或首差Token位置。完整JSON字节首差也不是供应商首差Token。

延迟是客户端非stream完整响应耗时，记录的首响应chunk在此模式不等于模型首Token时间；不从总耗时归因上传、排队或模型执行。即时请求从上一响应完成到下次发出约0–1ms，实际起始间隔还包含上一请求耗时。延时复测另记录匹配前缀上次响应后的间隔。

缓存实验共39次生成尝试：36次HTTP200、3次显式断点参数HTTP400；另GET `/models`一次。显式参数组合未被此兼容接口接受，不能断言是哪个字段不支持，更不能把400算缓存0。脚本预设同组3请求，首个400后仍执行了其余两个，这是低价值的多余验证；未上线该参数，后续应遇明确不支持即停止该候选。

### 客户端稳定率、供应商命中率与成本

初始GPT/DS构造组中，合规追加候选共22次（含显式参数被拒的2次暖候选），客户端完整旧消息块及tools保持率22/22；获成功响应的20次暖请求全部有正缓存字段。分母不含冷启动、早期System负对照，也不是生产稳定率。

- 初始GPT组（含route及GPT6对照）：成功暖请求12/12正命中，103,040 / 105,122输入Token已缓存，约98.02%。
- 初始DeepSeek组：8/8，76,032 / 77,682，约97.88%。
- 加延时/重热后，成功追加23次仍全部旧块相同；供应商正命中22/23，1次明确0。该例已直接否定“客户端前缀稳定=供应商必命中”。这是所选样本的描述，不是SLA。
- 未发生生产代码/配置缓存优化部署，故**生产前后命中率提升和账单下降未证明**，不能把冷热对照算部署收益。

中转未提供可核验的币种、单价、命中折扣或逐请求扣费字段。usage.credit含义未明，不按费用解释；实际金额与成本变化unknown。仅可计算条件公式：`(输入-缓存)*未命中单价 + 缓存*命中单价 + 输出*输出单价 + 可能的写入费`。不能擅用官方直连价作为中转账单，也不能只按缓存比例宣称节约同等百分比费用。

### 官方规则参照与接口事实的界限

[OpenAI缓存指南](https://developers.openai.com/api/docs/guides/prompt-caching)说明连续匹配前缀、模型相关边界与最低长度；[接口文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)描述显式断点参数。官方支持不代表中转实现相同，本轮中转对参数组合实际400。

[DeepSeek缓存指南](https://api-docs.deepseek.com/guides/kv_cache/)说明独立完整缓存前缀单元、请求/共同前缀/固定间隔写入和best-effort；这使“前段文本相同”仍不保证命中。[直连定价页](https://api-docs.deepseek.com/quick_start/pricing/)区分命中与未命中费率，但不是nai账单。本轮没有证实中转实际缓存类型、最小块、TTL、隐藏路由或会话粘性，不声称官方条款在中转均成立。
