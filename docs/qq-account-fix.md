# QQ号修改与机器人删除修复

用户要求：扫码QQ与预填号码不一致时，必须能修改；机器人必须能删除。

实施：QQ连接页独立编辑预填号码，允许留空，使用版本检查；更改账号时先停止旧AI/协议、撤销旧绑定和在途登录，保留登录文件但不把旧绑定当作新身份。保留真实扫码身份校验和QQ唯一性检查。删除从隐藏设置移到明显入口，先确认，显示异步删除进度，失败可重试。

验证：隔离API测试修改/清空/权限/版本冲突/旧登录失效、真实管理器执行删除后不可再访问、浏览器修改和确认删除；构建与生产检查。不得代用户删除现有机器人或覆盖其账号配置。

## 2026-10-30 交付结果

- 根因：Agent.context 原来使用 `expected_uin || binding.qq_uin`。空输入会被旧绑定补回，因此页面留空仍限制账号。现在只使用明确填写的 expected_uin；真实身份格式及账号唯一性检查仍保留。
- `PUT /v1/bots/:id/qq-account` 检查归属与 revision，改变号码时递增 generation/revision、停止旧连接、撤销旧绑定及有效二维码；保留人格、Key、记忆及登录文件。原配置保存接口保持兼容，网页改号使用新接口。
- QQ连接页新增显式编辑卡片。清空即不限制扫码账号；填写时只允许对应账号。保存后重新获取二维码。旧失败登录记录属于历史状态，刷新登录后才会被新会话替换。
- 删除入口移到各详情页可见位置，保留确认、进行中、失败重试和完成后回列表。浏览器测试实际执行 Agent 删除，不仅检查按钮。
- 身份健康探测增加 generation 检查，防止改号前的迟到结果恢复旧绑定或停止新连接。
- QQ编辑卡片和二维码卡片统一1050px最大宽度、左右边线和间距；390px手机布局无横向溢出。浏览器断言两卡片的 x/width 差小于1px。
