# FishBot 全项目提示词质量优化研究与实施计划

日期：2026-11-12。依据：[提示词深度审计](FishBot-全项目提示词与工具契约深度审计-20261112.md)、当前实现及现行上下文合同。研究与计划基线：`main / a3fd4cc3ba767b1621cbbff5a3ef7ff7eeca1fad`。

本轮交付研究和实施计划；尚未修改运行提示、调用付费模型或部署。本文中的候选写法、样本数和阶段均是待实施方案，不能作为已改善质量的证据。

## 1. 要改善的结果

目标是让 FishBot 更准确地理解、记住、选择、行动和表达，同时减少相互冲突的规则。修复 13 项审计问题是基础，质量提升另行验证。

| 质量目标 | 希望看到的行为 | 不采用的替代指标 |
| --- | --- | --- |
| 长期理解 | 压缩后仍理解人物、关系变化、目标动机、约束和不确定性 | 摘要写得长、所有字段都更新 |
| 自然表达 | 接住具体话题，有符合角色的立场和情绪，认真问题有充分内容 | 更短、更多口癖、更多表情或每轮追问 |
| 合法自主性 | 有机会判断，能续接、修订或放下目标，能行动也能休息 | 主动次数或工具调用数越高越好 |
| 工具能力 | 选对入口、使用真实句柄，按实际结果调整后续 | JSON 合法、调用函数就算完成 |
| 真实性与边界 | 不混作者、时间、权限、猜测、执行状态 | 多写免责声明或一律拒绝 |
| 工程可维护性 | 一个规则有明确责任，最终请求可检查，旧历史可恢复 | 大量拆文件、新框架、纯字符数下降 |

**优化收益必须表现为后续行为更好。** 文案更漂亮、结构更规整或 Token 更少，都不能单独证明质量提高。

## 2. 资料研究及适用边界

使用 OpenAI Docs Skill，查询并实际打开官方提示工程、工具、推理、评测与长期记忆示例。资料是候选设计依据，不是本项目已经验证的结论。没有调用自动提示优化服务，没有把项目私人材料上传给评测平台。

| 第一手资料 | 对本计划有用的原则 | 项目采用方式与边界 |
| --- | --- | --- |
| [Prompt engineering](https://developers.openai.com/api/docs/guides/prompt-engineering) | 任务、规则、例子和材料分清；用覆盖不同情况的少量例子解释目标 | 整理最终拼装结构，并为易错语义提供例子；不把所有提示合成万能大段 |
| [Function calling](https://developers.openai.com/api/docs/guides/function-calling) | 明确用途、适用场景、参数和结果；减少无效参数组合，程序提供已知信息 | 工具声明与真实宿主一致；身份、目标和预算继续由后端校验 |

| [Evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices) | 用真实任务分布、明确标准、配对比较和人工校准，注意位置与冗长偏好 | 合成代表性材料、盲化比较、多种可接受行为；小样本不作统计保证 |

### 本项目采用的写法原则

1. **先写目的与期望行为。** 如“保留让下一轮理解关系变化的原因和当前状态”，比反复写“不要乱记”更可评估。
2. **约束放在真正需要的边界。** 作者、授权、执行回执与输出格式明确；普通表达保留模型选择，避免每句都被规则规定。
3. **每次请求只有一个输出合同。** 人格聊天、辅助 JSON 判断、内部任务记录、压缩产品分别定义，不能用一份正文模板统管所有任务。
4. **材料完整度也是输入信息。** 明确部分展示、缺失及可操作集合；没有交给模型的资料，不能指望靠提醒恢复。
5. **少量例子解释区别。** 接受≠履行、准备≠发送、自己的新想法≠新发生的事实；例子不绑定关键词、固定回复或固定情绪。
6. **压缩保留因果和条件。** 事实列表之外，还要理解为什么形成目标、关系为何变化、哪些条件仍有效；不要求保留所有闲聊细节。
7. **减少同义叠加，保留必要语义。** 删除重复前先定位所有拼装入口；局部字符串变短不代表最终请求已经统一。
8. **修改一个行为维度，再比较。** 先建立无矛盾基线，再优化认知、表达、工具和自主性；避免把格式修复收益错算成全部质量提升。

这些是从资料结合项目合同作出的设计选择；不是“某写法对所有模型必然最好”的结论。当前生产模型身份、上游兼容性及自定义人格，实施前需核实。

## 3. 必须保留的合同

- 普通 35 个合法业务轮才进入检查点；管理员例外保留明确授权。工具循环、Provider 请求、自主周期不得冒充业务轮。
- 已提交历史的内容、角色、顺序、图片和工具结果保持不可变；A/B 混合格式可恢复。
- System 独立且按 Scope 守护。代码部署不是改写历史或改变 System 的许可；已有可信配置保存 permit 和合法检查点规则分别核验。
- 模型判断事实价值、关系、动机、是否说话和行动；程序持有授权、预算、幂等、账本、真实回执和可靠恢复职责。
- 有效定时任务、约定与执行账本不依赖聊天摘要重建或删除。
- 没有变化的产品可以省略；不能以“更新了几类记忆”奖励模型。
- 缺失原文允许按现存材料及缺失说明合法提炼；合法提交及 Journal 替换成功后按归属清理，不恢复 Coverage/Hold 或原文备份池。
- 事务失败、临时读取异常、未完成提交不能提前退休；unknown 外部操作不因提示变化变成可重试。
- 本次不迁移 Provider/API，不以稳定性为由新增关键词认知门禁，不覆盖用户自定义角色。

实施前有一个必须先收口的提交边界：当前审计发现可选产品被拒而摘要仍可能提交；最新合同要求产物可靠保存后退休。**省略无变化字段与提交了有效变更但被拒，必须分开。** 不得只增加一条 rejected 日志就宣称“全部保存、整批 clean”。在既有验证/事务路径内明确这两类结果及拒收后的处置；若最小改动无法证明安全，先保留材料并报告阻塞，不能顺便大改事务或静默放宽接受条件。

## 4. 工作包：纠错和质量一起设计

### W01：压缩与长期认知

位置：`memory_reflection.py`、`companion_insights.py`、`memory_products.py`、`summary_material.py`、`semantic_collection.py`、`memory_model_view.py`、`context_foundation.py`。

先处理 PR01/02/03/04/05/06/08，再对 PR07/09/13 作有样本支持的调整。

- 输出统一：small/big 都是唯一对象合同；summary 和各可选产品分别标明真实限制、来源及版本要求。
- 时间统一：提供可信当前时间/时区，分清历史发言时间、原约定时间和当前产品有效性，不重设持久任务日期。
- 旧事项统一：模型看得到、可以精确更新的 ID 集合要解释一致；展示裁选提供完整度，不能让未展示项被当成已不存在。
- 认知提炼：关注人物归属、关系变化及原因、当前状态、长期目标及其条件、纠正、工具经历与未知结果。保留模型有损选择，不增加逐事件覆盖清单。
- 产品分流：明确本轮生成的主协议；新语义操作承担综合认知，旧格式保留恢复/兼容职责。没有证据前不删旧解析器。
- big 不再泛化假定细节全部已进入 facts；只在材料证明另存时避免重复，必要约束仍可进入摘要或核心笔记。
- 核心笔记保持完整替换、可审视、可变更、可不变，不能成为第二份人格或每批流水账。

验收看压缩后的真实接受产品及后续理解：能否认出谁喜欢什么、关系为什么改变、答应是否已经履行、目标下一步受什么条件约束。**续问只能读实际持久化结果和本轮合法资料，不能偷偷喂回退休原文或被拒产品。**

### W02：人格、日常表达与参与判断

位置：`fish-persona.ts`、`context_protocol.py`、`behavior.py`、`periodic_guidance.py`、`participation.py`、`autonomy.py`。

- 将角色身份/偏好与公共执行规则分开维护，普通角色也能使用公共合同；不把“大肥鱼”的口癖或亲密关系套给自定义角色。
- 用具体期望替换多层“像人、不要机械”：回应眼前内容；按实际关系表达立场与情绪；提供所需信息；按语境选择留白或展开。
- 不强制迎合、安抚、反问、道别、配图或固定一两句。认真问题不为简短而遗漏关键条件；容量不足明确限制。
- 对群参与说明“本次是判断机会”，面向作者、对象及当前话题选择，不把熟悉或@直接变成必须答。
- 检查主人主动联系中鼓励表达与允许休息是否平衡；不以增加主动次数作为优化目标。
- PR11 采用既有明确偏好：语义贴切优先；同样贴切时优先 QQ 收藏，其次平台图包；明确指定来源时遵从请求。统一各层措辞，不为来源偏好牺牲相关性。

验收应同时包含闲聊、分歧、严肃求助、被纠正、无需接话和有真实接话动机；不能只用“更可爱”评分。

### W03：工具说明、参数与执行反馈

位置：`inner_tools.py`、`tenant_tools.py`、QQ/B站工具模块、`tool_outcome.py`、`execution_memory.py`、对应 contracts 与 SDK 工具适配。

- 统一为“用途和触发场景 → 输入来源/字段条件 → 实际副作用 → 结果及下一步”的简明结构。
- PR12 保留宿主限制，修正原生发送 schema/描述中的 path 和跨会话能力宣传；不能只把拒绝错误藏起来。
- 区分即时当前会话回复、授权跨群发送、准备图片、保存收藏、持久任务登记和真实外部写入，减少选错工具。
- 用已有类型/约束形成可见参数合同；已知 Bot、Owner、Scope 不让模型自造。无法用 schema 表达的互斥和来源条件在描述中说清。
- 统一 pending、prepared、confirmed、partial、unknown、rejected 的解释；已读到目录、检索元数据或字幕不能变成“看完视频”。
- 工具声明保持现有稳定性合同，动态授权、冷却和可用性放在当前权威状态中，不为优化提示偷偷改变授权或函数集。

验收分别检查工具选择、参数正确、真实执行结果解释及失败后调整；不是以调用次数多少评分。工具不适用时直接回答或询问都可以是正确结果。

### W04：自主目标与内部行动

位置：`autonomous_runtime.py`、`native_internal.py`、`initiative.py`、`autonomy.py`、`companion_schedule.py`、反馈上下文。

- PR10 统一 research：它是内部任务结果用途，不能用“只读”掩盖当前确实获授权的工具能力；内部最终文字不自动发 QQ 与工具是否可写分开说明。
- 让当前目标、形成原因、已确认成果、真实阻塞和最近反馈可理解，不把每次自主机会写成从零策划。
- 模型可继续、修订、结束或放下目标；允许形成后续目标，也允许休息。合理“放下”不必伪造成“完成”。
- 休息不取消已持久任务；新观点可以由真实经历形成，但不虚构刚发生的事件或把自主研究归给主人指令。
- unknown/迟到回执是核对与调整的依据，不奖励盲目重试。权限和预算仍由现有账本判断。

两请求样本只能检验一次续接/重估。休息后唤醒、跨进程恢复、多周期持续执行必须另由现有运行测试及后续观察证明。

### W05：辅助判断与媒体提示

位置：`group_freshness.py`、`companion_schedule.py`、`social.py`、`sticker_collection.py`、`packages/shared/qq-favorite-semantics.ts`、视频帧分析、`reply_voice.py`。

- 辅助任务只判断自己的问题，避免继承主聊天的正文、表情或语音格式要求。
- freshness 保留 keep/replace/drop 与 responded/ignored/尚需处理的区别；允许空集合，不能为提高吞吐把“看见”当作处理。
- 图片和视频分别说明看见什么、采样缺口及不确定性；人物、音频、未采样动作和梗来源不能靠猜补。
- 表达学习保持真实群样本和隐私限制；允许不学习。特殊语音角色的提示与真实包络一起检查，不能为了通用风格改坏它。
- 日程区分模型联系动机与已接受的用户定时任务，不将超过范围的约定缩成近期联系。

验收兼顾漏掉合法选择与错误新增行为，不以“更保守、更少输出”自动判优。

### W06：提示组装与代码整洁度

位置：以上拼装入口、`context_transport.py`、`readonly_journal.py`、`system_contract.py` 及相关测试。

- 每条规则标明责任位置和适用请求，整理重复内容前核对最终物理消息与工具定义。
- 固定人格、稳定来源合同、当前事件、只读记忆、工具 schema 各守现有边界；不新增提示服务或大型注册框架。
- 同一接收上限尽量由现有常量形成描述，避免文案与程序各维护一份数值；不得把整份执行器实现灌给模型。
- 同一措辞只保留必要一次；需要跨模块重复呈现的安全边界以一致语义保持，不按去重比例删除。
- 先确认冷启动、旧数据和历史恢复用途，再删旧分支；必要独立账本不属于冗余状态。
- 最终请求快照用合成材料，记录结构、字节数、提示版本和关键来源，不保存私人原话或 Key。

不承诺缩短百分比，也不把减少字数当作主要验收。华为云带宽和内存有限，需记录实际请求体积；旧图片、旧工具结果不为此重写。

## 5. 具体候选写法

以下用于解释方案方向，不是已生效模板。现有 schema、输出字段和限制仍应逐项嵌入；不能复制后遗漏原合同。

### 压缩的任务描述

```text
本次整理帮助同一机器人继续理解人物、关系、经历和目标。
依据本批可见材料与现有记忆，自主选择值得保留或修订的内容。
保留影响后续判断的原因、条件和当前状态；临时闲聊可以舍弃。
分清谁说/关于谁、历史时刻/现在、提议/接受/履行/取消/未知。
引用、角色玩笑、推断和真实工具回执按各自来源理解。
资料有缺口或仅部分展示时，只基于可见部分提炼并保留必要不确定性。
只输出本次指定的一个JSON对象；未变化产品可以省略。
选择更新的产品须符合提供的来源、长度、数量和版本合同。
本次不重建、删除或改期已有业务任务、有效约定及执行账本。
```

提示本身无法弥补未传入的时钟、合法 ID 或实际回执；这些必须由现有上下文提供。无需向聊天用户展示内部整理步骤。

### 日常表达的期望

```text
接住当前实际说出的内容，以既定角色的兴趣、立场和情绪作自然回应。
关系和共同经历以真实记录为依据；可以有不同看法，也可以承认事实纠正。
闲聊按当下内容决定说多少，严肃提问按所需信息完整说明。
是否接话、配图或继续话题由你结合语境判断；表达不需要固定收尾。
自己的新看法可以形成，发生过的事实需要证据；工具结果按真实回执表述。
```

角色自身设定保留在配置中；不追加“每次必须可爱/拒绝/主动”的行为脚本。

### 工具描述的示意

```text
准备本轮附图，不会立即发送。仅使用真实列表返回的favorite_handle。
需要发送当前会话回复时按公共投递合同输出；授权跨群附图使用相应群发工具。
prepared表示已准备，confirmed才证明对应发送获得确认。
unknown或部分成功时核对原动作，不重复发送整批。
来源、账号、会话、权限与预算由后端按当前Work校验。
```

实际 schema 仍需明确 operation、必填条件和限制；不能让说明中的副作用类别替代账本。

### 少量对照例子的使用方式

| 易错区别 | 希望模型形成的理解 | 允许的不同结果 |
| --- | --- | --- |
| “我答应了，下周做” | 已接受，尚未履行 | 摘要或可选认知产品均可表达；不能写已经完成 |
| 甲转述乙的偏好 | 甲说过这段转述，偏好对象是乙，核实程度有限 | 有价值才保留，不强迫建甲或乙事实 |
| 更晚明确纠正旧说法 | 当前事实采用有效纠正，保留必要变化背景 | 合并或替换方式可不同，不能继续把旧值当现值 |
| 已准备图片 | 可以决定附图，尚无发送证明 | 可用图或不用图，不能声称已送达 |
| 研究后形成自己的想法 | 机器人基于真实材料的新观点 | 可分享或继续研究，不能说成用户刚刚提过 |

### 7.2 质量评测的两组基线

- **A1 → B**：质量优化的主要比较，使用同材料、同实际模型/参数、同工具回执和产品限制。
- 两版本实验不能声称完成 A0/A1/B 三组独立归因。如果另需 A0 模型实验，须从预算中替换样本或另授权，不偷偷增加第三组。

建议准备 22 个小型场景，其中 16 个用于开发检查、6 个预先保留，不拿保留样本反复改提示。更换人物、日期、表达与消息顺序覆盖同一语义，避免“一眼GPT”“？”等具体字符串变成标准答案。

### 7.3 判分与采用条件

先写每例的输入事实、必须保留的关键约束、可接受行为集合和禁区，再运行；不给唯一聊天原文作为标准答案。

| 层次 | 判据 | 决策 |
| --- | --- | --- |
| 硬护栏 | 历史不可变、35轮、来源/隐私、权限、任务账本、unknown不盲重试 | 任何新增失败均否决该候选，风格分不能抵消 |
| 语义关键项 | 作者、当前事实、接受/履行区别、重要目标条件、真实回执 | 关键用例退化就定位修改；不以总体平均分掩盖 |

盲评隐藏版本名称，平衡前后顺序；不因更长、更甜、更像客服、更积极行动而判优。优先人工校准边界病例。候选应在其声称改善的不同场景中给出具体收益且没有新关键退化；若持平或证据冲突，保留较小改动，不为“优化完成”硬上新文案。

长期效果另需观察：一次续问不证明几个月的人格稳定；一次休息决策不证明计时器会再次唤醒；模拟 confirmed 不证明 QQ 实际发送。对应工程可靠性由隔离恢复测试与真实自然运行证据分别报告。

## 8. 发布、回退与长期观察

当前阶段不部署。后续进入 S4 时：

3. 动态资料、辅助请求、压缩请求与主聊天 System 分开采用；System 变更使用现有可信 permit，35轮重建不等于全局许可。

5. 回退不得 reset 任务、重放 unknown、恢复退休材料或重写模型前缀。若已接受新认知产品，不能通过旧数据库快照回滚来伪造恢复；保留格式兼容并按现有事务核对。

只观察少量指标：产品级拒收原因与真实变化、压缩格式降级、目标/约定状态证据、重复无效工具调用、模型判断机会及休息后再次唤醒、人工标注的记忆误归属与表达退化。不要把“更多写入/更多发言”当成成功。
