# R2：交互、背景语义与材质细化

## 执行依据（实施前固定）

用户在三套样板后的修正：

1. 组件交互性、高级感、程序化不足。
2. 背景交互逻辑意义不明确，与整体搭配不好。
3. 优化细节、材质、动效。

保留旧 B 的暖纸与陪伴气质，继续优化当前三套独立样板。范围仅限本目录；正式业务、已有脏文件和旧预览不在本轮修改范围内。基线副本及摘要保存在忽略目录 `test-results/design-lab-r2/`。

## 计划与验收条件

| 要求 | 实施位置与职责 | 验收条件 |
| --- | --- | --- |
| 加深组件操作 | `lab.js` 与局部交互模块：雷达拖动、人格预设与撤回；记忆收藏、编辑、撤销；时钟直接操作；表情按压；可中止的逐步回应 | 几何、文案和本地状态共同变化；鼠标与键盘替代有效；切换主题保留有效状态 |
| 让背景承担信息含义 | `art.js`：按当前关注、选中记忆、能力与回复阶段绘制三种场景；页面背景以组件间路线呈现操作去向 | 普通鼠标经过不再绘制任意图案；人格、记忆、消息与安静时段有可解释的不同反馈，并有简短图例 |
| 材质与运动一致 | 单一 CSS 入口与 Canvas 绘制：纸纤维、压印、哑光色层、印刷细线；短按压、带阻尼的直接操作、有限提交动效 | 三套各自保持一致；避免强光与整体悬停抬起；减少动态与手动暂停有效；桌面和手机可用 |
| 动画和回复生命周期 | 局部 operation owner：新操作、换机器人、休息、能力变更、退出时失效旧演示 | 旧演示不提交回复、不覆盖新状态；中止后可重试；退出后清理监听与动画；主题仅切换表现时可保留当前操作 |
| 与项目安全隔离 | 仅静态本地样板 | 无业务 API、真实消息或模型调用；保留用户已有工作；样例文本安全显示 |

## 验证方法

使用项目已安装的 Playwright Chromium，通过实际入口检查三主题的响应式布局与交互；以可控演示阶段制造中断、换身份和退出场景。查看实际桌面、手机及交互状态截图。检查模块语法、变更文件和原正式样式摘要。最终追加 Plan vs Actual，不改写上述依据与验收条件。

## 用户后续修正：控制台定位

用户明确：项目没有小鱼角色，产品是控制台型。此修正优先于上面的拟物场景方向。保留组件交互、状态联动、材质细化和生命周期验收；取消角色、鱼群、花园及陪伴叙事。三套改为控制台元素样本，背景只表达实例连接、能力路由、当前操作与运行状态。可爱感通过控件比例、圆角和细微反馈实现。

## R3 执行前修正：只做 01，激进的二次元可爱

用户进一步明确只以 01 为基础，停止 02 / 03；原先的可爱程度、动效强度及程序化表现均未达到要求，要求明显而激进的变化。本次优先级覆盖上面关于克制、三套同时细化的安排。

- 视觉：樱粉、奶油白、浅紫；原创二次元操作员插画、终端表情、漫画网点、透明亚克力与有层次的印刷细节。保持控制台元素样本定位。
- 可见程序化：单一帧循环驱动弹簧响应、在线心跳与路由包；可拖拽的处理节点、拖动雷达与记忆索引；控件形变、滑动页签、有限的完成爆发动画。
- 背景：节点位置控制连线几何；停用能力淡出相应路由；运行消息逐阶段高亮；鼠标仅改变局部感应场，页级线路表示当前关注组件与消息目标。区分在线心跳与处理中的信号。
- 控制：持续动态开关、系统减少动态、页面隐藏和退出均有效；暂停冻结动画但保留直接操作；旧消息在中止、切实例或停用后不得迟到回写。
- 验收：仅验证 01，实际桌面与窄屏截图、动画连续帧差异与暂停稳定、节点几何、状态关联、消息竞争和退出、无业务 API 请求。原计划的两套扩展明确停止，不算未授权遗留任务。

## R4：用户纠正“激进”的对象

用户明确主题为“大肥鱼 / DeepSeek 娘”，要求清爽中带可爱、保持控制台；激进的是程序化能力，而不是二次元装饰。本修正覆盖 R3 的樱粉宣传头图与新操作员设计。读取并复用已有 `public/illustrations/dafeiyu-rice.png` 及项目角色约定，角色约占 10–15%，操作占主体。

本轮执行：白底冷蓝控制台、小面积既有角色；节点自动布局与连线重算；可中止的测试处理支持手动步进；可回看事件轨迹和当前状态快照；背景以当前组件依赖关系及实际操作传播表示含义。继续保留单帧循环、减少动态、退出清理及原有独立样板范围。R3 新插画不再被页面引用。

用户最终强调“不要有角色主体”，因此移除所有角色主视觉，保留小头像、媒体预览和组件状态所需的小面积已有素材。

## 最终 Plan vs Actual / R4

执行范围最终为 01。原三套范围与 R3 装饰方向因用户纠正停止，未继续投入 02 / 03。实际实现包括：节点阻尼自动布局、直接操作接管、可中止运行与手动步进、最近 16 条阶段轨迹、当次执行配置快照、只读历史状态投影、按组件依赖绘制的背景传播以及九组本地交互样本。

合理新增：Ctrl / Cmd + K 搜索本地命令、快照与当前草稿分离、键盘接管布局弹簧，均服务于程序化操作要求。结构调整为唯一最终 `console.css` 入口，避免多轮风格覆盖继续相互叠加。此前拒绝的视觉文件没有被最终入口加载。

Playwright 当前入口实际通过 52 项检查，覆盖七档宽度、动画连续帧与暂停、手动门与操作取消/替换、切实例/停止、历史态与当前配置隔离、执行快照与后续草稿隔离、编辑安全、各组件直接操作、减少动态和退出后无迟到写入。浏览器异常与业务 API 请求均为 0。详见 `test-results/design-lab-r3/r4-verification.json`；已查看桌面、手机及处理中截图。未执行生产构建和后端回归。

边界没有变化：独立模拟样板，无业务调用、提交、推送或部署；未改正式 React 与原有工作。正式样式摘要与实施前一致。视觉评价仍以用户意见为准，不能因测试通过而宣称设计已获认可。

## R5 执行依据：纯 UI 视觉定调，功能扩展是错误偏移

用户明确：只需要按钮、背景、面板、小按钮及基础 UI 的高度程序化设计，用它们确定界面感觉；程序化与功能无关。R4 将路由、步进、轨迹、快照等记为“合理新增”的判断不成立。这些是本任务的不合理偏移，须从当前入口完全移除，不能用功能检查数量证明视觉要求完成。

本轮只做 01 的材质与基础元素陈列，不制作业务界面、角色主视觉或功能演示。

| 要求 | 本次修改位置 | 视觉验收 |
| --- | --- | --- |
| 清爽、含蓄可爱、可判断整套 UI 感觉 | 独立 `materials.css` 与纯元素 HTML | 白与冷蓝、清楚字阶；无人物主体、业务字段、路由或执行台 |
| 高度程序化按钮与小按钮 | `materials.js`：几何边界采样、耦合弹簧、指针吸附、按压冲击 | 实际轮廓与表面高光变化，离开后阻尼回弹；不只平移/缩放整块元素 |
| 程序化面板与细节 | 同一轮廓引擎与程序细纹、渐变光源 | 面板边界、亚克力层次与小元素共享材质规则 |
| 程序化交互背景 | 独立波场与 WebGL 材质着色 | 连续曲面法线、折射状光纹；指针扰动与点击波纹，非业务数据可视化 |
| 稳定与可预览 | 单帧时钟、系统减少动态、视图动态开关与退出清理 | 桌面/手机无溢出，暂停后时间稳定，退出后无持续写入；仅验证上述 UI |

保留先前过程文件以便追溯，但最终入口只加载本轮纯 UI 文件。视觉验收优先于检查数量。

## R5 后续修正与 Plan vs Actual 收口

用户连续指出“太轻了、看不清”，随后指出“这个交互质感脱离可爱清新风了”。因此可读性与柔软感同时保留：加深文字及主按钮，明确面板边界；取消加重过程中出现的硬压边、灰蓝反光和密集纹线。表面采用奶白、晴蓝、少量薄荷和粉色，轮廓响应由向内吸附改为柔软鼓起及局部按压；背景由交叉细网格改为连续的曲面光纹。此处追加修正，不改写 R4 的错误决策记录。

当前实现对照 R5：42 个独立采样的程序轮廓、耦合弹簧、指针光源、代码生成的细粒、二维波场及 WebGL2 材质着色均已接入。入口只加载 `materials.css`、`materials.js` 和 `ui-field.js`；旧业务演示、命令、轨迹和角色图片均不在运行链中。基础控件只改变其视觉状态，不存在业务执行。

实际 Playwright 检查 34 项通过，浏览器异常与业务 API 请求为 0。覆盖轮廓与回弹、微型按钮、键盘、页签/开关视觉弹簧、背景连续帧、暂停停止帧与图像稳定、减少动态、六档宽度、退出后无帧/迟到写入、重复退出及两种 GPU 回退。证据对应当前文件，位于 `test-results/design-lab-r5/verification.json`；已查看实际桌面、手机及波纹截图。原生输入文字截图有 1–3 级 RGB 的 Chromium 光栅差异，像素冻结检查只遮罩该原生文字区；程序输入框边缘及帧停止仍被验证，没有降低应用动画检查。

范围偏移已处置：R4 的功能扩展曾被错误标记为合理，当前入口已整体移除；先前视觉文件保留供追溯，不再加载。没有新增正式应用接口或修改用户原有业务文件。正式样式摘要不变。未运行整仓库构建、后端测试和专门的历史缓存恢复测试；这些不能冒充已验证。当前视觉是否满足“足够可爱、清新”仍需用户评价，测试通过不代表视觉已获认可。
